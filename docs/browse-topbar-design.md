# File Browse 上部領域の設計

対象: File Browse パネル上部(パス行〜セパレータ、および空状態)。

## 2.2 収斂した文法

- **定常クロームは1行。** 左に小さな固定ナビ群、行の唯一の可読テキストがパス、残りは右端のアイコン寸。追加の行はすべて一時的で Esc で消える。
- **パスは編集できる1本のテキスト行であり、箱の列ではない。** 表示⇄編集(⇄検索)は同一矩形のモード切替。パス自身はボタンを持たない — 読むためのステータスであって操作帯ではない。
- **絞り込みの常設入口は最大1つ。検索は召喚される。** 今ある一覧を薄くするものはリストに付属し、新しい集合を取ってくるものはロケーション側で召喚され、スコープは発動時にテキストで名乗る。幾何が意味を運ぶ。
- **リモートは場所の属性であって、別の道具ではない。** ホストは行を消費しないアンカー(パス最左/タイトル)で一度だけ名乗る。接続 OK は沈黙し、異常だけが画素を得る(それも同一アンカーの変異かリスト内インラインで)。
- **ジャンプ(bookmark/recent/host)は召喚。** 常設の場所を持たない。
- **エンジンはユーザーが選ばず、場所が決める。** ローカルな場所→即時、リモートな場所→往復。同じ入力面、同じ挙動、違うのは裏側だけ。

## 10.2 確定した方針

- **`more/less` は廃止。** 中身は各々の正しい住処へ:
  - ホスト名 → **パネルタイトル** `Browse [ssh: trc2]`
  - disconnect → **下端ステータス行**のホスト表示の隣
  - bookmark → **パスの右横**(★。点灯が「登録済み」の状態表示も兼ねる)
  - open folder → **メニューバー**(クラム右クリックの "Open folder (all stacks below)" は現在地に対する動詞なので残す)
  - サーバ検索 → 召喚チップに統合(Enter で確定)
- **`<` `>` `up` はバーから削除**(マウス/キー/`..` が代替、10.1)。
- **refresh・grp|flat・list|tree は別インターフェースへ**(`…` メニュー+キー)。
  非既定のときだけチップで名乗る。
- **Esc で戻す**: Browse に焦点があるときの Esc の段は
  **チップ → 選択解除 → (既存の app 全体の段: popup/text → ROI → compare off)**。

## 10.3 ホスト表示の置き場

**採る形: タイトル + 下端ステータス行。上部は1行(パス)のまま。**

```
+- Browse [ssh: trc2] -----------------------+   ← タイトルが名乗る
| v  /data/run42/dark_1ms            ★   …  |   ← 上部は1行。パスと bookmark と menu
| ------------------------------------------ |
|    (ファイル一覧)                           |
| ------------------------------------------ |
| [ssh] trc2 · 512 items · 3 selected  [切断] |   ← 下端: 状態と、状態に付く動詞
+--------------------------------------------+
```

下端ステータス行が引き受けるもの(= 上部から消えるもの):
接続状態 (A5) / listing・走査の進捗 (D1,D4) / 取得エラー (D2) / プロトコル警告 (D3) /
Watch の稼働 (D6) / 行数 (B12) / 選択件数と枚数 (E1,E2) / disconnect (F4)。

ホストは「稀に変わる事実」で、パスは「常に読む文」なので、
稀な方をタイトルへ、常に読む方を上部1行へ、状態は下端へ、と役割で分ける。
一般的なファイルブラウザ(Explorer / Dolphin / WinSCP)がまさにこの三分割。

**下端ステータス行は常設**。出没する行の上下動が今の重さの一因なので、
「たまにしか真でない事実」を1本の常設行に集める。

## 10.4 list のクリック確定

> **単クリックで確定してよいのは、可逆かつ安価な操作だけ。**
> フォルダへ降りるのは可逆(mouse4 で戻れる)で安価(一覧を引くだけ)。
> stack を開くのは高価(転送・メモリ・測定のやり直し)で、可逆ではない。

したがって:

| 行の種類 | list モードの単クリック | ダブルクリック |
|---|---|---|
| ディレクトリ / `..` | **そこへ行く**(可逆・安価) | (同じ) |
| ファイル / 連番グループ | **選択**(従来どおり) | 開く(確定) |
| tree モード | 全行とも選択のまま | 開く / 降りる |

これで `up` ボタンは本当に不要になり(`..` が1クリック)、複数選択(Enter で
それぞれを stack として開く)も壊れない。**代償**: list でフォルダを複数選択する
手段が Ctrl+クリックと右クリックだけになる。フォルダの複数選択は
"Copy paths" くらいでしか使わないので、許容と判断。

**チップの召喚は Ctrl+F のみ**で始める。打鍵召喚は使ってみてから判断。

## 10.6 tree の展開を行全体で受ける

したがって行全体を当たり判定にしてよい条件は**1つだけ**:
**その行にダブルクリックの意味が無いこと。**

さらに幾何が味方する: 展開は**自分の下**に子を差し込むので、押した行自身は
動かない。ダブルクリックしても「展開→畳む」で元に戻るだけで、
2打目が別の行に落ちる事故は起きない。

| tree の行 | 単クリック | ダブルクリック |
|---|---|---|
| ディレクトリ | **行のどこでも展開/畳み** | (意味を持たせない = 2回トグル) |
| 連番グループ | 選択 | 開く(確定) — **展開はシェブロンのみ**(開く意味があるため) |
| ファイル | 選択 | 開く(確定) |
| `..` | 親へ | (同上) |

つまり **tree でフォルダを「降りる」動詞は持たない**(降りるのは list の仕事)。
これで list と tree の役割が完全に分かれる:
**list = 場所を移動する / tree = 構造を見る**。10.4 の線引きとも矛盾しない
(展開は可逆かつ安価)。

グループ行だけシェブロン限定なのは不揃いに見えるが、理由は言える —
**開く意味を持つ行は、閃きを避けるためにシェブロンを要求する**。
