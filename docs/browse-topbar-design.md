# File Browse 上部領域の設計検討 — 一般的なブラウザのサーベイと提案

対象: File Browse パネル上部(パス行〜セパレータ、および空状態)。
背景: 「filebrowseの上側の認知負荷がやはりたかい」(2026-07-27)、「filterとsearch serverの二つの入り口があるのはなんでだろう」(項目14)、「ローカル用とリモート用、分けざるを得ないと思う」(項目17の再燃)。

### 1.2 診断 — なぜ「上側」が重く読めるのか

1. **定常4行はサーベイ収斂値(1行)の4倍。** しかも行数が呼吸する: エラー帯(16516)・折りたたみ時検索通知(16947)・プロトコル警告(17076)が出没して下の全てを上下させる。深いパスはクラム折返し(16417)でさらに増える。
2. **1行が複数の仕事をしている。** パス行はジャンプ入口(16404)+現在地(16417)+編集入口(16482)+通信状態(16490)+パネル生成(16492)の5役。ツールバー行は履歴ナビ+表示モード2組+絞り込み+折りたたみトグル(16702-16862)の混載。「1行1役」の自ルールに自分で違反している。
3. **稀な操作が常設クロームを占有。** `+`(16492)、`~`(16719)、`refresh`(16722)、`more`ボタン(16862)は毎グランス課税される。極めつけはアクション行: 常時提出なのにフロー処理がなく、既定幅271pxで `Temporal stats` 以降が右に黙ってクリップする(16987-17063)— 存在を示すことにすら失敗している。
4. **絞り込みの入口が2つ**(16795 vs 16925)。配置(常設/折りたたみ内)・確定(逐次/Enter)・範囲(この一覧/再帰)・コスト(ゼロ/往復)・結果(同じ表/置換ビュー)の全軸で同時に異なる同形のテキスト箱が2つ。展開時は兄弟として並ぶ — 項目14の混乱はこの幾何そのもの。
5. **リモート状態の優先度が逆転。** 最重要の事実「このパネルはどのマシンを見ているか」は折りたたみの中(16875)にしかなく、既定状態では不可視 — インスタンス化(項目17)後、2枚のパネルはピクセル単位で同一になる。一方で異常系(エラー帯・プロトコル警告)は全幅で行を奪う。
6. **空状態が別文法。** 「ローカル」「リモート」の2ボタン(16318/16329)は、docs/browse-as-file-manager.md が退けたはずの「接続」語彙をパネルの顔に再輸入している。

### 2.2 収斂した文法

4系統すべてが同じ文法に収斂し、逸脱したツール(digiKam, darktable, RawTherapee, FileZilla)がそのまま各分野の反面教師になっている。

- **定常クロームは1行。** 左に小さな固定ナビ群、行の唯一の可読テキストがパス、残りは右端のアイコン寸。追加の行はすべて一時的で Esc で消える。
- **パスは編集できる1本のテキスト行であり、箱の列ではない。** 表示⇄編集(⇄検索)は同一矩形のモード切替。パス自身はボタンを持たない — 読むためのステータスであって操作帯ではない。
- **絞り込みの常設入口は最大1つ。検索は召喚される。** 今ある一覧を薄くするものはリストに付属し、新しい集合を取ってくるものはロケーション側で召喚され、スコープは発動時にテキストで名乗る。幾何が意味を運ぶ。
- **リモートは場所の属性であって、別の道具ではない。** ホストは行を消費しないアンカー(パス最左/タイトル)で一度だけ名乗る。接続 OK は沈黙し、異常だけが画素を得る(それも同一アンカーの変異かリスト内インラインで)。
- **ジャンプ(bookmark/recent/host)は召喚。** 常設の場所を持たない。
- **エンジンはユーザーが選ばず、場所が決める。** ローカルな場所→即時、リモートな場所→往復。同じ入力面、同じ挙動、違うのは裏側だけ。

## 3. 提案

共通前提: クリック=選択(可逆)/ダブルクリック・Enter=確定は既定路線。全案 300px で成立すること。

### 案A 「一行+召喚」— 収斂文法の全面採用

```
+--------------------------------------------+
| v < ^  trc2: /data/run42/dark_1ms       …  |
| ------------------------------------------ |
|  > 20260721_night                          |
|    dark_0001-0480   [480]                  |
|    flat_0001-0120   [120]                  |
|    note.txt                                |
+--------------------------------------------+
```
絞り込み中(リストにフォーカスして打鍵、または Ctrl+F):
```
+--------------------------------------------+
| v < ^  trc2: /data/run42/dark_1ms       …  |
| ------------------------------------------ |
|    dark_0001-0480   [480]  +-------------+ |
|    dark_0481-0520   [ 40]  | dark_   2/4 | |
|                            +-------------+ |
+--------------------------------------------+
```

- **視線の流れ**: 1行目 — 小さな固定ナビ(`v` `<` `^`)は初日で背景化し、目は行内唯一の文である「trc2: /data/…」に着地する。「どのマシンの・どこか」を読字順で読み、線を越えたら即ファイル行。以上。上部で読むものはパス1文だけ。
- **filter と search の行き先**: 常設箱は両方消える。リストに打鍵するとチップが召喚され(エコー+N/M+Esc)、**打鍵中は常にクライアント側絞り込み(可逆=選択)**。場所がリモートのとき **Enter で同じ文字列がサーバ再帰 glob として確定**(確定=commit、結果は従来通り一覧を置換、チップに淡色 `server` タグとスピナー)。入口は1つ、エンジンは場所が決め、エスカレーションは既存の select/commit 文法に載る。項目14は構成的に消滅する。
- **リモート状態**: ホストはルートクラム `trc2:`(ローカル時は無表示=沈黙)+ウィンドウタイトル(`trc2 — Browse###…`、main.cpp:1245 の固定を解除)。ルートクラムの右クリックが接続メニュー(disconnect / update peer / bookmark host)。エラー・再接続はリスト領域内のインライン行(ステール一覧保持)。行コストゼロ。
- **消える/召喚化**: more帯一式(16862-16947)、常設 filter 箱(16795)、search 箱(16925)、`+`(16492)、`~`/`refresh`(16719/16722)、`grp|flat`/`list|tree`(16730/16748)→ `…` メニュー+キー。エラー帯(16516)・プロトコル警告(17076)→ リスト内/接続メニューへ。アクション行はクリップ問題ごと「選択時のみ下端に現れるバー」へ。
- **トレードオフ**: 発見可能性を「打てば絞れる」という習慣1つに賭ける(初回のみリスト末尾に淡いヒントが要る)。表示モード切替が1クリック→メニュー経由になる。チップは新規の描画面。

### 案B 「二段固定・単一スロット」— 常設 filter を残す保守案

```
+--------------------------------------------+
| v  trc2: /data/run42/dark_1ms              |
| < ^ [filter (Ctrl+F)_______] 34/512     …  |
| ------------------------------------------ |
|    rows...                                 |
+--------------------------------------------+
```
検索召喚時(Ctrl+Shift+F またはクラム右クリック「Search under here」— 2行目が同一スロットで変身、Esc で復帰):
```
| < ^ [search: frame_** ][Stop] 範囲:この下  …|
```

- **視線の流れ**: 1行目はパスだけの純粋な場所行(1行1役)。2行目は道具行 — ナビ2個、絞り込み箱1個、右端にメニュー。線、ファイル行。
- **filter と search**: 常設は filter のみ(Cyberduck / WinSCP マスクと同型)。search は召喚され **同じスロットを乗っ取る** ので、2つの箱は決して同時に存在しない。モードはラベル(`search:`+範囲表示)で名乗り、Esc で filter 行に戻る。
- **リモート状態**: 案Aと同一(ルートクラム+タイトル+接続メニュー、OK は沈黙)。
- **消える/召喚化**: more帯一式、`+`・`~`・`refresh`・表示モード2組→ `…` メニュー。4行→2行。
- **トレードオフ**: 収斂値(1行)より常設1行重いが、絞り込みの発見可能性は最大。同一スロット変身はモード誤認の芽(ラベルと Esc 復帰で抑える)。300px では filter 箱の床幅8フォントが窮屈。

### 案C 「ローカル/リモート分離」— ユーザー仮説の検証

```
+- Browse (local) ---------------------------+
| v < ^  C:/capt/run42                    …  |
| ------------------------------------------ |
|    rows...  (絞り込みは打鍵で召喚)          |
+--------------------------------------------+

+- Browse (ssh) -----------------------------+
| trc2  [ssh]                      [切断] …  |
| v < ^  /data/run42                         |
| ------------------------------------------ |
|    rows...                                 |
+--------------------------------------------+
```

- **視線の流れ**: ローカル版は案Aの縮退形で最軽量。リモート版は「ホスト行→パス行→一覧」— どのマシンかを常に1行目で確言する。
- **filter と search**: ローカル版には server search が**存在しない**ので入口は構成的に1つ。リモート版は結局「即時絞り込み+召喚検索」の両方が要り、案Aと同じ解を内部に持つことになる。
- **リモート状態**: 常設ホスト行+切断ボタン。最も明示的だが、「接続 OK は沈黙」の文法に真っ向から違反し、300px で恒久的に1行を支払う。
- **消える/召喚化**: 案Aに同じ(各パネル内では)。
- **トレードオフ**: 4系統のサーベイで**局所性によってパネル種を分けた例はゼロ**(VS Code Remote-SSH・Nautilus・Lightroom・Cyberduck はすべて単一面+場所属性。唯一の二面板 FileZilla 群は転送=2端動詞の産物で、本ビューアの動詞 OPEN は1端)。分割は場所・絞り込み・ジャンプの文法を二重実装し、「接続」語彙をパネルの顔に戻し(項目17の決定に逆行)、並置要求は既にインスタンス化で満たされている。ただしこの案が要求する中身 — ホストの恒常的な名乗り・ステール保持再接続・場所によるエンジン分岐 — は**全て単一パネルのまま案A/Bに吸収できる**。仮説の動機は正しく、解は分割ではない。

## 4. 推奨

**案A。** 理由(文法対照):
1. 「定常1行」を満たす唯一の案 — 「上側の認知負荷」への最大の直接回答。
2. 「入口は1つ、エンジンは場所」で項目14が構成的に消え、打鍵=可逆/Enter=確定という既存の select/commit 文法の上にそのまま立つ。
3. 「ホストはルートクラム、OK は沈黙」で多インスタンスの同一性問題(どのマシンか不可視)を行コストゼロで解消。
4. 300px でも1行+リスト内チップは崩れない(クリップするアクション行も同時に整理される)。
5. 案Cの正当な動機(リモートの明示)を、分割の二重実装コストなしで回収する。

コード面(表層のみ): **消える** — more/less(16862)、詳細帯一式(16875-16947)、常設 filter 箱(16795)、search 箱(16925)、`+`(16492)、`~`(16719)、`refresh`(16722)、`>`(16708)、`grp|flat`(16730)・`list|tree`(16748)の常設形、上部エラー帯(16516)、プロトコル警告行(17076)。**移る** — peerLabel→ルートクラム+タイトル(1245)、disconnect→ルートクラム右クリックメニュー、`*`→places ポップアップ(16404)とクラムメニュー(16436 既存)、open folder→クラムメニュー(既存)、絞り込み/検索→リスト上の召喚チップ(新規)、表示モード・refresh・`~`・`+`→ `…` メニュー+キー、アクション行(16987-17063)→選択時下端バー。**残る** — `v`(16404)、`<`(16702)、`^`(16714)、クラム(16417)、不可視編集域(16482)、`(listing...)`(16490)。

## 5. 未決事項(要ユーザー判断・推奨既定値つき)

1. **チップの既定動作**: 一致行のみ表示(hide、現行互換)か、非一致を淡色化して残す(highlight、連番シーケンスの文脈が残る)か。→ 既定: **hide**(N/M 表示と互換)。highlight は後日トグルで。
2. **ローカルな場所での Enter**: 何もしない/この下を再帰列挙に昇格(Open Folder 相当)。→ 既定: **リモートのみ昇格**。まず入口統一の効果を単純形で測る。
3. **`grp|flat`・`list|tree` の降格可否**: 実使用頻度はユーザーのみ知る。→ 既定: **`…` メニュー+キーへ降格**。頻繁と判明したら1行目右端にアイコン寸で復帰。
4. **`>`(進む)の削除**: Alt+Right / mouse5 のみに。→ 既定: **削除**。
5. **不慮の切断時**: ステール一覧保持+インライン再接続(WinSCP 型)か、空状態へ戻すか。自動再接続の試行回数も。→ 既定: **ステール保持、自動再接続1回**、失敗でインライン表示。
6. **パネルタイトルへのホスト名**(タブ幅を消費): → 既定: **出す**(`###` でレイアウト識別は不変)。

## 10. 実装方針 — ユーザー指示の記録 (2026-08-03)

### 10.1 すでに実装済み (作り直す必要なし)

| 指示 | 現状 | 場所 |
|---|---|---|
| Local にも File Browse が欲しい | **ある**。`Browse folder (local)` が `local://` peer 経由で同じパネルを使う | `browseLocalFolder` / `startRemote(I, "local://"+p)` |
| Ctrl+F で活性化 | **ある**(filter 箱にフォーカス)。新形では同じキーがチップを召喚する | main.cpp 16789 |
| 戻る/進むはマウスで足りる | **ある**。mouse 4/5 がパネル単位で効く(hover でも focus でも)+ Alt+←/→ | `rbHistGo` / 17258- |
| `..` があるので up は不要 | **ある**。`..` は list と tree の**両方**に出る | main.cpp 16092 |

つまり #8/#9/#10(`<` `>` `up`)は**機能を失わずにバーから消せる**。

### 10.2 確定した方針

- **`more/less` は廃止。** 中身は各々の正しい住処へ:
  - ホスト名 → **パネルタイトル** `Browse [ssh: trc2]`
  - disconnect → **下端ステータス行**のホスト表示の隣
  - bookmark → **パスの右横**(★。点灯が「登録済み」の状態表示も兼ねる)
  - open folder → **メニューバー**(クラム右クリックの "Open folder (all stacks below)" は現在地に対する動詞なので残す)
  - サーバ検索 → 召喚チップに統合(Enter で確定)
- **`<` `>` `up` はバーから削除**(マウス/キー/`..` が代替、10.1)。
- **refresh・grp|flat・list|tree は別インターフェースへ**(`…` メニュー+キー)。
  非既定のときだけチップで名乗る。
- **Esc で戻す**: Browse に焦点があるときの Esc の段は
  **チップ → 選択解除 → (既存の app 全体の段: popup/text → ROI → compare off)**。

### 10.3 ホスト表示の置き場 — 指示が3箇所を指していたので1つに決める

指示にはタイトル (`Browse [ssh: host]`)、下端 (`[ssh] host` の近所に disconnect)、
1行目 (`ssh: host名` + view 切替) の3案が同居していた。同じ事実を3箇所には出さない。

**採る形: タイトル + 下端ステータス行。上部は1行(パス)のまま。**

```
+- Browse [ssh: trc2] -----------------------+   ← タイトルが名乗る
| v  /data/run42/dark_1ms            ★   …  |   ← 上部は1行。パスと bookmark と menu
| ------------------------------------------ |
|    (ファイル一覧)                           |
| ------------------------------------------ |
| [ssh] trc2 · 512 items · 3 selected  [切断] |   ← 下端: 状態と、状態に付く動詞
+--------------------------------------------+
```

下端ステータス行が引き受けるもの(= 上部から消えるもの):
接続状態 (A5) / listing・走査の進捗 (D1,D4) / 取得エラー (D2) / プロトコル警告 (D3) /
Watch の稼働 (D6) / 行数 (B12) / 選択件数と枚数 (E1,E2) / disconnect (F4)。

**なぜ 1行目に置かないか**: 1行目に `ssh: host` を置くと、パス行が2行目に落ちて
上部が2行になる。ホストは「稀に変わる事実」で、パスは「常に読む文」なので、
稀な方をタイトルへ、常に読む方を上部1行へ、状態は下端へ、と役割で分ける。
一般的なファイルブラウザ(Explorer / Dolphin / WinSCP)がまさにこの三分割。

### 10.4 list のクリック確定 — 原則の拡張として採る

指示:「list のときはクリックでそこに行く。tree と使い方の差別化ができる」。
これは既存の原則「クリック=選択(可逆)/ダブルクリック=確定」と正面から当たる。
そこで原則を**壊すのではなく、線を引き直す**:

> **単クリックで確定してよいのは、可逆かつ安価な操作だけ。**
> フォルダへ降りるのは可逆(mouse4 で戻れる)で安価(一覧を引くだけ)。
> stack を開くのは高価(転送・メモリ・測定のやり直し)で、可逆ではない。

したがって:

| 行の種類 | list モードの単クリック | ダブルクリック |
|---|---|---|
| ディレクトリ / `..` | **そこへ行く**(可逆・安価) | (同じ) |
| ファイル / 連番グループ | **選択**(従来どおり) | 開く(確定) |
| tree モード | 全行とも選択のまま | 開く / 降りる |

これで `up` ボタンは本当に不要になり(`..` が1クリック)、複数選択(Enter で
それぞれを stack として開く)も壊れない。**代償**: list でフォルダを複数選択する
手段が Ctrl+クリックと右クリックだけになる。フォルダの複数選択は
"Copy paths" くらいでしか使わないので、許容と判断。

#### 10.4.1 単クリックで確定するなら、そのジェスチャ全体を所有する (2026-08-04)

10.4 は「単クリックで確定してよいのは可逆かつ安価な操作だけ」で線を引いた。
それだけでは足りない条件がもう1つあることを CI が示したので、ここに足す:

> **確定して一覧が入れ替わるなら、その打鍵連(click chain)の残りは
> ナビゲーションのものであって、入れ替わった後の一覧のものではない。**

理由は幾何にある。10.6 が tree の行全体展開を許した根拠は
「展開は自分の**下**に子を差し込むので押した行自身は動かない、
だから2打目が別の行に落ちる事故は起きない」だった。list の移動には
その保護が無い —— 一覧そのものが差し替わり、ポインタは1ピクセルも
動いていないので、**2打目は必ず別の行に落ちる**。そして
「フォルダは2回クリックするもの」という20年の習慣がある以上、
list を1クリックにしても2打目は来る。

CI (ubuntu) が出した反例。browse-keys の instance 節が panel 2 で
`scanroot/10lx` をダブルクリックする:

```
185 dbl          dir=.../rb/scanroot rows=3 imgs=44
186 waitdir:10lx dir=.../rb/scanroot/10lx rows=1 imgs=52
```

画像が8枚増えている。`10lx` の中身がちょうど8コマ。つまり
**フォルダに向けたダブルクリックが、そのフォルダの中身を開いた**。
1打目の release で `rbGoTo` が走り、非同期の一覧が2打目の press より先に
着き(ubuntu のローカル一覧は選択テストのフレーム予算 ~8ms に入る。
Windows では入らない —— これが「Linux でだけ落ちる」の正体で、
キーの配送先とは何の関係も無かった)、2打目は新しい一覧の行1、
すなわち `frame_000..007` グループに落ちた。ついでにその release が
キーボードカーソルを 1 に書き、`chkcursor:-1` が落ちた。

実装は `BrowseInstance::navChain` + `rbNavGesture` (core/main.cpp)。
連の同一性は ImGui 自身の `MouseClickedLastCount` で判定する —— 1つの
ジェスチャの打数を数え、次の press が遅すぎるか離れすぎていれば 1 に戻る
値なので、「まだ同じジェスチャ」は「数が増えた」と同義になる。
tree のダブルクリック(移動)も2打目の **press** で確定するため同じ窓を
持つ(1フレーム分だけ狭い)ので、同じ掛け金を使う。

`..` は掛けない。**`..` はどの一覧でも行0**なので、2打目は「別の行」ではなく
「同じコントロールをもう一度」であり、ツールバーの `up` ボタンと同じ扱いで
よい。

### 10.5 まだ決めていない小さな点

1. **チップは打鍵でも出るか、Ctrl+F だけか。** VS Code / JetBrains は打鍵で出る。
   打鍵で出すと、単キーのショートカット(将来)と食い合う。
   → 推奨: **まず Ctrl+F だけで出す**。慣れたら打鍵召喚を足す。
2. **下端ステータス行は常設か、何かある時だけか。** 常設だと 1 行を恒久的に払う。
   → 推奨: **常設**。行数・選択数・接続は「ほぼ常に真」で、
   出没する行は上下動でかえって読みにくい(現状の出没帯の教訓)。

### 10.6 tree の展開を行全体で受ける — 条件つきで採る

指示 (2026-08-03):「tree のときに ▼ ボタンのクリックが使いづらい。パスも
クリック判定してよいのでは」。

シェブロンを別の当たり判定にしたのは、**同じ行が単クリックで展開し
ダブルクリックで開く**と、開く意図の第一クリックで展開が閃く(以前の
「操作の品位が良くない」)から。現在のコードはその保証を構造で持っている:

> シェブロンの動詞は PRESS で確定。この帯にダブルクリックの意味は無いので
> (速い2連打はただの2回トグル)、楽観的な動作も取り消しも要らない。

したがって行全体を当たり判定にしてよい条件は**1つだけ**:
**その行にダブルクリックの意味が無いこと。**

さらに幾何が味方する: 展開は**自分の下**に子を差し込むので、押した行自身は
動かない。ダブルクリックしても「展開→畳む」で元に戻るだけで、
2打目が別の行に落ちる事故は起きない。

| tree の行 | 単クリック | ダブルクリック |
|---|---|---|
| ディレクトリ | **行のどこでも展開/畳み** | (意味を持たせない = 2回トグル) |
| 連番グループ | 選択 | 開く(確定) — **展開はシェブロンのみ**(開く意味があるため) |
| ファイル | 選択 | 開く(確定) |
| `..` | 親へ | (同上) |

つまり **tree でフォルダを「降りる」動詞は持たない**(降りるのは list の仕事)。
これで list と tree の役割が完全に分かれる:
**list = 場所を移動する / tree = 構造を見る**。10.4 の線引きとも矛盾しない
(展開は可逆かつ安価)。

グループ行だけシェブロン限定なのは不揃いに見えるが、理由は言える —
**開く意味を持つ行は、閃きを避けるためにシェブロンを要求する**。

### 10.7 未決2点の回答 (2026-08-03) — 推奨どおりで様子見

- **チップの召喚は Ctrl+F のみ**で始める。打鍵召喚は使ってみてから判断。
- **下端ステータス行は常設**。出没する行の上下動が今の重さの一因なので、
  「たまにしか真でない事実」を1本の常設行に集める。

### 10.8 メニューバーの整理 — command palette (Ctrl+P) の提案 (2026-08-03)

指示:「server 側の update は勝手にやってもらってメニューから消したい。
Ctrl+P (mac は Cmd+P) でコマンドメニューもしくはファイル検索メニューを出せば、
タスクバーが混沌から解放されないか」。

**方向は正しい。** ただし2つの別物が同じキーに乗っているので分けて考える:

1. **peer の更新を自動化してメニューから消す。** 現在は明示操作。
   プロトコル版が食い違ったときに黙って配り直せばよく、ユーザーの判断を
   求める場面ではない(判断材料を持っていないのはユーザーの方)。
   → **メニューから削除**し、不一致を検出したら自動で配布、結果は下端
   ステータス行に一文(§10.3 の受け皿)。失敗したときだけ操作を出す。
2. **Ctrl+P の中身**。VS Code は Ctrl+P=ファイル、Ctrl+Shift+P=コマンドと
   分けている。この道具でも同じ二分が効く:
   - **Ctrl+P = 開く**(最近のフォルダ・bookmark・開いている stack・
     Browse の現在地から検索) — 「どこへ行くか」
   - **Ctrl+Shift+P = コマンド**(メニューにある動詞を名前で引く) — 「何をするか」
   コマンド側が育てば、メニューバーは「発見のための地図」だけになり、
   使い込んだ人はメニューを開かなくなる。これがタスクバー整理の本筋。

**先に決めること**: コマンド一覧の出どころ。メニュー項目を手で二重登録すると
必ず片方が腐る。**メニューを1つのテーブルから生成し、palette は同じテーブルを
引く**形にすれば、追加のたびに両方に載る。順序は
「テーブル化 → メニューをテーブルから描く → palette を足す」。
