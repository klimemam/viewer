# .npz に key が入っているときどう扱うか

ユーザー提起 (2026-08-03):「npz で array 直ではなく、key が入った場合ってどういう対応しましょうかね」。

## 1. 今どうなっているか (コードで確認)

`loadNpz` (main.cpp 3661) は zip 内の `*.npy` メンバを**全部**、名前順に**黙って開く**。
各メンバは `loadNpyBuffer` → `decodeNpyBuffer` を通り、名前は `file.npz:key`。
セッションには `member <key>` が残り、復元は zip 経由で同じメンバを読み直す。

形の解釈 (decodeNpyBuffer 3900-3922):

| メンバの shape | 今の結果 |
|---|---|
| (H,W) / (H,W,C) / (F,H,W) など | 画像 / stack。**正しい** |
| 4次元より深い | **先頭要素 [0] を黙って取る** |
| **1次元 (N,)** | **H=1, W=N の「画像」になる** |
| スカラー | 1×1 の「画像」になる |
| 文字列・object dtype | `unsupported dtype` で拒否(正しい) |

### ここが欠陥

**1次元の配列が「高さ1ピクセルの画像」として開かれる。**
露光時間の列 `exposure_ms = [1,2,5,10,...]` を渡すと、それが**絵として** Files に並ぶ。
これは正典の「黙って捏造しない」に反する — 1次元配列は画像ではない。
4次元超の `[0]` 黙殺も同じ family。

そして**全メンバを無条件に開く**ので、`{data, dark, flat, exposure_ms, gain}` の
npz を開くと画像3枚 + 偽画像2枚が Files に並ぶ。

## 2. 提案 — npz は「入れ物」であって画像ではない

正典の層 (frame ⊂ stack ⊂ series ⊂ batch) にそのまま乗る:

- **npz ファイル = batch** (フォルダを開いたときと同じ意味。「一緒に開いたもの」)
- **メンバ = stack** (frame 軸があるとき) **または frame**
- 形の違うメンバが同居してよい (`dark` 480x640 と `flat` 1024x1024) — 別 stack になるだけ

### 2.1 メンバを役割で分類し、それを言う

| shape | 役割 | 扱い |
|---|---|---|
| 2次元以上で画像として解釈可能 | **画素** | stack / frame として開く |
| 1次元 (N,) | **軸か metadata** | 画像にしない。frame 数と一致すれば **per-frame 軸の候補**、そうでなければ metadata |
| スカラー | **metadata** | プロパティに出す (露光・ゲイン・温度…) |
| 文字列 / object | **metadata** | 同上 (今は拒否するだけ) |
| 4次元超 | **曖昧** | 黙って [0] を取らない。「どの軸を frame にするか」を訊くか、明示的に拒否する |

### 2.2 1次元 key は「捨てるもの」ではなく、いま一番欲しいもの

Temporal パネルには既に**フレームごとの X 軸**がある (貼り付けで与える。
カンマ/空白/タブ/改行区切り)。**長さが frame 数と一致する 1 次元 key は、
まさにその軸そのもの**。

つまり撮影スクリプトが `np.savez(out, data=stack, exposure_ms=exp)` と書けば、
リニアリティのチャートの X 軸が**ファイルから直接**来る。貼り付けが要らなくなる。

- 開くときに「軸候補が N 本ある」ことを言い、名前で選ばせる (`exposure_ms`, `lux`)
- 単位は key 名から推測しない。**軸名と単位はユーザーが確定する** (既存の
  seqaxisname / seqaxisunit にそのまま入る)

### 2.3 何を開くかを選ばせる — 既存のフォルダ picker と同じ形

今の「全部開く」は、key が意味を持つファイルでは間違い。
**メンバ一覧の picker** を出す (フォルダ picker と同じ語彙・同じ操作):

```
+- open dark_sweep.npz ----------------------------------+
| [x] data          (24, 480, 640)  uint16   -> stack 24 |
| [ ] dark          (480, 640)      uint16   -> frame    |
| [x] exposure_ms   (24,)           float64  -> axis     |
| [ ] gain          scalar          float64  -> metadata |
|                                                         |
| batch: dark_sweep.npz          [Open]  [Cancel]         |
+---------------------------------------------------------+
```

- **画像メンバが1つだけなら picker を出さずに開く** (今の使い勝手を落とさない)
- 軸候補は「その stack に適用する」チェックとして出す
- metadata は開く対象ではなく、**プロパティに残る**

### 2.4 Browse からも中身が見えるべきか

`.npz` の行を展開して中のメンバを見せるのは自然 (入れ物なので tree と相性が良い)。
ただし**リモートでは peer に zip の中身一覧を返す動詞が要る** — プロトコル追加。
ローカル先行、リモートは後続で良い。

## 3. 決めてほしいこと

1. **全部開く → picker、で良いか。** (推奨: 良い。画像1つなら picker なし)
2. **1次元 key を軸として提案するか。** (推奨: する。これが一番効く)
3. **metadata (スカラー/文字列) をどこに出すか。** (推奨: プロパティ。
   将来 series の値としても使えるが、それは別途)
4. **4次元超の黙殺をやめる方向で良いか。** (推奨: 良い。訊くか拒否する)
5. **Browse の npz 展開はローカル先行で良いか。** (推奨: 良い)
