## 1. Footer probe（旧 E3）

`g_footerProbe` は `drawCanvas` が実際に描いた1 frame分の文字列を
`ctx=...;zoom=...;name=...;count=...;` として保持する。値を別実装で再計算する
probeではない。

画像が無い frame では空文字列、画像がある frame では
`ctx=<batch  >  series>;zoom=<zoom NN%>;name=<file>;count=<n/N>;` という契約で、
描画した文字列そのものを保持した。

`--tile-selftest` T13 の実測結果:

| context 行が batch を名乗る | PASS |

## 2. ESC layer probe（旧 E7）

`g_escProbe` は1回の ESC を消費した層を
`popup / textedit / roi / compare / nothing` のいずれかとして記録する。

- `--abstats-selftest` S6: `roi;compare;nothing;` の1本の鎖を確認 — PASS。
- `--browse-keys-selftest`: popupを閉じる各ESCが、ちょうど1層に消費され、その層が
  `popup` であることを確認 — PASS。
- 校正: popupを開かずにESCを送ると、旧検査は通る一方、新probeは
  `chain 'nothing;'` を名指しして FAIL。空振り検査でないことを確認した。

`textedit` 層は記録面だけ追加され、このrunでは実行されていない。当時の残件は
旧 E1 / E2 / E4 / E5 と、text-editを実際に起こすactionだった。

旧 E1/E2 は Files の context menu の項目名・活性・理由と、共有印を含む badge
集合、旧 E4/E5 は toast / Messages 本文と tooltip 本文の観測を指す。線種・色・
線幅のような描画属性（旧 E6）は自動 probe の対象外のままとした。
