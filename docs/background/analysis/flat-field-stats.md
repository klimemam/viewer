## 実装の進め方 (提案 — 規範ではない)

凍結中に運搬側が先に着地した (畳み込み PR #99、reader 発 set PR #101、
Series Analysis パネル PR #102)。推定量はその下流に乗るだけなので、順序は
凍結前の案から差し替える:

1. **σ_fpn 補正 `−C` を共通の蓄積器に入れる** (判断2):
   `recomputeTemporalIfNeeded` / `computeStackStats` / serve
   `runTemporalStats` の3か所は同じ形の sum/sum²/cnt を持っており、追加は
   補正項の算術のみ。合成データ (既知 FPN + 既知 σ_t) の selftest を先に
   赤で書く。**local の ddof=0 → ddof=1 (判断3) は確定済みだが実装は別 PR**
   なので、本項の補正はそれと独立に入れられる — ただし σ_t 側が揃うまで
   σ_fpn の local/server parity は緑にならない (補正項 C が s_t,i² で
   できているため)。順序は問わない、揃って初めて parity が立つ。
2. **(a) の分解を純関数として足す** (σ_p/σ_row/σ_col + H_x/W_y 対応)。
   合成データで検算する単体テストを同時に書く — 既知の σ_p のみ → 比が 0、
   既知の行オフセット → σ_row がそれを回収、W/H を変えても不変、
   マスク下で H_x/W_y 版が漏れを抑えること。Projection へ配線。
3. **縞の固定/時間分離** (σ_row,fix / σ_row,temp) を Temporal に足す。
   誤った推定量 (フレーム毎 σ_row の時間σ) との対比を selftest に残す。
4. **直接 DSNU / PRNU の SetAnalyzer** — reader 発 set (PR #101) の上で、
   1–3 の合成として。拒否 (frame 役割・dark 不在・μ≤0) の文言まで含めて。
5. **分離フィット** — series + dark 役割。レベル毎 σ_fpn² は 1 の再利用。
6. **detrend 段** (多項式面 + ブロック中央値の2方式から)。パラメータを
   結果構造体の**必須フィールド**として持たせる (表示側が省略できない)。

各段で **local と peer が同じ算術を通る**ことを parity で確認する。

### 分離フィットの追加2項 (2026-08-10 確定)

実装 (PR #131) が上げた**判断3 / 判断4** に #57 でユーザーが回答した。番号は
**PR #131 の判断項目**のもので、上の7項リストとは別系列である (本文の (判断N)
印は7項リストの番号を指す)。

3. **dark と sweep の `WxH` 不一致** — **拒否で確定 (2026-08-10, #57)**。
   ユーザーの言葉:「dark, sweep の WxH 不一致は拒否．」

   分離フィットが dark から取るのは**面別スカラー1個** (`μ_ℓ = mean(M_ℓ) −
   mean(M_dark)`) だけで、画素毎の減算はどこにも無い。つまり **`WxH` が違っても
   算術は通り、数が出る** — 危険なのは計算できないことではなく、
   **計算できてしまい、正しい dark で出した数と見分けが付かない**ことである。
   よって直接 PRNU 行と同じ厳しさを採り、**両方の形状を名指しして**拒否する
   (PR #121 の教訓 — 何を拒否したか言わない拒否は行き止まり)。面 (ch / plane)
   の照合は PR #131 のまま**先に**立つ (3ch のメンバは両方同時に食い違うので、
   深い方の文が出る)。規範は (c)「加法性と乗法性の分離」節。

4. **dark が sweep のメンバを兼ねる構成** — **許容で確定 (2026-08-10, #57)**。
   ユーザーの言葉:「dark が sweep のメンバを兼ねるは、そう Analysis Set を
   作ったら許容．」

   「そう作ったら」が理由そのものである — 役割束縛は宣言であって推論ではない
   ので、この重複は set をそう組んだときにしか起きない (「level 0 = dark」は
   linearity の後方互換に閉じたままで、こちらへは広げない)。
   数としては**切片の錨**である: `μ = 0` (同じ stack を同じ関数で畳んだ値の
   差なので**厳密に 0**)、`y` = その dark 自身の補正済み `σ_fpn²` = 直接 DSNU
   行と**ビット一致**する量、そして `x = 0` は切片を読む当の横座標である。
   重み無し OLS (判断5) なので**他のレベルと同じ重みしか持たない** — dark 固有の
   固定パターンがレベル側と違えば、答えを静かに動かすのではなく**残差**に出る。
   許容する以上**黙ってはいけない**ので、結果は**タグ自身**でそれを言う
   (`sweep "…" N levels (level "dark" is also the dark role)`) — 正典の不変条件
   (a)「結果は自分の層と set を名乗る」の下で、1本の stack が1つの推定の中で
   2役を演じている事実は、引用された数が落としてよい情報ではない。

**実装は PR #150** (`core/app/setanalysis.inc` / `core/app/setanalysis_remote.inc`
/ `core/ui/panel_setanalysis.inc`)。形状の文は local と peer の**1関数**
(`sepShapeRefusal`) で、二重役の文も**1箇所** (`sepComposeFit`) で組む。
**線の上を通る物は何も変わっていない** — 判定はどちらの経路でも合成側にあるので
`setfold::foldForm` も `rp::VERSION` も動かない。
