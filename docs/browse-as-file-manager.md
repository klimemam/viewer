# Browse パネルは「接続するもの」ではなく「場所を見るもの」

決定記録 (2026-07-29)。きっかけ: grouped/flat トグルが「出ない」— パネルを
広げても出ない。原因はバグではなく設計で、未接続の Browse パネルは
「Connect to a machine, then pick the file here.」しか描かない。トグルは
接続後の世界にしか存在しない。

ユーザーの判定: 本質と離れている。そのとおりで、これは対症を重ねる場所ではない。

## 何が間違っているか

ローカルとリモートは 1 つのプロトコル (peer + LIST/TILE/MEASURE) に統一されて
いる。それは正しい。間違いは、**プロトコルのライフサイクル概念「接続」を UI の
入口概念にしたこと**。結果:

- パネルを開くと空。ファイルブラウザなのに、開いた瞬間に何も見せない。
- ローカルのフォルダを見るのに「File > Browse Folder (Local)...」という
  別の儀式を知らないといけない。パネル内からは辿り着けない。
- ローカルなのに `[ssh] local peer` を名乗る (セッションフラグから表示を
  導出しているから)。
- 「接続してから選ぶ」は正しい思想だったが、それは**パス文字列を先に
  組み立てさせない**という意味であって、「接続」をユーザーの語彙にする
  という意味ではなかった。

Explorer がネットワーク共有を開くとき、ユーザーは「接続」しない。場所を
クリックする。接続はその裏で起きる。

## あるべき形

**概念はひとつ: 場所 (place)。** ローカルパスも `user@server:~/data` も
同じ「場所」で、場所に入った瞬間に必要なら peer が裏で立ち上がる。

1. **パネルは開いた瞬間から常に中身がある。** 未接続状態は存在しない。
   初期表示は「場所の一覧」:
   - このマシン (ドライブ、ホーム、よく使うフォルダ)
   - ブックマークと最近の場所 (既存の places がそのまま)
   - 既知のサーバー (過去に入ったホスト)
   - 「サーバーを追加...」(今の Start Remote ダイアログの中身)
2. **場所に入る = 必要なら裏で接続。** ローカルは即座、リモートは
   リスト領域にインラインで進捗 (`connecting to trc2...`) を出し、失敗も
   その場所のページにインラインで出す (今のグローバルなエラー枠ではなく)。
   Explorer の「アクセスが拒否されました」ページと同じ文法。
3. **パスバーは何でも受ける。** ローカルパス、`ssh://user@host/path`、
   `host:~/path` — どれを貼っても「その場所へ行く」。入口の分岐が消える。
4. **セッションはリソースであってユーザー概念ではない。** 自動で張り、
   アイドルで畳む。disconnect ボタンは「この場所を忘れる」程度の意味に
   格下げ (置いてもよいが、押す必要が生まれない設計にする)。
5. **表示は場所から導出する。** `[ssh]` タグは現在の場所が実際にリモートの
   ときだけ出る。セッションフラグからではなく場所から導くので、ローカルが
   ssh を名乗る嘘は構造的に消える。
6. **メニューは薄くなる。** File > Browse Folder (Local)... と
   Start Remote (ssh)... は「パネルを開いて場所を選ぶ」の別名になるので、
   最終的には Browse パネルを開くだけの項目に畳める (急がない。移行期は
   両方生かす)。

## 実装スケッチ (大工事ではない)

- `drawPanelRemote` の `if (!B.connected) { ...return; }` を「場所ビュー」に
  置き換える。描くものは既存の places (ブックマーク/最近) + ドライブ列挙 +
  サーバー一覧 + 追加ボタン。
- `App::RemoteBrowse` は「現在の場所」になる (`connected` は内部状態に
  降格)。`rbGoTo(place)` が場所の種類を見て、必要なら遅延で
  `startRemote`/local peer 起動を rbDefer 経由で行う。
- 接続待ちとエラーは listing 領域のインライン表示 (専用の ph 行の親戚)。
- 既存の selftest 群 (`--browse-*`, `--localbrowse-*`) は startRemote を
  直接呼ぶので影響しない。追加で「パネルを開いた直後に場所一覧が空でない」
  を headless で assert する。
- ツールバー/フィルタ/grouped/flat/tree は接続後の世界のまま (場所ビューには
  出さない — 場所一覧に flat/grouped の意味はない)。

## やらないこと

- プロトコル層の変更。peer/セッション機構はそのまま (それは正しい層)。
- 「接続してから選ぶ」の放棄。むしろ徹底する — 接続すら選ばなくてよくなる。

## 順序

browse-polish (文言・Esc・列幅などの小修正) と review-fixes のマージを先に
済ませ、その上でこの入口反転を独立ブランチとして実装する。browse-polish が
今直している「空状態にローカル入口を足す」は、この設計への踏み石として
そのまま活かす (場所ビューが入れば自然に置き換わる)。
