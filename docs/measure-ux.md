# Measure UX — 測定体験の理想形

「Measure メニュー以下の項目や使い勝手、結果の提示が若干寂しい」への回答。
このファイルが理想の定義で、実装はここに書いた順序と理由に従う。
対象は Measure メニュー / Analysis パネル / 結果グリッド / カーブプロット。
Series Analysis(旧 Linearity)機能・remote/ssh 系・README は対象外(別導線で構築中)。

## 原則 — 測定ツールの結果は「それ単体で証拠になる」こと

ビューアの他のパネルは「見る」ためのものだが、Measure の出力は報告書や
チケットに貼られる。だからスクリーンショット1枚が自己記述的でなければ
ならない: **何を・どこで(provenance)・いつ・何に対して測ったか**が数値と
同じ画面に写ること。数値には**量と単位**が必ず付くこと。これが全設計判断の
基準である。

## 1. メニュー — 「何を知りたいか」で選ばせる

プラグインのファイル構成 (`stats/…`, `iso12233/…`) はカテゴリ名としては
実装の都合であって、ユーザーの頭の中の質問は「ノイズはいくつか」「解像は
出ているか」「ムラはあるか」である。メニューは質問で束ねる:

| 質問グループ | 項目 (category/name) |
|---|---|
| Noise / SNR | noise/floor、(連番があれば) Temporal パネルへの導線 |
| Resolution / Focus | iso12233/e-sfr、sharpness/gradient |
| Uniformity / Flat field | uniformity/prnu-fpn |
| Statistics / Sanity | stats/moments |

未知のカテゴリ(サードパーティ)は従来どおりカテゴリ名のまま末尾に並ぶ。
束ね方はホスト側の小さな対応表で、プラグイン ABI には触れない。

- **前提条件はツールチップ**(ABI v2/v3 の `description`。同梱プラグインは
  v3 化して自己申告に一本化)。メニュー右列は category/name を出し、
  項目の正体(規格番号)を隠さない。
- **満たせない前提はグレーアウト+理由**。ただしホストが機械的に判定できる
  ものだけ: 画像がない / e-SFR に CFA モザイクを渡そうとしている /
  temporal に連番がない。「フラットフィールドであること」のような
  ホストに知り得ない前提は無効化せず、ツールチップで言う。
  ホストが嘘の判定をするくらいなら実行してプラグインのエラーを見せる。
- **Measure again (`M`)**: 直前の測定を現在の画像・ROI で再実行。
  メニュー先頭に置き、プレーンキー `M` を全域ショートカットにする
  (比較対象を切り替えながら M を連打する、が多 ROI 比較の基本動作)。
- auto 再実行のトグルもメニューに置く(パネルまで行かなくても切れる)。

## 2. 使い勝手 — 測ったら結果が目の前に来る

- Measure メニューをクリックしたら **Analysis パネルを表示してフォーカス**
  する。「実行はされたがどこに出たか分からない」を作らない。`M` も同じ。
- **実行状態の1行**(ステータス行)を結果グリッドの直上に常設する。内容:
  `[local] 画像名 · 対象(whole / N ROIs) · 表示レンジ · 実行時刻 · 所要 ms ·
  アナライザ名 <version> (プラグインファイル名)`。
  未実行なら「まだ実行していない (Run / M)」。この行が provenance であり、
  スクリーンショットの自己記述性を担う。高さは状態によらず一定
  (ホバーや状態遷移でレイアウトが跳ねない)。
  - **誰が計算したか** (#46): アナライザ名・版・dll ファイル名は行に、
    フルパスは行のホバー(ツールチップ)と持ち出しの `# plugin:` 行に出す。
    ファイルはホスト側の帳簿(登録時に「どのファイルが登録したか」を記録。
    ABI には触れない)、**版はプラグインの申告**(ABI v3 記述子の `version`
    欄)で、ホストは逐語で運ぶだけ —— 解釈も順序づけも正規化もしない。
    **V1/V2 のアナライザは版を名乗らないので `<…>` ごと出ない**。空欄を
    埋めるための推測はしない(dll のファイル版リソースも読まない):
    出ていない版は「宣言されていない」であって「不明」ではない
    ([abi-v3.md §11](abi-v3.md)、[analysis-layers.md §8](analysis-layers.md))。
- **stale の可視化**: auto オフで入力(画像・ROI・レンジ・CFA)が変わったら、
  ステータス行に琥珀色で「inputs changed - Run (M)」を出す。古い数値を
  新しい画像の数値として読ませないための、auto オフ時の安全網。
  auto オンとの関係はツールチップで明示: auto = stale になった瞬間に再実行。
- **多 ROI 比較が主ワークフロー**: 列ヘッダを ROI の色(キャンバスの
  オーバーレイ・プロットと同じパレット)で塗る。画面上の枠・曲線・列が
  一目で対応する。

## 3. 結果の提示 — 単位・主役数値・持ち出し

- **unit 列**: グリッドに metric 名の隣へ単位列を常設。単位はキー名が
  自己申告するもの(`snr_db`→dB、`*_pct`→%、`mtf50 (cy/px)`→cy/px)は
  そこから、画像値系(mean/std/noise/percentile)はホストが dtype から
  決める: 整数系 dtype は DN、float は単位を断定せず dtype 名を出す
  (float の .npy が反射率か e- かはファイルには書かれていない。
  Inspector と同じ規約)。相対指標(sharpness)は a.u.、無次元は ratio。
- **主役数値の強調**: アナライザごとの見出し数値(mtf50、prnu_pct、noise、
  snr_db)の行をアクセント色で強調する。グリッドは全数値を保持しつつ、
  「まずこれを読め」を視覚で言う。**ABI v3 記述子はこれを自分で申告する**
  (`headline`。申告なし = 見出しなし)。V1/V2 記述子だけがホスト側の
  対応表を通る([abi-v3.md §3.2](abi-v3.md))。
- **数値は右揃え・固定幅列**(textNum 規約)。テキスト行(method/note)は
  左揃えのまま。
- **リファレンス線**: プロットに任意の y= 基準線(規格値・合格ライン)を
  1本引ける。値はセッションに保存。線があるだけで「合否」が図から読める。
- **プロットのホバー読み出し**: カーソル位置の x にスナップして各 ROI の
  y 値をツールチップ表示。曲線から数値を目で補間させない。
- **持ち出し**: グリッドは「Copy (TSV)」でクリップボードへ(先頭行に
  provenance を # コメントで含める)。カーブは「Export CSV...」で
  series ごとの wide 形式(x, ROI1, ROI2, …)。どちらも列に量と単位が付く。
  どちらも2行目に `# plugin: <version> dll のフルパス` を含める — 報告書が
  引用するのはここで、ステータス行はファイル名まで、フルパスは持ち出し側の
  仕事。version を名乗らない V1/V2 では `# plugin: dll のフルパス` のまま
  (version が前に来るのは、パスに空白がありうるため —— 後置だとパスの一部と
  区別できない)。

## 4. やらないこと(今回のスコープ外)

- **非同期実行**: 測定は明示トリガ(Run / M / auto の stale 検知)の単発で、
  毎フレームではない。現状の同期実行は数 Mpx で数十 ms であり、
  ワーカー化はフレーム所有権(処理・クローズとの競合)の問題を持ち込む。
  遅い測定が現れた時点で cancel 付きワーカーを設計する。
- **アナライザ専用 UI**: 出力は「グリッド+曲線」の2型に固定
  (ARCHITECTURE.md の governance)。強調・単位・基準線はすべて
  この2型の上の汎用装飾である。
- **params_schema**(測定パラメータの宣言 UI)は ABI v2 の未実装項目の
  まま。今回の装飾はパラメータを持たないので依存しない。
- **Series Analysis(旧 Linearity)/ remote 系 / README.md** には触れない。
