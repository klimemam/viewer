## 1. スロットとは何か【立場】

**スロットは「stack への参照 + follow 規約」である。画像そのものではない。**

`ed14f86` 以降、B もエクストラも同じ一つの規則 (`followFrame`) で解決される:

- ピン (メンバ frame の uid) が **stack を指名**し、クリックした frame は
  「follow が切れているときに見せる frame」を兼ねる。
- follow ON かつ両側 stack なら、**A のフレーム番号を持つ兄弟**が答え。
- 単発 frame は長さ1の stack として退化し、動かない (dark / golden sample)。
- A 自身の stack へのピンは follow しない (frame 対 frame 比較のため —
  Shift+B の流儀)。
- A の番号の frame が無ければ **diverged**: ピンした frame を [stale] 付きで
  見せる。黙って別番号を「対」として見せることは決してしない。

この定義から次が従う。

**B は「スロット B」になる。** 今は `compareBUid`/`compareB`/`compareBSeq` と
`cmpExtra` の二本立てだが、意味はもう同じ (解決規則が同一) なので、**一本の
順序付きリスト `slots[0..]` に畳む**。`slots[0]` が B。B だけが持つ特権は
「二枚モード (wipe / diff / flip) の相手である」ことと「既定で自動補充される
(`ensureCompareB`) こと」の2点で、これはリストの先頭という**位置**の性質と
して残す。resolveB / cmpB / setCompareB は slots[0] へのアダプタとして
存置し、呼び出し側 (~40箇所) は段階的に書き換える。

**A はスロットではない。カーソルである。** アプリ全体 (Inspector・Histogram・
Analysis・レンジスコープ) が `cur()` に紐づいており、A をピン化することは
項目28 が言う「`cur()` の単一性を壊す」問題そのもの。そこは項目28-4
(パネルを画像にピン留め) の話であって比較の話ではない。比較の文書としての
立場: **A = いま見ているもの、B.. = 留めたもの**。この非対称は仕様であり、
画面の言葉もそれで統一する (「A を動かす」「D を留める」)。

**1画像1文字。** 同じ画像が B と D を兼ねると、同じ画素が2枚のパネと2行の
表に出る。`ed14f86` で入れた規律 (既定 B は文字持ちを飛ばす / 明示指名は
昇格 = 文字を放す / B は文字を取れない) をそのまま正式仕様にする。

**文字は「位置」であって「名前」ではない。** D を外せば E が D になる
(tile selftest T7 が固定済み)。歯抜けの文字を保持する案は捨てる — 表・色・
キャッシュはすべて添字で紐づいており、歯抜けは「欠測」に見える。

## 2. follow とフレーム発散 (divergence)

**規則は全スロット共通で一つ** (`followFrame`)。スロットごとに独立に発散する:
C は frame 200 を持ち D は 150 で終わる、が普通に起きる (再撮で枚数が違う)。

見せ方 (実装済みを正式化):

- タイルのバッジ: `D  name  [stale]`。
- Projection / Temporal: 琥珀の注意行「follow-frame: slot D: no frame 200 in
  that stack …」。文は B の `g_abFollowDiverged` と同型 — **同じ主張には同じ
  語彙** ([stale])。
- 発散中の数値行は消さない。**ピンした frame の数値を出し、stale と言う**。
  消すと「D が壊れた」に読める。frame が戻れば (remote の遅着など) 黙って復帰。

## 3. 画像側のレイアウト — N に意味のある見せ方だけ

項目19 の分析のとおり、wipe / diff / flip は **2枚の意味しかない**。3枚の
ワイプは無い。無理に一般化しない。

- **タイル (Split)** — N の主役。実装済み: 1 zoom / 1 center、等幅、狭ければ
  枚数と必要幅を言って退く。これで足りる場面が大半 (同一シーン N 撮りの
  一覧比較)。
- **順次点滅 (N-blink)** — 追加する価値がある唯一の新レイアウト。flip の
  一般化: 全画面で A → B → C → … をスロット順に巡回、文字を大きく重畳。
  目は「ちらつく場所」を差分として拾う — 2枚で有効なものは N でも有効。
  手動送り (B / Space) と auto (`flipPeriod`) をそのまま流用。
- **wipe / diff は厳密に A 対 B のまま。** 差分の基準は常に A (符号 A−B、
  画像側 Diff と数値 Δ 列の符号は既に一致)。「A と D の差分が見たい」の
  答えは**昇格**: D を B にする (Files 右クリック 1回 / 状態バー)。第4の
  概念 (「アクティブパートナー」のような選択状態) は**作らない** — 文字が
  動く方が、隠れた選択が一つ増えるより読める。昇格すると D の文字が
  空くのは §1 の「位置」規則どおり。
- 表示中スロット数の上限はタイル幅の式 (`tileMinPaneW`) が既に握っている。
  それを超える指定は今と同じく「言って退く」。

## 4. 数値側 — 残っている N 化

Projection は済 (行 = スロット、wide 表は行軸をスロットに空けてある)。
Temporal はチャート済・表は A|B|Δ のまま。残り:

- **キャッシュの N 化が先決。** ~~`hist[2]` / `temporal[2]`~~ → **`hist[2]` のみ**。
  この行は書かれた時点 (`3fc19f4`) では正しかったが、同じ日の `0f3020b` で
  `temporalExtra` が入っており、temporal は当時すでに N 化されていた。文書が
  コードより古いだけで、残っていたのは `hist` 一本。`histExtra` として
  `projExtra` / `temporalExtra` と同じ「**cmpExtra 添字 = 文字**」の
  ベクタで着地済み。
- **Histogram の N 重ね**: スロット色 (`temporalSlotInk`) で N 本。ただし
  CFA 4面 × N は読めないので、**N ≥ 3 か CFA では plane セレクタで1面に
  絞ったときだけ重ねる** (ab-stats-plan §2 の「8面は読めない」の一般化)。
  絞らないときは「plane を選べば重なります」と言って A/B のみ。
- **Temporal 表**: A|B|Δ|Δ% の列対は2項のまま正しい。Δ は「A と B の差」で
  あって N の性質ではない。スロットはチャートの線 (済) と、必要なら
  「A|各スロット」の値列 (Δ 無し) を wide 表に足すに留める。
- **ROI 表**: 1 ROI = N 行 (A行/B行方式の拡張)。行数 × N の描画コストは
  ab-stats-plan §6 の再測定に含める。既定は A+B のみ、N 行はトグル。
- **Analysis**: `Run on B` を `Run on slot …` に一般化 (自動実行しないのは
  そのまま)。

## 5. 入る・出る・キー

`ed14f86` 後の形をそのまま正式仕様とする:

| キー | 動作 |
|---|---|
| `C` / `\` | モード巡回 Off → wipe → split → diff → flip → Off。**Off は常に A 単独** |
| `Shift+C` | Split を直接アーム = スロット一覧 (タイル)。スロット無しなら言う |
| `Shift+\` | A ↔ B swap (二重予約は解消済み。JIS は状態バーのボタン) |
| `Shift+B` | いまの frame を B にピン |
| `B` (押下中) | B を全画面フラッシュ (タイルより優先。既存) |

- スロットの**追加は Files 右クリックのみ**とする (文字を明記した項目)。
  修飾キー付きクリックのような不可視の入口は作らない (`caa5216` の判断を
  維持)。
- **出口は Off**。タイル中に C を3回でも、View メニューでも、必ず「A 単独」
  に着地する。スロット文字は Off でも Files と数値側に残る — 比較モードは
  見せ方であってスロットの生死ではない。
- **全解放**: View > Compare A/B に「Release all slots」を1項足す (今は
  1個ずつ外すしかない)。

## 6. Files の見せ方

- 行頭の文字バッジ (実装済): frame 行はその frame の文字、stack 行は中の
  frame が持つ文字を**全部** (`BC` など)。B と同じインク・同じ視覚重量。
- 右クリック: `Add as compare slot D` / `Remove from compare slot D` /
  B 系項目 (既存)。B の行にはスロット項目を出さない (1画像1文字)。
- バッジをクリックで外す案は**採らない** — 行クリック (選択) との誤爆が
  読みより高くつく。

## 7. セッション・上限・メモリ

- **セッション**: `cmpslot` (path + frame) と B の保存は済。B がスロット化
  したら `cmpslot` の1行目が B になるだけ。旧キー (`cmpb` 系) は読み続ける
  (セッションは名前で復元する正典どおり)。
- **上限**: `SLOT_LETTERS` の14枠は過剰。**A+B+6 (エクストラ6) に切り下げ**を
  推奨。根拠: 8 パネは 1600px 缶バスに最小幅でちょうど収まる (tile selftest
  T6 の実測)。9 枚目からはタイルも点滅巡回も読めず、数値表も横に破綻する。
  数値側だけ多く持てる設計 (画像は8まで・表は14) は「画面ごとに違う上限」で
  説明コストの方が高い。
- **メモリ (1スロット当たり、構造体レイアウトからの算出値)**:
  - Histogram: bins 4×256×4B ≈ **4.2 KB** (固定)
  - Projection: 5系列 × (W+H) × 4B — 4000×3000 で **137 KB**
    (multi の 80×64 では 0.6 KB)
  - Temporal: 3 × frames × 4B — 300 frames で **3.6 KB**
  - 合計 ≈ **145 KB/スロット @ 12Mpx + 300f** — キャッシュは安い。
  - 本当に高いのは (a) **タイル表示中の GL テクスチャ = W×H×4B ≈ 46 MB/枚
    @ 12Mpx** (表示中のみ、既存の使用順 evict に乗る) と、(b) follow 中の
    **ステップ当たり再計算 × N** (これは `abStepBusy` throttle が既に N 対応)。
    上限の実効的な根拠はキャッシュ RAM ではなく可読性と VRAM。

## 8. 今の暫定から残るもの / 置き換えるもの / 移行

**残る (そのまま正式化)**: followFrame と per-slot divergence、resolveSlots
(文字 = 添字が解決結果と一緒に運ばれる形)、タイルとその退き方、Files の
文字バッジ、昇格規則 (set-as-B が文字を放す)、Off = A 単独、`cmpslot`
セッション、projExtra/temporalExtra の添字規約、`temporalSlotInk` の N 色。

**置き換える**:

1. `compareBUid`/`compareB`/`compareBSeq`/`lastCompareBUid` → `slots[0]` +
   アダプタ (resolveB は残す)。呼び出し ~40 箇所、機械的。
2. `hist[2]`/`temporal[2]` → 文字添字ベクタ (proj は済)。`abStatsFrame` の
   「slot 1 だけ潰す」も全スロット版へ。
3. `SLOT_LETTERS` 14 → 6。
4. flip → N-blink (2枚のときの見た目は今と同一)。

**移行コスト見積り**: 2 が本体 (recompute 呼び出しの引数は既に参照渡し化
済みなので配列化は小さい)。1 は広いが機械的。3・4 は小。どれも selftest
(S/T 群) がそのまま回帰網になる。

## 9. 推奨する形 (結論)

比較とは**1本の順序付きスロット列**である: A はカーソル (ピンではない)、
B..H は「stack への参照 + follow」で、各自が A のフレーム番号に追従し、
追従できなければその場で [stale] と言う。二枚モード (wipe/diff/flip) は
常に A 対 B で、別の文字と比べたければ**昇格**が唯一の操作 — 隠れた
「選択中パートナー」状態は作らない。画像側はタイル + 順次点滅 (N-blink)
の2本、数値側は全パネルがスロット添字のキャッシュで N に伸び、上限は
A+B+6 とする。

**そこへ至る増分** (各増分の末尾で selftest を拡張):

- **I1**: `hist`/`temporal` のスロット添字化 + Histogram N 重ね (plane
  セレクタ連動)。数値側の N 化がここで完了。
- **I2**: B を slots[0] に畳む (アダプタ経由、挙動不変)。上限を6に。
- **I3**: N-blink (flip の置き換え)。
- **I4**: Release all slots、ROI 表 N 行トグル、`Run on slot`。
- **I5** (別線、項目28): パネルのピン留めがスロットを対象に取る —
  「Histogram を D に固定」。スロットが比較以外の使い道を持つのはここから。

## 10. 表示レイアウト — ユーザー判断 (2026-08-04)

issue #60 の続きとして、**画像側の見せ方**が決まった。原文:

> A/B/C....(compare-n)の場合，並べて表示(side by side, もしくは今後はグリッド
> レイアウト) か，Difference/Blinkの1表示に集約の二通りになると思いますので，
> これをサポートしてください．

> N が2を超えたらグリッドは，これは自明ではない．Grid にするか本当の
> SideBySide にするかはユーザーが選ぶべき．(Fast Stone でつかいづらいなっと
> 個人的には感じるところ)

> 実装的には，side-by-side がグリッドの特殊形，というのには異論はありません．

**二系統ある。**

1. **並べる (laid out)** — side-by-side と grid。
2. **1枚に畳む (collapsed)** — Difference / Blink。N 枚から1枚の絵を作る。

**並べる方の中の選択は、枚数から導出してはならない。** ここが判断の核心で、
§3 が「タイル」一本で済ませていたところを置き換える:

- **実装は共有する。** グリッドエンジンは1つ。side-by-side は
  **行数を1に固定したグリッド**である。レイアウト経路を2本書かない。
- **モードはユーザーが選ぶ。** 既存の compare モードの隣に並ぶ設定で、
  他と同様に永続する。**スロットを1つ足したくらいで勝手に変わってはならない。**
  5枚目を立てた瞬間に既に見ていた4枚が動くのは、ユーザーが頼んでいない理由で
  画面を作り直すこと — FastStone が使いづらい、と名指しされたのはこれ。
- **どちらも任意の N で成立する。** N=2 のグリッドも、N=8 の
  side-by-side (1行のまま細くなる / 横スクロール) も、どちらも正当な要求。
- どちらが正しいかは**画像のアスペクト比と何を比べたいか**で決まるのであって、
  枚数では決まらない。

**チャートは重ねる (overlay)。** タブでも表でもない。原文:
「同じチャートに複数プロット重ねるスタイルで．A/B/C....とラインカラーとかを
合わせたくなるので，そこは考慮してください．」

**色はスロットの持ち物。** 文字 (`SLOT_LETTERS`)・Files のバッジ・タイルの
バッジ・チャートの線は**同じ1つのスロットの別々の顔**なので、色は1箇所
(`slotInk`) が決め、各パネルはそれを訊きに行く。パネルごとに独自の配色を
作ることは、既に名前のあるものに二つ目の名前を与えることになる。
`ui_theme` の「アクセント色は『いまどこ/何が選択されているか』専用」規則とは
衝突しない — スロット色はプロット矩形の中のデータインクであって、
ウィジェットの選択表現ではない。

**足りなくなったら黙らずに言う。** `slotInk` が判別できるのは
`slotInkCount()` 個で、その先は剰余で先頭の色に戻る。**2つのスロットが同じ色**
は、配列長の代わりに色が嘘をついているだけで #60 と同じ欠陥。描ける本数で
打ち切り、**打ち切った文字を名指しする**。CFA 4面 × N も同じ扱い
(1面に絞れば重なる、と言う)。
