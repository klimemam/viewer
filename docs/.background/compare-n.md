## 1 の続き — B をスロット列に畳む案

**B は「スロット B」になる。** 今は `compareBUid`/`compareB`/`compareBSeq` と
`cmpExtra` の二本立てだが、意味はもう同じ (解決規則が同一) なので、**一本の
順序付きリスト `slots[0..]` に畳む**。`slots[0]` が B。B だけが持つ特権は
「二枚モード (wipe / diff / flip) の相手である」ことと「既定で自動補充される
(`ensureCompareB`) こと」の2点で、これはリストの先頭という**位置**の性質と
して残す。resolveB / cmpB / setCompareB は slots[0] へのアダプタとして
存置し、呼び出し側 (~40箇所) は段階的に書き換える。

## 3. 画像側のレイアウト — N に意味のある見せ方だけ

項目19 の分析のとおり、wipe / diff / flip は **2枚の意味しかない**。3枚の
ワイプは無い。無理に一般化しない。

- **タイル (Split)** — N の主役。実装済み: 1 zoom / 1 center、等幅、狭ければ
  枚数と必要幅を言って退く。これで足りる場面が大半 (同一シーン N 撮りの
  一覧比較)。
- **順次点滅 (N-blink)** — 追加する価値がある唯一の新レイアウト。flip の
  一般化: 全画面で A → B → C → … をスロット順に巡回、文字を大きく重畳。
  目は「ちらつく場所」を差分として拾う — 2枚で有効なものは N でも有効。
  手動送り (B / Space) と auto (`flipPeriod`) をそのまま流用。
- **wipe / diff は厳密に A 対 B のまま。** 差分の基準は常に A (符号 A−B、
  画像側 Diff と数値 Δ 列の符号は既に一致)。「A と D の差分が見たい」の
  答えは**昇格**: D を B にする (Files 右クリック 1回 / 状態バー)。第4の
  概念 (「アクティブパートナー」のような選択状態) は**作らない** — 文字が
  動く方が、隠れた選択が一つ増えるより読める。昇格すると D の文字が
  空くのは §1 の「位置」規則どおり。
- 表示中スロット数の上限はタイル幅の式 (`tileMinPaneW`) が既に握っている。
  それを超える指定は今と同じく「言って退く」。

## 4. 数値側 — 残っている N 化

Projection は済 (行 = スロット、wide 表は行軸をスロットに空けてある)。
Temporal はチャート済・表は A|B|Δ のまま。残り:

- **キャッシュの N 化が先決。** `hist[2]` / `temporal[2]` を `projExtra` /
  `temporalExtra` と同じ「**cmpExtra 添字 = 文字**」のベクタに置き換える
  (`ed14f86` で projExtra はこの添字規約に統一済み)。これが済むまで
  Histogram に C 以降は出せない。
- **Histogram の N 重ね**: スロット色 (`temporalSlotInk`) で N 本。ただし
  CFA 4面 × N は読めないので、**N ≥ 3 か CFA では plane セレクタで1面に
  絞ったときだけ重ねる** (ab-stats-plan §2 の「8面は読めない」の一般化)。
  絞らないときは「plane を選べば重なります」と言って A/B のみ。
- **Temporal 表**: A|B|Δ|Δ% の列対は2項のまま正しい。Δ は「A と B の差」で
  あって N の性質ではない。スロットはチャートの線 (済) と、必要なら
  「A|各スロット」の値列 (Δ 無し) を wide 表に足すに留める。
- **ROI 表**: 1 ROI = N 行 (A行/B行方式の拡張)。行数 × N の描画コストは
  ab-stats-plan §6 の再測定に含める。既定は A+B のみ、N 行はトグル。
- **Analysis**: `Run on B` を `Run on slot …` に一般化 (自動実行しないのは
  そのまま)。

## 7. セッション・上限・メモリ

- **セッション**: `cmpslot` (path + frame) と B の保存は済。B がスロット化
  したら `cmpslot` の1行目が B になるだけ。旧キー (`cmpb` 系) は読み続ける
  (セッションは名前で復元する正典どおり)。
- **上限**: `SLOT_LETTERS` の14枠は過剰。**A+B+6 (エクストラ6) に切り下げ**を
  推奨。根拠: 8 パネは 1600px 缶バスに最小幅でちょうど収まる (tile selftest
  T6 の実測)。9 枚目からはタイルも点滅巡回も読めず、数値表も横に破綻する。
  数値側だけ多く持てる設計 (画像は8まで・表は14) は「画面ごとに違う上限」で
  説明コストの方が高い。
- **メモリ (1スロット当たり、構造体レイアウトからの算出値)**:
  - Histogram: bins 4×256×4B ≈ **4.2 KB** (固定)
  - Projection: 5系列 × (W+H) × 4B — 4000×3000 で **137 KB**
    (multi の 80×64 では 0.6 KB)
  - Temporal: 3 × frames × 4B — 300 frames で **3.6 KB**
  - 合計 ≈ **145 KB/スロット @ 12Mpx + 300f** — キャッシュは安い。
  - 本当に高いのは (a) **タイル表示中の GL テクスチャ = W×H×4B ≈ 46 MB/枚
    @ 12Mpx** (表示中のみ、既存の使用順 evict に乗る) と、(b) follow 中の
    **ステップ当たり再計算 × N** (これは `abStepBusy` throttle が既に N 対応)。
    上限の実効的な根拠はキャッシュ RAM ではなく可読性と VRAM。

## 8. 今の暫定から残るもの / 置き換えるもの / 移行

**残る (そのまま正式化)**: followFrame と per-slot divergence、resolveSlots
(文字 = 添字が解決結果と一緒に運ばれる形)、タイルとその退き方、Files の
文字バッジ、昇格規則 (set-as-B が文字を放す)、Off = A 単独、`cmpslot`
セッション、projExtra/temporalExtra の添字規約、`temporalSlotInk` の N 色。

**置き換える**:

1. `compareBUid`/`compareB`/`compareBSeq`/`lastCompareBUid` → `slots[0]` +
   アダプタ (resolveB は残す)。呼び出し ~40 箇所、機械的。
2. `hist[2]`/`temporal[2]` → 文字添字ベクタ (proj は済)。`abStatsFrame` の
   「slot 1 だけ潰す」も全スロット版へ。
3. `SLOT_LETTERS` 14 → 6。
4. flip → N-blink (2枚のときの見た目は今と同一)。

**移行コスト見積り**: 2 が本体 (recompute 呼び出しの引数は既に参照渡し化
済みなので配列化は小さい)。1 は広いが機械的。3・4 は小。どれも selftest
(S/T 群) がそのまま回帰網になる。

## 9. 推奨する形 (結論)

比較とは**1本の順序付きスロット列**である: A はカーソル (ピンではない)、
B..H は「stack への参照 + follow」で、各自が A のフレーム番号に追従し、
追従できなければその場で [stale] と言う。二枚モード (wipe/diff/flip) は
常に A 対 B で、別の文字と比べたければ**昇格**が唯一の操作 — 隠れた
「選択中パートナー」状態は作らない。画像側はタイル + 順次点滅 (N-blink)
の2本、数値側は全パネルがスロット添字のキャッシュで N に伸び、上限は
A+B+6 とする。

**そこへ至る増分** (各増分の末尾で selftest を拡張):

- **I1**: `hist`/`temporal` のスロット添字化 + Histogram N 重ね (plane
  セレクタ連動)。数値側の N 化がここで完了。
- **I2**: B を slots[0] に畳む (アダプタ経由、挙動不変)。上限を6に。
- **I3**: N-blink (flip の置き換え)。
- **I4**: Release all slots、ROI 表 N 行トグル、`Run on slot`。
- **I5** (別線、項目28): パネルのピン留めがスロットを対象に取る —
  「Histogram を D に固定」。スロットが比較以外の使い道を持つのはここから。
