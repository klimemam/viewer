# viewer 操作マニュアル

対象バージョン: main ブランチ(プラグイン ABI v2)。
クイックスタートと機能一覧は [README](../README.md)、測定の中身は [analyzers.md](analyzers.md)。

---

## 1. 画面構成(ドッキング式パネル)

パネルは**自由に配置できます**(タイトルをドラッグしてドッキング/タブ化/フロート化)。
配置は自動保存され(`%APPDATA%/viewer/layout.ini`、Linux/macOS は `~/.config/viewer/`)、
`View > Panels` で表示切替、`View > Panels > Reset layout` で既定配置に戻せます。

| パネル | 役割 | 既定位置 |
|---|---|---|
| **Files** | 画像・塊(連番)の一覧、フレームスライダ | 左 |
| **Image View** | キャンバス(ルーラー・ツール) | 中央 |
| **Inspector** | ホバー画素値、画像情報、レンジ/解釈/カラーマップ/crop | 右 |
| **ROIs** | **ROI/POI 一覧 + 基本統計**(mean/std/min/max) | **フローティング** |
| **Analysis** | **詳細解析**(解析プラグイン、ROI×指標グリッド、カーブ) | **フローティング** |
| **Histogram** | ヒストグラム(選択 ROI 追従) | 下部タブ |
| **Projection** | H/V 射影とその統計 | 下部タブ(既定は非表示) |
| **Temporal** | 時間ノイズ/固定パターン、frame mean グラフ | 下部タブ |
| **Projection** | 水平/垂直射影とその統計 | 下部タブ(既定は非表示) |

**基本 / 詳細の切り分け**: ROI を置いた瞬間に見たい値(平均・標準偏差・最小最大)は
ROIs ウィンドウの表に常時出ます。プラグインによる重い測定(ノイズフロア、PRNU、SFR…)は
Analysis ウィンドウで実行し、結果は ROI ごとの列に並びます。どちらも同じ ROI に紐づきます。

## 2. ファイルを開く

方法は3つ: `Ctrl+O` / ウィンドウへ**ドラッグ&ドロップ** / **コマンドライン**(§9)。

### 2.1 .npy
そのまま開けます。対応 dtype: u8/i8/u16/i16/u32/i32/f32/f64/bool。
ビッグエンディアン・Fortran order 対応。

**形状の解釈**(先頭軸がチャンネル数として不自然なら「フレーム軸」= 塊として読み込み):

| 形状 | 解釈 |
|---|---|
| `(H,W)` | 1ch 画像 |
| `(H,W,C)` C≤4 | Cch 画像 |
| `(C,H,W)` C≤4 | Cch 画像(CHW→HWC 変換) |
| **`(F,H,W)`** F>4 | **F フレームの塊**(1ch) |
| **`(F,H,W,1)`** | **F フレームの塊**(1ch) |
| **`(F,H,W,C)`** C≤4 | **F フレームの塊**(Cch) |
| `(F,C,H,W)` | F フレームの塊(CHW→HWC) |
| 5次元以上 | 先頭軸の [0] を取って上記へ |

### 2.1b .npz(非圧縮 / 圧縮)

`np.savez`(非圧縮=stored)と `np.savez_compressed`(deflate)の**両方**に対応。
中の全配列を読み込み、それぞれ `ファイル名:配列名` として一覧に並びます。
配列がフレーム軸を持つ場合(`(F,H,W)` など)はその配列だけが塊になります。
zip64 のサイズ拡張にも対応。読めない配列があっても他の配列の読み込みは継続します。

### 形状の曖昧さ

`(3,H,W)` のように **先頭が4以下だと「3チャンネル画像」と「3フレーム」が曖昧**です。
既定はチャンネル(従来の挙動)。フレームとして読みたい場合は `--npy-axis frames` を指定します。
塊として読まれた場合は Files パネルに `12f` のようにフレーム数が出て、
時間方向解析(Temporal)と `←`/`→` のフレーム送りがそのまま使えます。

### 2.2 ベタバイナリ (.bin / .raw / .yuv / .dat ...)
RAW ダイアログが開きます。指定は**直交する2軸**:

| 軸 | 選択肢 | 意味 |
|---|---|---|
| **pixel format** | u8 / u16 / f32 / f64(+エンディアン) | 1サンプルがファイル内でどう格納されているか |
| **interpretation** | Gray / RGB / BGR / RGBA / BGRA / **Bayer / Quad Bayer**(+RGGB/BGGR/GRBG/GBRG) | サンプル列を何チャンネルの何として読むか |

任意の組合せが有効(例: **RGGB × float32**)。補助機能:
- **サイズ候補**: ファイルサイズを割り切れる W×H を自動列挙
- **ファイル名ヒント**: `..._1920x1080_`、`rggb`、`bayer`、`quad`、`f32` などを自動認識
- **offset**: 先頭ヘッダのスキップ、**crop on load**: 巨大ダンプの部分読み(§5.3)

### 2.3 開いた後にフォーマットを変える
- **Interpret**(右パネル、1ch 画像): Gray ⇔ Bayer ⇔ Quad Bayer とパターンを**即時切替**。
  npy で受け取った CFA データにも使える(メタデータのみ、再読込なし)
- **Reinterpret raw...**: RAW 由来の画像を画素フォーマットから読み直し(ダイアログ再表示、
  ビュー位置・ズームは維持)

## 2.4 連番(シーケンス / 塊)

**1枚開くと、同じフォルダの連番を1つの「塊」として裏で読み込めます。** 塊は
**時間方向の解析ができる単位**で、フレームは同じデコードレシピ・同じ表示レンジを共有します。

- **検出**: ファイル名のうち **フォルダ内で実際に変化している数字フィールド**を番号と判定
  (`shot_0007_1920x1080.raw` は `0007` でグループ化され、解像度の数字では割れない)
- **読み込むかの選択**: 既定は毎回確認。`File > Sequence loading` で
  「毎回確認 / 常に読む / 読まない」を切替、モーダルの「remember my choice」でも設定される。
  CLI は `--sequence ask|always|never`
- **バックグラウンド**: 読み込み中も操作可能。左パネルに進捗と Stop ボタン。
  メモリ上限(約6GB)に達すると自動停止
- **メモリ**: GPU テクスチャは直近12フレームのみ常駐(古いものは自動的に解放・再生成)
- **セッション**: 塊ごとに1行(**見ていたフレーム番号**+再読込レシピ)を保存。全フレームは書きません

### フォルダを開く(複数の塊を一括)

`File > Open Folder...`(`Ctrl/Cmd+Shift+O`)、フォルダのドラッグ&ドロップ、
または CLI 引数にフォルダを渡すと、**その下にある連番グループを1回の操作ですべて読み込みます**。

```
A/00/*.npy   →  塊 "00/frame_###.npy"
A/01/*.npy   →  塊 "01/frame_###.npy"     ← A を1回開くだけで両方読める
A/02/*.npy   →  塊 "02/frame_###.npy"
```

- **読み込む塊を選べます**: 2つ以上見つかると選択ダイアログが開き、
  **フォルダ階層のツリー**で表示されます。フォルダ単位のチェックで一括切替、
  個別チェックで除外、`Select all` / `Select none`。選択中の塊数・ファイル数が下部に出ます
  (部分選択のフォルダには `~` を表示)。`--sequence always` 指定時はダイアログを省略して全読み込み
- サブフォルダは**深さ3まで**再帰。1フォルダ内に複数の命名パターンがあればそれぞれ別の塊
- 塊の名前は「ルートからの相対フォルダ + パターン」なので、どのフォルダ由来か一目で分かる
- **RAW の場合、フォーマット指定は最初の1回だけ**(ダイアログに「これらの設定は
  待機中の N 個の塊すべてに適用されます」と表示)。以降の塊は同じレシピで自動的に読み込む
- 塊は**順番に**バックグラウンド読み込み。左パネルに進捗と残り塊数、Stop で中断
- 上限: 塊は64個まで

### ナビゲーション(時間 = 水平、塊 = 垂直)

| 操作 | キー |
|---|---|
| 次 / 前のフレーム(時間方向) | `→` / `←`、`Ctrl+F` / `Ctrl+B` |
| 次 / 前の塊(シーケンス) | `↓` / `↑`、`Ctrl+N` / `Ctrl+P` |
| 先頭 / 末尾フレーム | `Home` / `End`、`Ctrl+A` / `Ctrl+E` |

左パネルの塊はスライダでも移動でき、塊を切り替えると**直前に見ていたフレームに戻ります**。
ステータスバーに `frame 7/24` を表示。

## 3. 表示操作(モードレス)

**ツールモードはありません。** 押した場所で動作が決まります:

| 左ドラッグの場所 | 動作 |
|---|---|
| 何もない所 | **新規 ROI** を作成(既定。View メニューでパンに変更可) |
| ROI の内側 | その ROI を移動 |
| ROI の角(ハンドル) | リサイズ |

- **ピン(POI)は `P` キー** — カーソルを合わせた画素にその場で打てます(クリック不要・修飾キー不要)
- **右クリックでコンテキストメニュー** — Add pin here / 全幅・全高バンド / この ROI でクロップ / 削除 / フィット
- クリック(ドラッグなし)で ROI 選択、何もない所をクリックで **All(全画面)** に戻る
- `Shift+ドラッグ` は既定の逆(既定が ROI 作成ならパン、パン設定ならROI作成)
- 微小ドラッグはクリック扱い(誤操作防止)。ただし**片方の辺が3px以上あれば作成**するので、4x1 のような細長い ROI も引けます

それ以外は常に共通:

| 常時共通 | 操作 |
|---|---|
| パン | **中ボタンドラッグ** / **Space+ドラッグ** / ホイール=縦 / Shift+ホイール=横 |
| ズーム | **Ctrl(⌘)+ホイール**(カーソル中心)/ `+` `-` / `1` 等倍 / `F` or ダブルクリック=フィット |
| 選択解除 / 削除 | `Esc` / `Del` |

補足: View メニュー「Wheel zooms without Ctrl」でホイール直接ズーム派に切替可。
`G` でピクセルグリッド(8倍以上)。表示レンジ(黒点/白点)、ガンマ(1.0/2.2)、
1ch 用カラーマップ(viridis 等、Display プラグインで追加可)は右パネル Image セクション。

## 3b. A/B 比較(ワイプ / 並べて / 差分)

`\` を押すたびに **オフ → ワイプ → 並べて → 差分 → オフ** と切り替わります
(View > Compare A/B からも同じ)。**A = いま選択中の画像**、**B = もう一枚**で、
B は View > Compare A/B > B image で選びます(未選択なら隣の画像が自動で B)。

| モード | 見え方 | 向いている用途 |
|---|---|---|
| **ワイプ** | 1枚のキャンバスに A を全面、B を仕切りの右側だけ重ねる。**仕切りは掴んでドラッグ** | 同一被写体の微差(ノイズ量、シャープネス、色被り)を**境界で**見る |
| **並べて** | 左右2ペイン。**同じズーム・同じ位置**の同じ領域を映す | 差が大きい場合、また ROI や解析結果を左右で見比べる |
| **差分 (A−B)** | 差そのものを画像化。**符号=色相**(A が明るい=暖色 / B が明るい=寒色)、**大きさ=明るさ** | 残差が**ランダムノイズなのか、列 FPN なのか、エッジのアーティファクトなのか**を空間分布で判断する |


- **ズーム・表示位置は A と B で常に共通**なので、同じ画素が必ず同じ場所に来ます
- **`Shift+\` で A と B を入れ替え**(どちらが上か迷ったら押す)
- **`B` を押しっぱなしで B を全面表示** — 仕切りを動かすより、パッパッと切り替える方が
  微差は見えます。離すと元のモードに戻ります
- **`Shift+B` で「いま見ているフレームを B に固定」**。そのまま `→` で次フレームへ行けば
  **同じ塊のフレーム 12 と 13 の比較**になります(A が B の位置に来たら自動で A/B 入替)
- `[` `]` で仕切りを 1% ずつ(`Shift` 併用で 10% ずつ)移動
- 仕切りは掴める範囲が線の左右 7px。カーソルが ⇔ に変われば掴めます。
  ROI の上では ROI 操作が優先されます
- `\` が効かない配列のキーボードのために **`C` でも同じ操作**ができます
- ROI / POI / ピクセルグリッドは**両側に同じものが描かれます**(座標は A 基準)
- Inspector の Pixel 表に **`A` / `B` / `A-B`** の列が増えます(整数型なら単位 `[DN]`)。
  ワイプでは読めない「その画素でいくつ違うのか」はここで読みます。
  差分は**両者のうち広い型**で表示します(u16 と f32 の比較で小数が消えないように)
- A と B でサイズ・dtype・**表示レンジ**が違う場合は Inspector に注意が出ます。
  **表示レンジ違いは要注意** — 画素が同一でも別物に見えるので、
  「match B to A」ボタンか View > Link range で揃えてから判断してください
- 並べて表示では**カーソルのあるペインが基準**です。ステータスバーの座標・画素値も
  `A (x, y) = ...` / `B (x, y) = ...` と、どちら側か明示されます
- 比較の状態(モード・仕切り位置・B の画像)は**セッションに保存**されます
- CLI: `viewer --compare wipe|split|diff a.npy b.npy`(先頭2枚が A と B)

**差分モード**(A と B が同サイズのときのみ):

- フルスケールは既定で**自動**(|A−B| の 99.9 パーセンタイルを 1/2/5 系のキリ番に丸め)。
  Inspector の「auto scale」を外せば手動で指定できます
- **フルスケールを超えた画素は黄色**にして「x.xx% off scale」と表示します。
  スケールが小さすぎるまま眺めて誤判断しないためです
- キャンバス左下に**カラーバーと数値**(整数型なら単位 DN)を常時表示
- 「magnitude only |A−B|」で符号なしのグレー表示に切替
- 再計算は A / B / スケール / モードが変わったときだけ
  (実測: 0.3 Mpx で 3 ms、12 Mpx で 107 ms。大きい画像でフレームを送ると各フレームで再計算)

## 4. アノテーション(ROI / POI)

- ROI(矩形)と POI(点)は**共通のアノテーションリスト**。8色パレット自動割当、
  キャンバス上の色と解析グリッド/カーブの色は一致
- 一覧(右パネル Annotations): クリックで選択、チェックで表示/非表示、`x` で削除、
  選択中は下の入力欄で**改名**(解析グリッドの列名になる)
- **`X` / `Y` = 行 / 列の選択**。選択しているものによって対象が決まります:

  | 選択中 | `X` の動作 |
  |---|---|
  | **POI(ピン)** | そのピンを通る**1ライン(高さ1px)の行 ROI**を作成(`Y` なら列)。もう一度 `X` でそのピクセル1点に戻る |
  | **なし(All)** | **カーソル位置**の行/列を1px で選択 |
  | **ROI** | 全幅(行バンド)/全高(列バンド)へトグル。もう一度押すと元の矩形に復元 |

  1px の行/列はドラッグでは作りづらいので、キーか右クリックメニュー
  (「Select this row (1 px)」)から作ります。細長いドラッグ(片方の辺が1px)も可。
  正確な値は ROI ウィンドウ下部の x/y/w/h 入力で直接指定できます(ピンは x/y)
- POI の値一覧: 表示中の全ピンの座標と **ch 毎の画素値**(CFA はチャンネル名 [Gr] 等付き)
- すべて**セッションに保存**される(§8)

## 5. 検査機能

### 5.1 ピクセル検査
ホバーで右パネル Pixel に座標・raw 値・正規化値(黒点/白点基準)。ステータスバーにも表示。
CFA 画像はそのピクセルの色チャンネル(R/Gr/Gb/B)を併記。ズーム2倍以上でホバー画素を枠表示。

### 5.2 統計(常時表示)
右パネル **Statistics** に ch 毎(CFA は R/Gr/Gb/B 別)の **mean / std / var** を常に表示。
ROI を選択している間はその ROI の値になります(未選択なら画像全体)。

### 5.2b 時間方向の解析(連番のみ、常時表示)
連番を開いていると **Temporal** セクションが出ます(対象は同じく選択 ROI / 全体):

| 指標 | 意味 |
|---|---|
| temporal noise (σ_t) | 画素ごとの時間方向 std の平均 = **時間ノイズ** |
| fixed pattern (σ_s) | 時間平均画像の空間 std = **固定パターン**(平坦部でない場合は絵柄成分を含む) |
| total (quadrature) | √(σ_t² + σ_s²) |

加えて **frame number(横軸)vs ROI mean value(縦軸)** のグラフを表示(現在フレームの位置に
マーカー)。フレーム間のドリフト・フリッカ確認に使えます。EMVA 1288 の温度/固定パターン分離と
同じ考え方ですが、単一シーケンスからの簡易版です。

### 5.3 ヒストグラム(内蔵)
- 黒点/白点レンジで正規化した 256bin。**選択中の ROI に自動追従**(未選択なら全体)
- **CFA 画像は R/Gr/Gb/B の4系列**に自動分離(チャンネルバランスが一目)
- log 切替、黒点未満/白点超過のクリップ率表示。約100万px サンプリング+キャッシュ

### 5.3 動的クロップ
- ROI を選択して **「Crop to selected ROI」** → メモリ上で即切り出し(ファイル再読込なし)。
  アノテーションは新しい座標系に追従シフト
- **「Restore full」** → RAW はレシピから、npy はパスから読み直して全体復帰
- CFA 画像の crop 原点はパターン周期(Bayer 2px / Quad 4px)に自動スナップ
- 読み込み時クロップは RAW ダイアログの **crop on load** か CLI `--raw-crop`

## 6. 測定(Analysis)

1. **Measure メニュー**(カテゴリ別、右側に前提条件ヒント)か、Analysis パネルの
   カテゴリ → 測定の2段セレクタで選び **Run**(`auto` で画像/ROI 変更時に自動再実行)
2. 対象: **表示中の ROI 全部**(それぞれが1列)。ROI がなければ画像全体
3. 結果:
   - 数値 → **ROI × 指標の比較グリッド**(ROI のラベルが列名)
   - 曲線(SFR 等)→ グリッド下の**折れ線プロット**(ROI 色で重畳)
   - `method` 行に手法と制約が必ず明記される

同梱の測定(詳細・出力キー・制約 → [analyzers.md](analyzers.md)):

| 測定 | 用途 | 前提 |
|---|---|---|
| stats/moments | 基本統計・分散・エントロピー | 任意 |
| noise/floor | ノイズフロア(タイル中央値)・SNR、CFA別 | 平坦め ROI |
| uniformity/prnu-fpn | PRNU%・行/列 FPN・シェーディング | 明るいフラット |
| sharpness/gradient | フォーカス相対比較 | 同一シーン |
| iso12233/e-sfr | SFR カーブ・MTF50/20 | 斜めエッジ ROI(5〜40°) |

## 7. Process(画像→新画像)

Process メニュー。結果は新しい画像としてリストに追加(元画像は不変)。
同梱: **demosaic (bilinear)** — Bayer → RGB f32(Quad Bayer は未対応と明示エラー)。

## 8. セッション

`Ctrl+S` / File > Save Session... で `.vsession`(テキスト)に保存:
開いている全画像の**再読込レシピ**(RAW は2軸+crop まで、.npz は配列名まで)、
黒点/白点(link 表示レンジ含む)、選択画像、ズーム・表示中心、ガンマ、グリッド、
**全アノテーション**(バンド化前の矩形と選択状態も)、**開いていたパネル構成**、
ヒストグラム/射影/解析の表示設定、**A/B 比較の状態**。
連番は塊ごとに**見ていたフレーム**まで復元されます。
復元は Open / ドラッグ&ドロップ / `--session`。旧版セッションも読める。
注意: Process で生成した画像(ファイル実体なし)は保存対象外。

## 9. コマンドライン

```
viewer [options] [files...]
  --session <f.vsession>     セッション復元
  --raw-dtype <t>            u8|u16|f32|f64
  --raw-interp <i>           gray|rgb|bgr|rgba|bgra|bayer|quad-bayer
  --raw-format <fmt>         旧式複合名 (gray16, bayer16, ...) も可
  --raw-size <WxH>           ダイアログなしで開くには dtype/interp と size が必要
  --raw-offset <bytes>  --big-endian  --bayer-pattern <RGGB|...>  --quad-bayer
  --raw-crop <x,y,WxH>       部分読み込み
  --zoom <z>  --center <x,y> 起動時の表示状態
  --compare <off|wipe|split> 先頭2枚を A/B 比較で開く
  --sequence <ask|always|never>  連番の裏読み込み
  --npy-axis <auto|frames>   (F,H,W) の解釈
```
例: `viewer --raw-dtype f32 --raw-interp bayer --bayer-pattern rggb --raw-size 4096x3072 dump.raw`

## 10. トラブルシューティング

| 症状 | 対処 |
|---|---|
| Linux でファイルダイアログが開かない | `zenity` か `kdialog` をインストール(D&D は常に可) |
| 日本語ファイル名が「?」になる | CJK フォント導入(Ubuntu: `fonts-noto-cjk`)。起動時トーストで警告 |
| Bayer の crop 位置が 1px ずれる | 仕様: CFA 周期(2/4px)へのスナップ。パターン破壊防止 |
| e-sfr が "no clear single edge" | ROI 内にエッジ1本だけ入れる。傾き 5〜40°、コントラスト確保 |
| 解析グリッドが出ない | ROI が16個以上 → 一部を非表示に(注記が出ます) |
| プラグインが読み込まれない | 起動時 stderr に理由(ABI 版数不一致 / CPU 実装なし / 重複名)。`plugins/` は exe と同階層 |

### ビルド環境まわり (Windows)

| 症状 | 原因と対処 |
|---|---|
| ターミナルで `cmake` が見つからない | インストール後に開いたままのターミナル/VSCode は**古い PATH を保持**している。VSCode を完全終了して再起動(タスクバー常駐も終了) |
| configure が `SSL peer certificate ... was not OK` (status_code 60) で失敗 | MinGW/WinLibs 同梱の CMake は CA ストアを持たず、FetchContent の GitHub ダウンロードが検証エラーになる。**CA バンドルを指定**する:<br>`cmake -S . -B build -DCMAKE_TLS_CAINFO="C:/Program Files/Git/mingw64/etc/ssl/certs/ca-bundle.crt"`<br>環境変数 `CMAKE_TLS_CAINFO` に同じ値を設定すれば以後不要(`CMAKE_TLS_VERIFY=0` での回避は非推奨) |
| MinGW でのビルド例 | `cmake -S . -B build-mingw -G Ninja -DCMAKE_BUILD_TYPE=Release` → `cmake --build build-mingw` → `.\build-mingw\viewer.exe`(MSVC は必須ではない) |
