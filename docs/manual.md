# viewer 操作マニュアル

対象バージョン: main ブランチ(プラグイン ABI v2)。
クイックスタートと機能一覧は [README](../README.md)、測定の中身は [analyzers.md](analyzers.md)。

---

## 1. 画面構成

```
┌────────────────────────────────────────────────────────┐
│ File  View  Measure  Process  Help          ← メニューバー │
├──────────┬──────────────────────────┬──────────────────┤
│ 画像リスト │  [Nav][ROI][Pin] ツール    │ Pixel   (ホバー値) │
│ Open     │   ┌─ルーラー(X座標)─────┐ │ Image   (情報/範囲)│
│ Close    │  ル│                    │ │ Histogram         │
│          │  ｜│   キャンバス         │ │ Annotations       │
│          │  Y│   (画像+ROI+ピン)   │ │ Analysis (グリッド │
│          │  座│                    │ │  +カーブプロット)   │
│          │  標└────────────────────┘ │                  │
├──────────┴──────────────────────────┴──────────────────┤
│ [ツール名] ファイル名 WxH ch dtype | zoom | (x,y)=値      │
└────────────────────────────────────────────────────────┘
```

- **左**: 開いている画像のリスト。クリックで切替、ツールチップにフルパス
- **中央**: キャンバス。上/左にルーラー(画像座標、ズームに応じ目盛り自動調整、ホバー位置マーカー)
- **右**: 検査・解析パネル(この文書の §4〜7)
- **下**: ステータスバー(現在ツール、画像情報、ズーム%、ホバー画素値)

## 2. ファイルを開く

方法は3つ: `Ctrl+O` / ウィンドウへ**ドラッグ&ドロップ** / **コマンドライン**(§9)。

### 2.1 .npy
そのまま開けます。対応: u8/i8/u16/i16/u32/i32/f32/f64/bool、形状 (H,W)・(H,W,C≤4)・
(C≤4,H,W)(自動で HWC 化)・4次元以上はバッチ先頭 [0]。ビッグエンディアン・Fortran order 対応。

### 2.2 ベタバイナリ (.bin / .raw / .yuv / .dat ...)
RAW ダイアログが開きます。指定は**直交する2軸**:

| 軸 | 選択肢 | 意味 |
|---|---|---|
| **pixel format** | u8 / u16 / f32 / f64(+エンディアン) | 1サンプルがファイル内でどう格納されているか |
| **interpretation** | Gray / RGB / BGR / RGBA / BGRA / **Bayer / Quad Bayer**(+RGGB/BGGR/GRBG/GBRG) | サンプル列を何チャンネルの何として読むか |

任意の組合せが有効(例: **RGGB × float32**)。補助機能:
- **サイズ候補**: ファイルサイズを割り切れる W×H を自動列挙
- **ファイル名ヒント**: `..._1920x1080_`、`rggb`、`bayer`、`quad`、`f32` などを自動認識
- **offset**: 先頭ヘッダのスキップ、**crop on load**: 巨大ダンプの部分読み(§5.3)

### 2.3 開いた後にフォーマットを変える
- **Interpret**(右パネル、1ch 画像): Gray ⇔ Bayer ⇔ Quad Bayer とパターンを**即時切替**。
  npy で受け取った CFA データにも使える(メタデータのみ、再読込なし)
- **Reinterpret raw...**: RAW 由来の画像を画素フォーマットから読み直し(ダイアログ再表示、
  ビュー位置・ズームは維持)

## 2.4 連番(シーケンス / 塊)

**1枚開くと、同じフォルダの連番を1つの「塊」として裏で読み込めます。** 塊は
**時間方向の解析ができる単位**で、フレームは同じデコードレシピ・同じ表示レンジを共有します。

- **検出**: ファイル名のうち **フォルダ内で実際に変化している数字フィールド**を番号と判定
  (`shot_0007_1920x1080.raw` は `0007` でグループ化され、解像度の数字では割れない)
- **読み込むかの選択**: 既定は毎回確認。`File > Sequence loading` で
  「毎回確認 / 常に読む / 読まない」を切替、モーダルの「remember my choice」でも設定される。
  CLI は `--sequence ask|always|never`
- **バックグラウンド**: 読み込み中も操作可能。左パネルに進捗と Stop ボタン。
  メモリ上限(約6GB)に達すると自動停止
- **メモリ**: GPU テクスチャは直近12フレームのみ常駐(古いものは自動的に解放・再生成)
- **セッション**: 表示中のフレーム1枚+「塊として再読込」フラグを保存(全フレームは書かない)

### ナビゲーション(時間 = 水平、塊 = 垂直)

| 操作 | キー |
|---|---|
| 次 / 前のフレーム(時間方向) | `→` / `←`、`Ctrl+F` / `Ctrl+B` |
| 次 / 前の塊(シーケンス) | `↓` / `↑`、`Ctrl+N` / `Ctrl+P` |
| 先頭 / 末尾フレーム | `Home` / `End`、`Ctrl+A` / `Ctrl+E` |

左パネルの塊はスライダでも移動でき、塊を切り替えると**直前に見ていたフレームに戻ります**。
ステータスバーに `frame 7/24` を表示。

## 3. 表示操作(ツールモデル)

左ドラッグの意味だけがツールで変わります。それ以外は常に共通:

| 常時共通 | 操作 |
|---|---|
| パン | **中ボタンドラッグ** / **Space+ドラッグ** / ホイール=縦 / Shift+ホイール=横 |
| ズーム | **Ctrl(⌘)+ホイール**(カーソル中心)/ `+` `-` / `1` 等倍 / `F` or ダブルクリック=フィット |
| 選択解除 / 削除 | `Esc` / `Del` |

| ツール | キー | 左ドラッグ / クリック |
|---|---|---|
| **Navigate** | `V` | ドラッグ=パン、クリック=アノテーション選択。Shift+ドラッグ=ROI、Ctrl+クリック=ピン(ショートカット) |
| **ROI** | `R` | 空白でドラッグ=新規 ROI、ROI 内ドラッグ=移動、**角ハンドル=リサイズ** |
| **Pin** | `P` | クリック=ピン追加 |

補足: View メニュー「Wheel zooms without Ctrl」でホイール直接ズーム派に切替可。
`G` でピクセルグリッド(8倍以上)。表示レンジ(黒点/白点)、ガンマ(1.0/2.2)、
1ch 用カラーマップ(viridis 等、Display プラグインで追加可)は右パネル Image セクション。

## 4. アノテーション(ROI / POI)

- ROI(矩形)と POI(点)は**共通のアノテーションリスト**。8色パレット自動割当、
  キャンバス上の色と解析グリッド/カーブの色は一致
- 一覧(右パネル Annotations): クリックで選択、チェックで表示/非表示、`x` で削除、
  選択中は下の入力欄で**改名**(解析グリッドの列名になる)
- **`X` / `Y`**: 選択 ROI を全幅(行バンド)/全高(列バンド)へトグル。もう一度押すと元の矩形に復元。
  ズームインしたまま行/列選択ができる
- POI の値一覧: 表示中の全ピンの座標と **ch 毎の画素値**(CFA はチャンネル名 [Gr] 等付き)
- すべて**セッションに保存**される(§8)

## 5. 検査機能

### 5.1 ピクセル検査
ホバーで右パネル Pixel に座標・raw 値・正規化値(黒点/白点基準)。ステータスバーにも表示。
CFA 画像はそのピクセルの色チャンネル(R/Gr/Gb/B)を併記。ズーム2倍以上でホバー画素を枠表示。

### 5.2 統計(常時表示)
右パネル **Statistics** に ch 毎(CFA は R/Gr/Gb/B 別)の **mean / std / var** を常に表示。
ROI を選択している間はその ROI の値になります(未選択なら画像全体)。

### 5.2b 時間方向の解析(連番のみ、常時表示)
連番を開いていると **Temporal** セクションが出ます(対象は同じく選択 ROI / 全体):

| 指標 | 意味 |
|---|---|
| temporal noise (σ_t) | 画素ごとの時間方向 std の平均 = **時間ノイズ** |
| fixed pattern (σ_s) | 時間平均画像の空間 std = **固定パターン**(平坦部でない場合は絵柄成分を含む) |
| total (quadrature) | √(σ_t² + σ_s²) |

加えて **frame number(横軸)vs ROI mean value(縦軸)** のグラフを表示(現在フレームの位置に
マーカー)。フレーム間のドリフト・フリッカ確認に使えます。EMVA 1288 の温度/固定パターン分離と
同じ考え方ですが、単一シーケンスからの簡易版です。

### 5.3 ヒストグラム(内蔵)
- 黒点/白点レンジで正規化した 256bin。**選択中の ROI に自動追従**(未選択なら全体)
- **CFA 画像は R/Gr/Gb/B の4系列**に自動分離(チャンネルバランスが一目)
- log 切替、黒点未満/白点超過のクリップ率表示。約100万px サンプリング+キャッシュ

### 5.3 動的クロップ
- ROI を選択して **「Crop to selected ROI」** → メモリ上で即切り出し(ファイル再読込なし)。
  アノテーションは新しい座標系に追従シフト
- **「Restore full」** → RAW はレシピから、npy はパスから読み直して全体復帰
- CFA 画像の crop 原点はパターン周期(Bayer 2px / Quad 4px)に自動スナップ
- 読み込み時クロップは RAW ダイアログの **crop on load** か CLI `--raw-crop`

## 6. 測定(Analysis)

1. **Measure メニュー**(カテゴリ別、右側に前提条件ヒント)か、Analysis パネルの
   カテゴリ → 測定の2段セレクタで選び **Run**(`auto` で画像/ROI 変更時に自動再実行)
2. 対象: **表示中の ROI 全部**(それぞれが1列)。ROI がなければ画像全体
3. 結果:
   - 数値 → **ROI × 指標の比較グリッド**(ROI のラベルが列名)
   - 曲線(SFR 等)→ グリッド下の**折れ線プロット**(ROI 色で重畳)
   - `method` 行に手法と制約が必ず明記される

同梱の測定(詳細・出力キー・制約 → [analyzers.md](analyzers.md)):

| 測定 | 用途 | 前提 |
|---|---|---|
| stats/moments | 基本統計・分散・エントロピー | 任意 |
| noise/floor | ノイズフロア(タイル中央値)・SNR、CFA別 | 平坦め ROI |
| uniformity/prnu-fpn | PRNU%・行/列 FPN・シェーディング | 明るいフラット |
| sharpness/gradient | フォーカス相対比較 | 同一シーン |
| iso12233/e-sfr | SFR カーブ・MTF50/20 | 斜めエッジ ROI(5〜40°) |

## 7. Process(画像→新画像)

Process メニュー。結果は新しい画像としてリストに追加(元画像は不変)。
同梱: **demosaic (bilinear)** — Bayer → RGB f32(Quad Bayer は未対応と明示エラー)。

## 8. セッション

`Ctrl+S` / File > Save Session... で `.vsession`(テキスト)に保存:
開いている全画像の**再読込レシピ**(RAW は2軸+crop まで)、黒点/白点、選択画像、
ズーム・表示中心、ガンマ、グリッド、**全アノテーション**。
復元は Open / ドラッグ&ドロップ / `--session`。旧版セッションも読める。
注意: Process で生成した画像(ファイル実体なし)は保存対象外。

## 9. コマンドライン

```
viewer [options] [files...]
  --session <f.vsession>     セッション復元
  --raw-dtype <t>            u8|u16|f32|f64
  --raw-interp <i>           gray|rgb|bgr|rgba|bgra|bayer|quad-bayer
  --raw-format <fmt>         旧式複合名 (gray16, bayer16, ...) も可
  --raw-size <WxH>           ダイアログなしで開くには dtype/interp と size が必要
  --raw-offset <bytes>  --big-endian  --bayer-pattern <RGGB|...>  --quad-bayer
  --raw-crop <x,y,WxH>       部分読み込み
  --zoom <z>  --center <x,y> 起動時の表示状態
```
例: `viewer --raw-dtype f32 --raw-interp bayer --bayer-pattern rggb --raw-size 4096x3072 dump.raw`

## 10. トラブルシューティング

| 症状 | 対処 |
|---|---|
| Linux でファイルダイアログが開かない | `zenity` か `kdialog` をインストール(D&D は常に可) |
| 日本語ファイル名が「?」になる | CJK フォント導入(Ubuntu: `fonts-noto-cjk`)。起動時トーストで警告 |
| Bayer の crop 位置が 1px ずれる | 仕様: CFA 周期(2/4px)へのスナップ。パターン破壊防止 |
| e-sfr が "no clear single edge" | ROI 内にエッジ1本だけ入れる。傾き 5〜40°、コントラスト確保 |
| 解析グリッドが出ない | ROI が16個以上 → 一部を非表示に(注記が出ます) |
| プラグインが読み込まれない | 起動時 stderr に理由(ABI 版数不一致 / CPU 実装なし / 重複名)。`plugins/` は exe と同階層 |

### ビルド環境まわり (Windows)

| 症状 | 原因と対処 |
|---|---|
| ターミナルで `cmake` が見つからない | インストール後に開いたままのターミナル/VSCode は**古い PATH を保持**している。VSCode を完全終了して再起動(タスクバー常駐も終了) |
| configure が `SSL peer certificate ... was not OK` (status_code 60) で失敗 | MinGW/WinLibs 同梱の CMake は CA ストアを持たず、FetchContent の GitHub ダウンロードが検証エラーになる。**CA バンドルを指定**する:<br>`cmake -S . -B build -DCMAKE_TLS_CAINFO="C:/Program Files/Git/mingw64/etc/ssl/certs/ca-bundle.crt"`<br>環境変数 `CMAKE_TLS_CAINFO` に同じ値を設定すれば以後不要(`CMAKE_TLS_VERIFY=0` での回避は非推奨) |
| MinGW でのビルド例 | `cmake -S . -B build-mingw -G Ninja -DCMAKE_BUILD_TYPE=Release` → `cmake --build build-mingw` → `.\build-mingw\viewer.exe`(MSVC は必須ではない) |
