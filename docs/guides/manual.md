対象バージョン: main ブランチ(プラグイン ABI v3)。
クイックスタートと機能一覧は [README](../../README.md)、測定の中身は [analyzers.md](../reference/analyzers.md)。

## 1. 画面構成(ドッキング式パネル)

パネルは**自由に配置できます**(タイトルをドラッグしてドッキング/タブ化/フロート化)。
配置は自動保存され(`%APPDATA%/viewer/layout.ini`、Linux/macOS は `~/.config/viewer/`)、
`View > Panels` で表示切替、`View > Panels > Reset layout` で既定配置に戻せます。

**ウィンドウ自体の見分け**: タイトルは `画像名 - viewer`、リモートを見ているときは
`画像名 - viewer [user@server]`。タスクバー/ウィンドウのアイコンも**枠の色が青=ローカル /
緑=リモート接続中**に変わります(ステータスバー左端のリンク表示と同じ色)。

### タイトルバー(統合フレーム)

既定では**OS のタイトルバーを出さず、メニューバーにタイトルと最小化/最大化/閉じるを
統合**します(VSCode などと同じ方式)。縦 1 段ぶん画面が広くなり、ウィンドウが
「他人の枠に入ったアプリ」ではなく1枚の面になります。

| 操作 | 場所 |
|---|---|
| 移動 | メニューバーの**空いている所をドラッグ**(メニューとボタンの間) |
| 最大化 / 復元 | 同じ場所を**ダブルクリック**、または □ ボタン |
| リサイズ | ウィンドウの**四辺・四隅**(カーソルが変わります) |
| 最小化 / 閉じる | 右端の ─ / ✕ |

**OS の作法はそのまま使えます** —— Windows は Aero Snap(画面端ドラッグ)、`Win+←→`、
Win11 の**スナップレイアウト**(□ ボタンにホバー)、`Alt+Space` のシステムメニュー、
影と角丸まで OS が担当します(自前実装ではなく `WM_NCHITTEST` で「ここはタイトルバー」と
答えているだけなので)。Linux(X11)は `_NET_WM_MOVERESIZE` でウィンドウマネージャに
移動/リサイズを渡すため、WM 側のタイル配置・スナップがそのまま効きます。

**元に戻すには** `View > Integrated title bar` のチェックを外します(次回以降も保持)。
ウィンドウマネージャとの相性で操作不能になった場合の逃げ道として、
起動時に **`viewer --frame system`**(この起動だけ OS のタイトルバー)も使えます。

対応状況: Windows / Linux(X11)。**Wayland と macOS では自動的に OS のタイトルバー**に
なります(Wayland はクライアントが自分の位置を動かせない、macOS は信号機ボタンが
OS のもの、という理由。メニュー項目に理由が出ます)。
デスクトップからの起動については [startup.md](startup.md#0-2-デスクトップ--スタートメニューから起動する)。

| パネル | 役割 | 既定位置 |
|---|---|---|
| **Files** | batch 管理下の frame / stack / series と、それらを役割参照する AnalysisSet の一覧 | 左 |
| **Browse** | ローカル・サーバのフォルダを**開かずに**見る([startup.md](startup.md#2-2-接続してから選ぶ)) | 左(Files とタブで重なる)、既定は非表示 |
| **Image View** | キャンバス(ルーラー、下端にフレームのスクラブバー) | 中央 |
| **Inspector** | ホバー画素値、画像情報、レンジ/解釈/カラーマップ/crop、A/B の設定 | 右 |
| **Histogram** | ch 毎の mean/std/var + ヒストグラム(選択 ROI 追従) | 下部タブ |
| **Temporal** | 時間ノイズ/固定パターン、frame mean グラフ | 下部タブ |
| **Projection** | 水平/垂直射影とその統計 | 下部タブ(既定は非表示) |
| **ROIs** | **ROI/POI 一覧 + 基本統計**(mean/std/`std / mean [%]`/min/max)。比較中は**スロットごとの数値**(§6.1) | **フローティング** |
| **Analysis** | **詳細解析**(解析プラグイン、ROI×指標グリッド、カーブ) | **フローティング** |
| **Series Analysis** | series(系列)層の解析(旧 Linearity): linearity / PTC フィット、read noise、SNR カーブ([startup.md](startup.md#series-系列--掃引を-1-本の測定として扱う))。メンバは stack と frame の混在可で、stack メンバは宣言した畳み方(mean / sum)で 1 点に立つ — フィットに入るのは mean 統計だけで、sum 立ちのメンバがあるとフィットは理由を言って拒否します。フィット窓(なし / 自動 5..95% / 手動)と方式(OLS / rev4-style)もこのパネルの持ち物 | **フローティング**、既定は非表示 |
| **Messages** | toast の履歴(`[error]` 印つき、コピー可) | **フローティング**、既定は非表示 |

**フレームスライダは Files ではなく Image View の下端**にあります(名前・スクラブバー・
`現在/総数`)。選択した行の下に現れる作りだったころは、行が伸びて一覧全体が跳ねていました。

**基本 / 詳細の切り分け**: ROI を置いた瞬間に見たい値(平均・標準偏差・`std / mean [%]`・
最小最大)は ROIs ウィンドウの表に常時出ます。プラグインによる重い測定(ノイズフロア、
`uniformity/prnu-fpn`、SFR…)は Analysis ウィンドウで実行し、結果は ROI ごとの列に
並びます。どちらも同じ ROI に紐づきます。

**「PRNU」は2か所にあり、同じ数ではありません。** ROIs の表の `std / mean [%]` は
その ROI の **σ/mean をそのまま**(ローパス除去なし)、プラグインの `X.prnu_pct` は
**9×9 ボックスのローパスを引いた残差**の σ/mean です(§5.2 と
[analyzers.md](../reference/analyzers.md#uniformityprnu-fpn))。シェーディングや絵柄を含むか
含まないかが違うので、同じ画像・同じ ROI でも一致しません。

| 方法 | どこ |
|---|---|
| ファイル / フォルダを選ぶ | `Ctrl+O` = **File > Open...**、`Ctrl+Shift+O` = **File > Open Folder...** |
| ドラッグ&ドロップ | ウィンドウへ。フォルダを落とせばその下の連番を全部拾います |
| コマンドライン | §9 |
| **見てから選ぶ** | **Browse** パネル —— **File > Browse Folder (Local)...**(このマシン)か **File > Start Remote (ssh)...**(サーバ)。開かずにプレビューでき、サーバ側の時間統計もそこから撃てます([startup.md](startup.md#2-2-接続してから選ぶ)) |

### 2.1 .npy
そのまま開けます。対応 dtype: u8/i8/u16/i16/u32/i32/f32/f64/bool。
ビッグエンディアン・Fortran order 対応。

**形状の解釈**(**次元数と、最後の軸だけ**を見ます。**先頭の軸の大きさは見ません**):

| 形状 | 解釈 |
|---|---|
| `(H,W)` | **1枚**・1ch |
| `(H,W,C)` C≤4 | **1枚**・Cch(`(H,W,1)` はモノクロ1枚、`(H,W,3)` はカラー) |
| `(F,H,W)` | **F 枚の stack**・各1ch(`(3,H,W)` も **3枚**。3ch 画像ではありません) |
| `(F,H,W,C)` C≤4 | **F 枚の stack**・各 Cch(`(F,H,W,1)` は 1ch の F 枚) |
| 上記以外 | **開きません。**形を名指しして断り、adapter を促します |

「上記以外」に落ちるもの: 1次元・スカラー・5次元以上、および最後の軸が 5 以上の
4次元(`C > 4` として断ります)。

- **`(C,H,W)` は native では C 枚の stack です。** 暗黙の CHW→HWC 変換は廃止しました
  —— 先頭の軸を見て推測すると、3枚の stack と 3ch のカラー画像を取り違えるためです。
  1枚の Cch 画像として読みたい場合は、開いてから Inspector の
  **「re-read as...」**で `(C,H,W)` を選びます(ファイルごと・セッションに残ります)。
- **`(F,C,H,W)`**(torch の NCHW をそのまま保存したもの)は最後の軸がチャンネル
  ではないので `C > 4` として断られます。逃げ道は adapter —— 軸の順序を知って
  いるのは書いた人なので、そこで `permute` して返します。
- **5次元以上は先頭軸を落としたりしません。** 形を名指しして断ります。

### 2.1b .npz(非圧縮 / 圧縮)

`np.savez`(非圧縮=stored)と `np.savez_compressed`(deflate)の**両方**に対応。
最初に member 名・shape・dtype を走査して、**画像 / 軸候補 / metadata / 曖昧 / 読めない**
に分類します。画像を全部いきなり展開することはありません。

- 画像 member が1つで軸候補が無ければ、その1つを直接開きます
- 画像が複数、または frame 数と同じ長さの1次元配列があれば picker で選びます。
  選んだ画像だけが `ファイル名:member名` として開き、`(F,H,W)` 等は stack になります
- 1次元配列は絵にせず x 軸候補、scalar / string は Inspector の metadata に出します
- zip64 に対応し、読めない member があっても他の member の選択は続けられます
- ssh 先でも protocol 13 以降の `MSG_NPZ_SCAN` で同じ分類と picker を使います。
  `.npz` 自体には単一 geometry がないため、1クリック preview はしません

### 形状の曖昧さ

**先頭の軸は見ません。** 次元数と最後の軸だけで決まり、`(H,W)` / `(H,W,C≤4)` /
`(F,H,W)` / `(F,H,W,C≤4)` が native、それ以外の形は理由を名指しして開きません。
なので `(3,H,W)` は **3 フレーム**です(3 チャンネル画像ではありません)。

**最後の軸が 4 以下なら channel** です。つまり `(H,W,1)` は**モノクロ1枚**、
`(H,W,2)` は**2ch の1枚**で、どちらも stack にはなりません
(`img[:, :, None]` や `np.expand_dims(a, -1)` が作る形はこれです)。
1枚に時間軸は無いので Temporal は出ません —— ここを stack として読むと
存在しない σ_t を報告してしまうため、そうしません。
そう読みたくないファイルは、開いてから Inspector の **「re-read as...」**で言い直します
—— ファイルごと・画面に見える形で・セッションに残ります(旧 `--npy-axis` の後継)。
stack として読まれた場合は Files パネルに `12f` のようにフレーム数が出て、
時間方向解析(Temporal)と `←`/`→` のフレーム送りがそのまま使えます。

### 2.2 ベタバイナリ (.bin / .raw / .yuv / .dat ...)
RAW ダイアログが開きます。指定は**直交する2軸**:

| 軸 | 選択肢 | 意味 |
|---|---|---|
| **pixel format** | u8 / u16 / f32 / f64(+エンディアン) | 1サンプルがファイル内でどう格納されているか |
| **interpretation** | Gray / RGB / BGR / RGBA / BGRA / **Bayer / Quad Bayer**(+RGGB/BGGR/GRBG/GBRG) | サンプル列を何チャンネルの何として読むか |

任意の組合せが有効(例: **RGGB × float32**)。補助機能:
- **サイズ候補**: ファイルサイズを割り切れる W×H を自動列挙
- **ファイル名ヒント**: `..._1920x1080_`、`rggb`、`bayer`、`quad`、`f32` などを自動認識
- **offset**: 先頭ヘッダのスキップ、**crop on load**: 巨大ダンプの部分読み(§5.4)

### 2.2b 名前付きレシピ (RAW recipes パネル)
毎回ダイアログを組み直さなくて済むように、**View > RAW recipes** に一覧があります。
中身は**寿命の違う2つ**で、パネルでも別々に出ます。

| | どこ | 寿命 | 勝手に当たるか |
|---|---|---|---|
| **レシピ庫** | `settings.jsonc` の `loading.rawRecipes`(手で書く) | 永続 | **当たりません**。選んで初めて効きます |
| **サイズ→レシピ** | プロセス内だけ | **終了で消えます** | 当たります。ただし**このセッションであなたが選んだもの**だけ |

つまり —— **セッション最初の1枚は必ずダイアログ**です。そこで選んだ設定は
**ファイルサイズで**覚えられ、次に同じバイト数のファイルを開くとそれが当たり、
**どのレシピで開いたかを1行出します**:

```
beta_48x16.bin: opened with "MyCam 32x24" (32x24 u16 gray) - this session's recipe for 1536-byte files
```

読み方を変えたいときは**レシピを当て直します**(パネルの Apply、または RAW
ダイアログでの選び直し)。そのサイズの対応は**最後に選んだもの**に更新されます。

対応表を**どこにも保存しない**のは意図です。ヘッダレスは「読めた/読めない」で
守ってくれない唯一の形式で、4096×3000 と 3000×4096 は**同じバイト数**、転置した絵は
**普通に出ます**。だから勝手に当たってよいのは「**あなたが数分前に選んで、まだ
覚えているもの**」だけ、という線を引いています。先週のレシピが後日ひとりでに
当たることはありません。

**レシピの書き方。** アプリは `settings.jsonc` を**書きません**(§8)。RAW ダイアログの
**Copy as JSONC**(またはパネルの Copy)が貼り付ける1行をクリップボードに入れ、
貼り先のパスを Messages に出します:

```jsonc
"loading": {
  "rawRecipes": [
    { "name": "うちの 4096x3000 u16 RGGB", "size": [4096, 3000], "dtype": "u16",
      "interpretation": "bayer", "bayerPattern": "RGGB" },
    // headerBytes / byteOrder ("little" | "big") / crop [x,y,w,h] は省略可
  ],
}
```

語彙は CLI と同じです(`--raw-dtype` / `--raw-interp` / `--bayer-pattern`)。
`name` と `size` は必須で、無ければ**そのレシピだけ**名指しで断り、残りは活きます。
`viewer --settings-template` はいま読み込んでいるレシピ庫もそのまま書き出すので、
テンプレートに移行してもレシピを失いません。

### 2.3 開いた後にフォーマットを変える
- **Interpret**(Inspector、1ch 画像): Gray ⇔ Bayer ⇔ Quad Bayer とパターンを**即時切替**。
  npy で受け取った CFA データにも使える(メタデータのみ、再読込なし)
- **Reinterpret raw...**: RAW 由来の画像を画素フォーマットから読み直し(ダイアログ再表示、
  ビュー位置・ズームは維持)

### 2.3b PNG / JPEG / ベンダ RAW / TIFF / OpenEXR

そのまま開けます。**値は保存されたまま** —— 8bit は 0..255、16bit は 0..65535 [DN] で、
**0..1 に正規化しません**。表示レンジの初期値だけがビット深度から決まります。

| | 読めるもの | 備考 |
|---|---|---|
| **PNG** | 1/2/4/8/16 bit、grey / grey+alpha / RGB / RGBA / palette / interlace | **16bit がそのまま 16bit で入ります** |
| **JPEG** | baseline / progressive、8bit | codec の YCbCr→RGB を通った値である旨が note に出ます |
| **ベンダ RAW** | `.dng .cr2 .cr3 .nef .arw .orf .rw2 .raf .pef .srw` ほか(Canon / Nikon / Sony / Olympus / Panasonic / Fujifilm / Apple ProRAW …) | **センサが数えた CFA モザイクそのもの**が 1ch で入ります。デモザイクも WB もガンマも**しません**(下記) |
| **TIFF** | 8/16bit 整数と **32bit float**、grey / grey+alpha / RGB / RGBA、II・MM 両方、strip、無圧縮 / PackBits / LZW / Deflate(predictor 付きも) | **複数ページは stack になります**(下記)。読めないものは**名指しで断ります** |
| **OpenEXR** | half / float、scanline と 1レベル tiled、圧縮は全種(ZIP・PIZ・DWA など) | **シーンリニアの値をそのまま**入れます —— トーンマップも clamp もしません。**レイヤは1枚ずつ別の画像**になります(下記) |
| **y4m** | progressive、8〜16bit の**輝度のみ**、Cmono / C420 / C422 / C444 など | **1ファイル = 1つの stack。** 非圧縮なので値は DN。他の動画形式は名指しで断ります(§2.3c) |

- チャンネル数は npy と同じ規則: **grey は 1ch、RGBA は 4ch**(モノクロが 4ch に
  水増しされることはありません)
- **何をして、何をしなかったかは Inspector の note に出ます** ——
  `PNG greyscale, 16-bit; values as stored, no scaling or transfer curve applied` や
  `TIFF page 2 of 3, 16-bit greyscale, LZW, Predictor 2 (horizontal differencing) undone,
  7 strips; values as stored, ...` のように。
  4bit 以下の PNG だけはデコーダが 0..255 へ展開する(×17 等)ので、**その倍率も note に出ます**
- **PNG / JPEG / TIFF / OpenEXR は CFA を運ばない**(TIFF の CFA ページは
  **断ります**)ので **Bayer とは名乗りません**。モザイクとして扱いたい場合は
  Inspector の **Interpret** か `--cfa`(=ユーザーの宣言)を使います。
  **ベンダ RAW だけは別**です —— ファイルがパターンを名乗るので、
  開いた時点で **Bayer として、正しい並びで**入ります(下記)
- **Browse パネルでは、PNG / JPEG / TIFF / 単一 document の OpenEXR / y4m を
  `local://` と `ssh://` のどちらでも同じように扱います。** 1クリック／矢印移動は
  使い捨て preview、ダブルクリック／Enter は Files に登録する正式 open です。
  protocol 14 の `viewer-serve` が同じ形式表と decoder を使います。
- **複数 named layer を持つ OpenEXR はローカルでだけ開けます。** 現行 remote wire は
  ファイル内の layer を指せないため、peer は先頭 layer を黙って返さず、理由と
  代替手順として「そのマシンで開く／手元へコピーする」と表示します。
- **ベンダ RAW はローカル専用**です。peer のビルドは LibRaw を含まないため ssh 先では
  淡色になり、理由と代替手順として「Reader を選ぶ／ローカルで開く／コピーする」と表示します。
  ヘッダ無し RAW と `.npz` は開く前にレシピ／member 選択が要るため、1クリックは
  preview せず選択だけです。

**ベンダ RAW は「モザイクをそのまま」開きます。** カメラの `.NEF` や `.CR3` を
開くと、**現像された写真ではなく、センサが数えた CFA モザイク**が 1ch の画像として
入ります。デモザイク・ホワイトバランス・カラーマトリクス・トーンカーブは
**1つもかかりません**(かける関数はこのビルドに**リンクすらされていません**)。

ファイルが宣言している数は、**note に出るだけで、画素には適用しません**:

```
LibRaw 0.22.2 (nikon_load_raw()), Nikon 1 AW1; the CFA mosaic, one plane;
CFA RGGB, read from the file; 12-bit samples as the file declares them;
black level 0, SHOWN and not subtracted; white level 4095;
4620x3082 read out of a 4620x3084 raw frame at (0,0) - the masked border the
file excludes is not read; no demosaic, no white balance, no colour matrix,
no tone curve; values as stored, no scaling or transfer curve applied
```

- **CFA パターンはファイルから読んだもの**です。RGGB を仮定しません。
  なので per-plane の統計(4面を混ぜない、という規則)が最初から正しく効きます
- **ブラックレベルは表示するだけで、引きません。** 上の実例のように
  **「black level 0」と宣言しながら画素が 80 から始まる**機種が実在します。
  引く実装はそこで間違い、他の全部で無言になります。引き算をしたければ、
  それは**あなたが見て決めること**です
- **可視領域だけ**を渡します。マスク境界(光学黒)は読みませんが、
  **あることは note が言います**
- 表示レンジの初期値は 16bit の既定(0..65535)なので、**12/14bit の RAW は
  暗く見えます**。note のホワイトレベル(上の例なら 4095)を Display の白に
  入れてください。中身に合わせるだけなら Inspector の **Auto**(実測 min–max)
  か **Auto %**(0.1–99.9%、ホットピクセルに引っ張られない)でも構いません(§3a)

**ベンダ RAW が断るもの**(いずれも名指しで、`Open With a Reader...` へ誘導します):
Nikon HE / HE\*(このビルドの LibRaw が復号しません)/ JPEG-XL の DNG
(Adobe DNG SDK が要ります)/ GoPro VC-5(GPR SDK)/ X-Trans などの
**非 Bayer モザイク** / Foveon X3 / すでに 3面・4面になっている RAW /
float の DNG。

```
Nikon_Z8_HE.NEF: vendor RAW: Nikon High Efficiency (HE, NEFCompression 13):
  LibRaw 0.22.2 does not decode it - upstream's own camera list says
  "not supported yet" (LibRaw 0.22.2)
  choose a reader to read it another way
```

**`.raw` はこれとは別**です。あれは**ヘッダの無い生バイト列**で、
形と深度をあなたが宣言するダイアログのままです(§2.3 の raw ダイアログ)。
カメラの RAW とは別の物なので、拡張子も取り違えません。

**複数ページの TIFF は stack です。** 1ページ = 1フレームで、連番フォルダから
できる stack とまったく同じもの(§2.4)—— 時間方向の解析も montage も効きます。
ただし **`NewSubfileType` が「縮小版」と名乗るページ(サムネイル)はフレームに
数えません**。落としたことは note に出ます。ページごとに大きさや深さが違う
ファイルは stack ではないので、**一部だけ開かずに断ります**。

**TIFF が断るもの**(いずれもタグと値を名指しし、`Open With a Reader...` へ誘導します):
BigTIFF / tiled / `PlanarConfiguration 2` / CCITT・JPEG・JPEG2000・LZMA・Zstd・WebP 圧縮 /
palette・CMYK・YCbCr など / **CFA (photometric 32803)** / 1・4・12bit や符号付き整数や
half / `Predictor 3`。とくに **CFA は「当てて開く」より断るほうを選んでいます** ——
パターンを取り違えると色も面別統計も静かに間違うためです。

```
scan_tiled.tif: TIFF: tiled layout (TileWidth 256, TileLength 256): this build
  reads strip layouts (tiffread 1, core/tiffread.cpp)
  choose a reader to read it another way
```

**OpenEXR は「レイヤ = 別の画像」です。** `.exr` が `diffuse` と `specular` の
2レイヤを持つなら、開くと **2枚の画像**(`beauty.exr:diffuse` と
`beauty.exr:specular`)になります —— 複数ページ TIFF のような1つの stack では
ありません。レイヤは順番でも同じ形でもなく(`diffuse` は 3ch、`Z` は 1ch)、
`.npz` のメンバと同じものだからです。**セッションは開いていたレイヤだけを
開き直します**。同じ layer 名に `R`,`G`,`B`(あれば `A`)が揃っていればまとめて
1枚のカラー画像になり、それ以外のチャンネルは **1本ずつ 1ch の画像**になります。

**値には何もしません。** シーンリニアの EXR は 1 を超える値も負の値も普通に
持ちます。`12.5` は `12.5` のまま入り、half は float に**無損失で**広がります。
**トーンマップ・ガンマ・0..1 への clamp はいずれも行いません** —— 見た目を
整えるのは表示レンジ(§3)の仕事で、測定値の側には触りません。

**OpenEXR が断るもの**: multi-part / deep / **mipmap・ripmap(複数解像度)** /
chroma subsample されたチャンネル・`Y`/`RY`/`BY` / **UINT チャンネル**。
**tiled(1レベル)は読めます** —— タイルは格納形式にすぎず可逆に解けるためです。
mipmap を断るのは「どの解像度がその絵か」を勝手に選ばないためです。

```
beauty.exr: OpenEXR: multi-part EXR (2 parts): each part is a separate image
  with its own header, and which one was meant is not something a loader may
  decide (OpenEXR 3.4.13)
  choose a reader to read it another way
```

`.exr` はどのビルドでも読めます。かつては `-DVIEWER_WITH_EXR=OFF` で外せまし
たが、その切り替えは廃止しました(2026-08-09)——「この viewer は `.exr` を
読む」を、配布物ごとに違う話にしないためです。ビルドする側の代償は
付録の「ビルドとネットワーク」を見てください。

### 2.3c 動画 — y4m だけ開きます(理由があります)

**`.y4m` は開きます。1ファイルが1つの stack** になり、フレームは提示順、値は
**ビット完全な DN** です(輝度プレーンのみ)。時間方向の解析もフレーム送りも
連番フォルダの stack とまったく同じに使えます。

**`.mp4` / `.mov` / `.mkv` / `.avi` / `.webm` などは開きません。** 「未対応」では
なく**測ってから決めた**結果です: 8bit の lossy 往復に通すと、既知の
σ_t = 40 DN16 が **0.00 になります**(劣化ではなく消滅)。8bit で表現できる
ノイズも 11% 減衰し、GOP 周期のバイアスが乗ります。**その stack でノイズを
測ると、測っているのはエンコーダです。**

なので落としても黙って失敗しません。**形式名・理由・変換コマンド**が出ます:

```
capture.mp4: MP4 (H.264/HEVC) needs a video codec this build does not link.
  Decoded 8-bit video is display-referred, not DN - a known sigma_t of 40 DN16
  comes back as 0.00 ...
  Convert the frames you want to measure and open the .y4m:
      ffmpeg -i "capture.mp4" -pix_fmt gray16le -strict -1 out.y4m
```

そのまま貼れば `.y4m` になり、それは開きます。`.mov` / `.mkv` / `.avi` は
可逆 codec (FFV1 など) を入れられるコンテナなので、その場合の話も文面に出ます。

**y4m のうち断るもの**: インターレース(1フレームが2フィールド = **2つの瞬間**
なので、その σ_t は時間ノイズではありません)、知らない colour space。
**クロマは読みません** —— 2x2 に1サンプルから色を作るのは補間で、補間値は
測定値ではないからです(あったことは note に出ます)。

**途中で切れたファイルは「n of N」を言います。** y4m はフレーム数をどこにも
書かないので、N は**残ったバイトから割り算で出した数**です。

測定と判断の全文: [video-support.md](../features/media/video-support.md)

設計と、ライブラリの差し替え方: [input-adapters.md §3.6](../features/adapters/input-adapters.md)

## 2.4 連番(stack)

**1枚開くと、同じフォルダの連番を1つの stack として裏で読み込めます。** stack は
**時間方向の解析ができる単位**で、フレームは同じデコードレシピ・同じ表示レンジを共有します。

- **検出**: ファイル名のうち **フォルダ内で実際に変化している数字フィールド**を番号と判定
  (`shot_0007_1920x1080.raw` は `0007` でグループ化され、解像度の数字では割れない)
- **形の違う兄弟は積みません**。検出は**名前**しか見ない(`.raw` / `.bin` は形を名乗らず、
  300枚のヘッダを覗けばフォルダを2度読むことになる)ので、形が分かるのは**読んだ後**です。
  先頭フレームと違う形のファイルはそこで**名指しで断ります** ——
  `shape_2.npy: 8x8 3ch and shape_1.npy is 8x8 1ch: a run of numbered files is a stack,
  and a stack's frames are one shape - open it on its own`。
  stack は**時間軸**を持つ層なので(`terminology.md`)、形が揃っていなければ σ_t も
  FPN 分離も per-frame 表も意味を失います。**断られたファイルは単独で開けば普通に開き**、
  そのときはそれが先頭フレームになります。何枚中何枚読めたかは Files パネルに残ります
  (複数ページ TIFF が形の違うページを断るのと同じ規則です → §2.3b)。
  **Browse から開いたリモートのフォルダも同じで、断り文も同じです** —— 同じフォルダが
  ローカルとリモートで違う積まれ方をするのは、この道具では欠陥として扱います
- **読み込むかの選択**: 既定は毎回確認。`File > Stack loading` で
  「毎回確認 / 常に読む / 読まない」を切替、モーダルの「remember my choice」でも設定される。
  CLI は `--stack ask|always|never`
- **バックグラウンド**: 読み込み中も操作可能。Files パネルに進捗と Stop ボタン。
  **メモリ予算**に達すると自動停止します
- **メモリ予算**: 既定は**物理メモリの 60%**(最低 2 GB)。`File > Stack loading > Memory budget`
  で GB 単位に固定でき、いま何 GB 使っているかも同じ所に出ます
- **GPU テクスチャ**: 直近12フレームのみ常駐(古いものは自動的に解放・再生成)
- **セッション**: stack ごとに1行(**見ていたフレーム番号**+再読込レシピ)を保存。全フレームは書きません

### フォルダを開く(複数の stack を一括)

`File > Open Folder...`(`Ctrl/Cmd+Shift+O`)、フォルダのドラッグ&ドロップ、
または CLI 引数にフォルダを渡すと、**その下にある連番グループを1回の操作ですべて読み込みます**。

```
A/00/*.npy   →  stack "00/frame_000‥023.npy"
A/01/*.npy   →  stack "01/frame_000‥023.npy"   ← A を1回開くだけで全部読める
A/02/*.npy   →  stack "02/frame_000‥023.npy"
```

- **読み込む stack を選べます**: **Select stacks** ダイアログが**必ず**開きます —— 見つかった stack が
  1つでも、`--stack always` でも省略されません(絞り込みがここにしか無いため)。
  `--stack` の3値は「**1枚のファイルを開いたとき、その連番兄弟をどうするか**」の設定で、
  フォルダ Open には効きません
- ダイアログは**フォルダ階層のツリー**。フォルダ単位のチェックで一括切替、個別チェックで除外、
  `All` / `None` / `Invert`。選択中の stack 数・ファイル数が下部に出ます
  (部分選択のフォルダには `~` を表示)。連番行を開くと実際に読まれるファイルが並びます
- **絞り込みは1本の入力欄**、打鍵ごとに反映。`dark` = `フォルダ/ファイル名` のどこかに含む、
  `!ng` = 除外、`*_A.npy` = ワイルドカード。**全語 AND**
- **stack のまとめ方**も同じダイアログで決めます: 「**N 個の別スタック**」か「**まとめて 1 スタック**」、
  「**1 batch**」か「**トップフォルダ毎に batch**」、そして
  「**open as a sweep (creates a series)**」([startup.md の series 節](startup.md#series-系列--掃引を-1-本の測定として扱う))
- サブフォルダは `loading.folderScanDepth` で指定した深さまで再帰（既定 **6**、
  Preferences の loading 節で変更可）。1フォルダ内に複数の命名パターンがあればそれぞれ別の stack
- stack の名前は「ルートからの相対フォルダ + パターン」なので、どのフォルダ由来か一目で分かる。
  変化する桁は `?` ではなく**実際の範囲**で出ます(`frame_000‥023.npy`)
- **RAW の場合、フォーマット指定は最初の1回だけ**(ダイアログに「これらの設定は
  待機中の N 個の stack すべてに適用されます」と表示)。以降の stack は同じレシピで自動的に読み込む
- stack は**順番に**バックグラウンド読み込み。Files パネルに進捗と残り stack 数、Stop で中断
- 上限: 1回の走査で拾う stack は256個まで(打ち切ったときは toast で言います)

### ナビゲーション(時間 = 水平、stack = 垂直)

| 操作 | キー |
|---|---|
| 次 / 前のフレーム(時間方向) | `→` / `←`、`Ctrl+F` / `Ctrl+B` |
| 次 / 前の stack | `↓` / `↑`、`Ctrl+N` / `Ctrl+P` |
| 先頭 / 末尾フレーム | `Home` / `End`、`Ctrl+A` / `Ctrl+E` |

**Image View の下端のスクラブバー**でも移動できます(ドラッグ)。stack を切り替えると
**直前に見ていたフレームに戻ります**。ステータスバーに `frame 7/24` を表示。

### データ層と関係(frame / stack / series / AnalysisSet / batch)

Files パネルは `frame ≼ stack ≼ series` のデータ順序を、batch の管理下に表示します。
AnalysisSet はそのデータを役割付きで参照する別のノードです。定義と操作の正典は
[terminology.md](../terminology.md)、触り方は [startup.md の用語節](startup.md#用語正典は-docsterminologymd)。
`Ctrl/Cmd+W` が閉じるのは**その frame が属する stack**(単発 frame なら frame)で、
`Ctrl/Cmd+Alt+W` が1枚だけ、`Ctrl/Cmd+Shift+W` が batch ごとです。

## 3. 表示操作(モードレス)

**ツールモードはありません。** 押した場所で動作が決まります:

| 左ドラッグの場所 | 動作 |
|---|---|
| 何もない所 | **新規 ROI** を作成(既定。View メニューでパンに変更可) |
| ROI の内側 | その ROI を移動 |
| ROI の角(ハンドル) | リサイズ |

- **ピン(POI)は `P` キー** — カーソルを合わせた画素にその場で打てます(クリック不要・修飾キー不要)
- **右クリックでコンテキストメニュー** — Add pin here / 全幅・全高バンド / この ROI でクロップ / 削除 / フィット
- クリック(ドラッグなし)で ROI 選択、何もない所をクリックで **All(全画面)** に戻る
- `Shift+ドラッグ` は既定の逆(既定が ROI 作成ならパン、パン設定ならROI作成)
- 微小ドラッグはクリック扱い(誤操作防止)。ただし**片方の辺が3px以上あれば作成**するので、4x1 のような細長い ROI も引けます

それ以外は常に共通:

| 常時共通 | 操作 |
|---|---|
| パン | **中ボタンドラッグ** / **Space+ドラッグ** / ホイール=縦 / Shift+ホイール=横 |
| ズーム | **Ctrl(⌘)+ホイール**(カーソル中心)/ `+` `-` / `1` 等倍 / `F` or ダブルクリック=フィット |
| 選択解除 / 削除 | `Esc` / `Del` |

補足: View メニュー「Wheel zooms without Ctrl」でホイール直接ズーム派に切替可。
`G` でピクセルグリッド(8倍以上)。表示レンジ(黒点/白点)、表示ガンマ、
1ch 用カラーマップ(viridis 等、Display プラグインで追加可)は Inspector の Image セクション。
表示ガンマの 1.0（線形）/ 2.2 は Inspector と View メニューからすぐ選べます。
任意値は File > Preferences の Display gamma 行にある `Custom:` へ入力します。
入力できるのは 0 より大きい有限値です。無効な値は適用せず、直前の値を保ちます。
Custom が有効な間は 1.0 / 2.2 のどちらも選択済みとは表示しません。
これは正規化後の表示値 `x` に `x^(1/γ)` を適用する設定で、生の画素値や測定結果は
変更しません。

## 3a. 表示レンジ(黒点 / 白点)

Inspector の `Range (black / white)` で決めます。上段の数値欄に直接入力でき、
下のボタンは**よく使う入れ方の近道**です。**画素値そのものは変えません** ——
表示の伸縮だけで、測定値は生の DN のままです。

| ボタン | 入る値 |
|---|---|
| **Auto** | **実測の min–max**。有限画素の最小値と最大値そのもの |
| **Auto %** | **有限画素の 0.1–99.9 パーセンタイル** |
| `0-1` / `0-255` / `0-65535` | 固定値 |

**Auto と Auto % は「良い方・悪い方」ではなく、別の質問への答えです。**

- **Auto** は、持っている画素を**1つ残らず**表示レンジに入れる唯一の答えです。
  ただし**ホットピクセルが1つ、欠陥列が1本**あるだけで、残り全部が潰れます
- **Auto %** は上下 0.1% ずつを切り落とすので、その手の外れ値がレンジを決めません。
  代わりに**きれいな画像でも 0.2% は切ります**(一様分布の 0.3–0.6 なら
  0.3003–0.5997)。飽和画素の有無を見たいときは Auto です

`Range` モード(link)が **Linked across all images** のときは、どちらも
**開いている全画像**に対して答えます。Auto は全画像の min/max、Auto % は
全画像の画素を**1つのヒストグラムに合算**してから分位を取ります
(分位は画像ごとに取って平均できません)。

パーセンタイルは 65536 bin のヒストグラムで求めます(1パス・メモリ一定)。
有限画素が無い、min==max など答えが出せない場合は **min–max に落ちます**。

**Range モードは3通り**(同じ場所のコンボ):

| モード | 意味 |
|---|---|
| **Auto per frame** | フレームを送るたびに、**そのフレーム自身の min–max** に合わせ直します |
| **Per stack**(既定) | stack のフレームは基準フレームのレンジを共有し、そのまま比較できます |
| **Linked across all images** | 1つの表示レンジを全画像に重ねます。表示だけで、各画像は自分のレンジを保持し、link を外すと戻ります |

`Auto per frame` は**読み込み時の既定値とは別物**です。読み込み時は「整数型は型の
フルスケール(u8→0..255 等)、0 付近の float は 0..1」という慣習が効きますが、
`Auto per frame` はその慣習を通しません —— 任意単位で 0.3–0.6 のような float の
stack が、送るたびに 0..1 に吸着して**モードが効いていないように見えていた**のを
直しました(#245)。読み込み時の既定値そのものは変えていません。

## 3b. A/B 比較(ワイプ / 並べて / 差分)

`\` を押すたびに **オフ → ワイプ → 並べて → 差分 → ブリンク → オフ** と切り替わります
(View > Compare A/B からも同じ)。**A = いま選択中の画像**、**B = もう一枚**。
B は **Files で対象行を右クリック > Set as compare B**(実体を指すので同名スタックでも
取り違えません。選ばれた行には青い **B** が付きます)か、View > Compare A/B > B image
(1 stack = 1 行)で選びます。未選択のままモードを選ぶと、**直前に見ていた画像**が自動で B です。

| モード | 見え方 | 向いている用途 |
|---|---|---|
| **ワイプ** | 1枚のキャンバスに A を全面、B を仕切りの右側だけ重ねる。**仕切りは掴んでドラッグ** | 同一被写体の微差(ノイズ量、シャープネス、色被り)を**境界で**見る |
| **並べて** | 左右2ペイン。**同じズーム・同じ位置**の同じ領域を映す | 差が大きい場合、また ROI や解析結果を左右で見比べる |
| **差分 (A−B)** | 差そのものを画像化。**符号=色相**(A が明るい=暖色 / B が明るい=寒色)、**大きさ=明るさ** | 残差が**ランダムノイズなのか、列 FPN なのか、エッジのアーティファクトなのか**を空間分布で判断する |
| **ブリンク** | 同じ場所で A と B を**ぱちぱち入れ替える**。`B` か `Space` の**タップ**で切替(このモードだけ押しっぱなしではありません)、Inspector の `auto blink` + `seconds per side` で自動往復 | 位置合わせ済みの2枚のどこが動いたか。目は「重ねた差」より「切り替わり」に敏感 |


- **ズーム・表示位置は A と B で常に共通**なので、同じ画素が必ず同じ場所に来ます
- **`Shift+\` で A と B を入れ替え**(どちらが上か迷ったら押す)
- **`Shift+C` で B より後の比較スロット(C, D, …)を並べて表示**
- **`B` を押しっぱなしで B を全面表示** — 仕切りを動かすより、パッパッと切り替える方が
  微差は見えます。離すと元のモードに戻ります(**ブリンクモードだけは長押しではなくタップ**で、
  そちらは離しても戻りません)
- **`Shift+B` で「いま見ているフレームを B に固定」**。そのまま `→` で次フレームへ行けば
  **同じ stack のフレーム 12 と 13 の比較**になります(A が B の位置に来たら自動で A/B 入替)
- **A と B が両方 stack なら、A を送ると B も同じフレーム番号に追従**します
  (`Compare A/B > B follows A's frame number`、既定オン)。B が1枚きりの基準画像
  (ダーク、ゴールデンサンプル)のときは切ってください
- `[` `]` で仕切りを 1% ずつ(`Shift` 併用で 10% ずつ)移動
- 仕切りは掴める範囲が線の左右 7px。カーソルが ⇔ に変われば掴めます。
  ROI の上では ROI 操作が優先されます
- `\` が効かない配列のキーボードのために **`C` でも同じ操作**ができます
- ROI / POI / ピクセルグリッドは**両側に同じものが描かれます**(座標は A 基準)
- **ROIs パネルもスロットを読みます。ROI は1組のまま**で、数値だけがスロットぶん増えます:
  - **並べて表示のとき**(または View > Compare A/B > Statistics layout = side by side):
    1 ROI = 1行のまま、**スロットごとに mean / std / `std / mean [%]` / min / max の
    列グループ**が右へ並びます。列の上にスロットの文字がそのスロットの色で乗ります。
    名前・region・可視チェック・削除は**左に固定**されたままなので、列が画面幅を
    超えても「どの ROI の行か」は見失いません
  - **ブリンクのとき**: 表は重ねられないので、**キャンバスが今映している側の数値**に
    入れ替わります。目は同じセルに留まったまま数字だけが変わるので、**桁が変われば
    一目で分かります**。表の上の帯が「今どれ」を必ず言います
  - ワイプ / 差分 / 比較オフでスロットだけ立てている場合は **A** を出し、
    出していないスロットの文字を下に名指しします
  - **スロットのフレームに ROI が収まらない場合、そのスロットのセルは空欄**になり、
    理由が下に出ます。はみ出した分を切り詰めて測ると、**同じ ROI 名の下に別の母集団**が
    並ぶことになるためです(`All (全画面)` の行だけは各スロット自身の全画面なので常に出ます)
- Inspector の Pixel 表に **`A` / `B` / `A-B`** の列が増えます(単位 `[DN]`)。
  ワイプでは読めない「その画素でいくつ違うのか」はここで読みます。
  差分は**両者のうち広い型**で表示します(u16 と f32 の比較で小数が消えないように)
- A と B でサイズ・dtype が違う場合は Inspector に注意が出ます
- **表示レンジの関係は3通り**(Inspector の `A/B:` コンボ、または View > Compare A/B > Display range):

  | 設定 | 何をするか |
  |---|---|
  | **`auto over every side (union)`(既定)** | 比較中の全側 (A・B・スロット) を **min/max の和集合**に合わせ直す。どの側も飽和せず、どの側も贔屓されない。**フレームを送るたびに引き直します** |
  | `every side uses A's range` | 1つのレンジ、A のもの。A を送っても動きません。他の letter を「A に対して」測っているときはこれ |
  | `each keeps its own` | それぞれの黒点/白点のまま。露出が大きく違う2枚の**形**だけを比べる場合。値が違って見えることを画面が警告します |

  既定が union なのは、`every side uses A's range` だと露出違いの B が飽和して(実測 `>white 99.69%`)
  ヒストグラムが右端の1本になってしまうためです(union では同じデータで `0.02%`)。
  いずれも**表示だけ**で、各画像の黒点/白点そのものは書き換えません。
  `View > Link range` を入れている間はそちらが優先です
- CLI: `viewer --compare wipe|split|diff|blink a.npy b.npy`（先頭2枚が A と B。
  `flip` も `blink` の互換 alias として受理します）
- 並べて表示では**カーソルのあるペインが基準**です。ステータスバーの座標・画素値も
  `A (x, y) = ...` / `B (x, y) = ...` と、どちら側か明示されます
- **統計パネル(Histogram / Projection / Temporal)も A/B になります** — §3c
- 比較の状態(モード・仕切り位置・B の画像・レンジの関係・統計の並べ方・ブリンクの設定)は
  **セッションに保存**されます
- CLI: `viewer --compare wipe|split|diff a.npy b.npy`(先頭2枚が A と B。ブリンクは CLI では選べません)

**差分モード**(A と B が同サイズのときのみ):

- フルスケールは既定で**自動**(|A−B| の 99.9 パーセンタイルを 1/2/5 系のキリ番に丸め)。
  Inspector の「auto scale」を外せば手動で指定できます
- **フルスケールを超えた画素は黄色**にして「x.xx% off scale」と表示します。
  スケールが小さすぎるまま眺めて誤判断しないためです
- キャンバス左下に**カラーバーと数値**(単位 DN)を常時表示
- 「magnitude only |A−B|」で符号なしのグレー表示に切替
- 再計算は A / B / スケール / モードが変わったときだけ
  (実測: 0.3 Mpx で 3 ms、12 Mpx で 107 ms。大きい画像でフレームを送ると各フレームで再計算)

## 3c. A/B の統計(Histogram / Projection / Temporal)

compare が入っている間、この3パネルは **B も一緒に**出します。並べ方は
`View > Compare A/B > Statistics panels` の**1か所**で決まります —— パネルごとの設定では
ありません(「画像と同じ並べ方」は比較の性質であって、ヒストグラムの性質ではないため)。

| 設定 | 見え方 |
|---|---|
| **Auto**(既定) | **画像の並びに追従**。並べて(split)なら左右2枚、ワイプ / 差分 / ブリンクは画像が1面なので重ね描き |
| Overlay | 常に重ね描き。**A が実線、B が破線**、プロットの下に凡例の行 |
| Side by side | 常に左右、**必ず 50/50・A が左**(仕切り位置は真似しません —— 幅の違う2枚では形を比べられないため)。パネルが**論理幅 320 px 未満**だと重ね描きに落ち、そう書きます |

| パネル | A/B で変わるところ |
|---|---|
| **Histogram** | 縦軸が**各側の標本数に対する割合 [%]** に変わります(サイズの違う2枚を棒の高さで比べないため)。B は**必ず A と同じビン**で数えます —— 別々に切ったビンの上に2本の曲線を重ねても比較になりません。x 軸のラベルは**実際に効いているレンジ**を名乗ります(`A and B combined range` / `A's black-white range`)。CFA は plane セレクタで**両側を同時に**絞れます |
| **Projection** | 重ねるのは**同じ軸のときだけ**。原点も長さも一致しない profile は、Side by side を選んでいなくても左右に落として理由を書きます —— 伸ばして重ねたら、データに無い対応関係を捏造することになるからです |
| **Temporal** | **A / B / delta A-B / delta [%]** の表になります。B が stack でなければその列に `- (not a stack)`、チャンネル数が違えば delta 列そのものを出しません。dtype が違えば「両方 DN だが記憶クラスは別」と警告。frame mean のグラフは A 実線 / B 破線で1本の軸に乗ります |

フレームを連続で送っている間は **B 側の再計算を止めます**(1ステップごとに2枚ぶん計算すると
送りが重くなるため)。止めている間は琥珀色の `[stale]` が付き、送るのをやめると追いつきます。
**サーバ集計だけは自動では走りません** —— Temporal パネルの `Measure B` を押したときだけです。

## 4. アノテーション(ROI / POI)

- ROI(矩形)と POI(点)は**共通のアノテーションリスト**。8色パレット自動割当、
  キャンバス上の色と解析グリッド/カーブの色は一致
- 一覧(**ROIs** パネル、既定はフローティング): クリックで選択、チェックで表示/非表示、
  `x` で削除、選択中は下の入力欄で**改名**(解析グリッドの列名になる)。
  `channel` セレクタで表の値を ch(CFA なら R/Gr/Gb/B)ごとに絞れます
- **`X` / `Y` = 行 / 列の選択**。選択しているものによって対象が決まります:

  | 選択中 | `X` の動作 |
  |---|---|
  | **POI(ピン)** | そのピンを通る**1ライン(高さ1px)の行 ROI**を作成(`Y` なら列)。もう一度 `X` でそのピクセル1点に戻る |
  | **なし(All)** | **カーソル位置**の行/列を1px で選択 |
  | **ROI** | 全幅(行バンド)/全高(列バンド)へトグル。もう一度押すと元の矩形に復元 |

  1px の行/列はドラッグでは作りづらいので、キーか右クリックメニュー
  (「Select this row (1 px)」)から作ります。細長いドラッグ(片方の辺が1px)も可。
  正確な値は ROI ウィンドウ下部の x/y/w/h 入力で直接指定できます(ピンは x/y)
- POI の値一覧: 表示中の全ピンの座標と **ch 毎の画素値**(CFA はチャンネル名 [Gr] 等付き)
- すべて**セッションに保存**される(§8)

## 5. 検査機能

### 5.1 ピクセル検査
ホバーで **Inspector > Pixel** に座標・raw 値・正規化値(黒点/白点基準)。ステータスバーにも表示。
CFA 画像はそのピクセルの色チャンネル(R/Gr/Gb/B)を併記。ズーム2倍以上でホバー画素を枠表示。
compare 中は同じ表に **`A` / `B` / `A-B`** の列が増えます(§3b)。

### 5.2 統計(常時表示)
**Histogram パネルの先頭**に、ch 毎(CFA は R/Gr/Gb/B 別)の **mean / std / var** を常に表示。
ROI を選択している間はその ROI の値になります(未選択なら画像全体)。
ROI ごとの mean/std/`std / mean [%]`/min/max は **ROIs** パネルの表です。

`std / mean [%]` は **その行の σ ÷ その行の mean × 100**(表に出ている σ と mean そのもの。
間引いて測っていればその標本の比)。**1枚・dark 補正なし・flat 補正なし**なので時間ノイズ
込みであり、固定パターンとしては**上界**にしかなりません。EMVA が言う PRNU は frame を
超えた層(flat stack + dark stack)が要ります([flat-field-stats.md](../features/analysis/flat-field-stats.md))。
mean が 0 以下の行は比が意味を持たないので `-`(nan も inf も出しません)。
channel = all の CFA/多チャンネルでは**面ごとのレベル差が σ に入る**ため、この列は
面別(R/Gr/Gb/B)で読んでください — 全面の値は面別の値の平均にはなりません。

見ているのが **frame average / frame sum**(§5.2c)のときは、その側の列名が
**畳み方を名乗ります**: `std (mean_t)` / `std / mean [%] (mean_t)`(sum なら
`(sum_t)`)。素の frame には付きません。これは Temporal パネルの `sigma_fpn` と
**取り違えないための名前**です — 同じ蓄積器から出る数ですが、σ_fpn だけが時間残差を
引いた補正済みの量で、この列は畳んだ絵の**素の**空間 σ です
([analysis-layers.md §3.2](../analysis-layers.md) の 2026-08-09 修正)。

### 5.2b 時間方向の解析(連番のみ)
連番を開いていると **Temporal** パネル(下部タブ)に出ます(対象は同じく選択 ROI / 全体):

| 指標 | 意味 |
|---|---|
| temporal noise (σ_t) | 画素ごとの時間方向 var(**ddof=1 の不偏分散**)の平均の √ = **時間ノイズ** |
| fixed pattern (σ_fpn) | 時間平均画像の空間 std(**ddof=1**)から**時間残差を引いた** = **固定パターン**(平坦部でない場合は絵柄成分を含む) |
| &nbsp;&nbsp;temporal residual subtracted (fpn_corr) | 引いた量 `sqrt(mean(s_t,i²/n_i))` [DN]。σ_fpn からは**二乗で**引かれます |
| total (quadrature) | √(σ_t² + σ_fpn²) |

**σ_fpn は補正済みの量です(2026-08-09, #57 判断2)。**
N 枚平均しても時間ノイズは **√N でしか落ちません**。残った分を引かずに
「固定パターン」と呼ぶと、それは量の推定値ではなく**上界**です
(N=16・σ_t=10 DN なら、真の 5 DN の固定パターンが 5.59 DN と読めます)。
そこでこのパネルは `σ_fpn² = max(0, var_spatial(時間平均) − C)`、
`C = mean(s_t,i²/n_i)` を出し、**引いた量 `fpn_corr` を必ず併記します** —
補正前の上界が要るときは `√(σ_fpn² + fpn_corr²)` で戻せます。
NaN で枚数が減った画素は**その画素自身の n_i** で補正されます。

- **引き算が負に落ちたときは 0 に「クランプ」し、そう言います** — 値のセルが
  `0 (clamped)` になり、表の下に理由が1行出ます。**この 0 は「固定パターンが
  無い」ではなく「この stack は自分の時間ノイズ床より下を分解できない」**
  という測定についての申告です。枚数を増やすか、より平坦な被写体で測り直してください
- `Copy (TSV)` / `Save (CSV)` にも `fpn_corr [DN]` と `fpn_clamped` の列が出ます
- **時間平均画像(frame average)の空間 σ とは別の数です** — 同じ蓄積器から出ますが、
  片方だけが補正されています。取り違えないように ROIs 側の列は
  `std (mean_t)` と畳み方を名乗ります(§5.2c)
- サーバ集計も**同じ式**です。古いピア(protocol 5 以下)は補正前の数を返すので、
  接続時に自動更新されます

**σ_t は 1 つの stack の量で、測る場所が変わっても数は変わりません。**
このパネルで測っても、サーバ集計(下記)で測っても、Stack ROIs の蓄積器から
出しても、画素毎の時間分散は ddof=1 の同じ式です(#57 項目3)。以前は
このパネルだけが ddof=0 で、同じ stack が local と server で √(N/(N−1)) 倍
(N=16 で 3.3%)食い違っていました。**local / server は転送路であって量では
ありません。**

加えて **frame number(横軸)vs ROI mean value(縦軸)** のグラフを表示(現在フレームの位置に
マーカー)。フレーム間のドリフト・フリッカ確認に使えます。EMVA 1288 の温度/固定パターン分離と
同じ考え方ですが、単一 stack からの簡易版です。

- **`Copy (TSV)` / `Save (CSV)...`** で、temporal summary(plane 毎の σ_t/σ_fpn/σ_tot と
  補正の申告 fpn_corr/fpn_clamped)・
  同じ画像/ROI の **H/V profile statistics**(Projection パネルの数値そのまま)・per-frame 表
  (plane 毎の mean / sigma [DN]、行/列プロファイルの非一様性 [%])が provenance ヘッダ付きの
  **1つの文書**として出ます(`#` 見出しのセクション、各セクションは矩形 ——
  docs/features/export/export-design.md)。per-frame 行に **σ_t の列はありません** —— σ_t は stack の
  属性であって frame の属性ではないからです。compare 中は A/B/slot 全側が side 列付きで
  載ります。temporal と profile の測定領域が違うとき(サーバ集計は常に全面)は両方を明記します
- **`x axis...`** で per-frame チャートの横軸をフレーム番号から実量(経過時間・露光・温度
  など)に差し替えられます: 名前・単位・値リスト(カンマ/空白/タブ区切り、1フレーム1値)を
  貼って Apply。個数がフレーム数と合わなければ両方の数字を言って拒否します。stack 毎に
  保存され(セッション往復可)、export の per-frame 表にも列として載ります。この軸の役割は
  **監視**(mean カーブ)です —— 軸に対するリニアリティの**フィット**は Series Analysis
  パネルの仕事になりました(条件を振った並びは定義上 series。docs/analysis-layers.md §3.3)
- リモートの stack は**サーバ側で集計**され、`[server <ホスト>, N frames]` と出ます
  (`File > Stack loading > Remote processing` で切替)。
  開いてすらいない連番も Browse パネルの**連番(group)行**を右クリックして
  「Temporal stats (server) for stack "…"」から測れて、そのときは
  `not opened:` 付きで出ます。**1 回 = 1 stack です** —— 複数行を選んでから
  σ_t を計算する経路は**ありません**(2026-08-09 裁定, #107)。選択をまたいだ
  σ_t は「別の時間軸のフレームを 1 本に混ぜた数」で、どの stack の測定値でも
  ないためです(#81 の平均と同じ理由。ただし平均は「stack 毎に 1 枚」という
  正しい答えがあったのに対し、σ_t には**選択の形をした答えが存在しない**ので
  入口ごと消えました)。stack が 3 つあるなら 3 回測ってください。
  複数行を選んだまま連番行を右クリックしてこの項目を選ぶと、**どの stack を
  測ったかをトーストと Messages に残します**
- compare が入っていると **A / B / delta の表**になります(§3c)

### 5.2c stack を1枚に畳む(frame average / frame sum)

stack の時間軸を畳んで **1枚の frame** として開けます。畳み方は **mean / sum の
選択**で、既定は mean です([analysis-layers.md §3.2](../analysis-layers.md) の裁定):

| 入口 | 畳み方 |
|---|---|
| Files で stack 行を右クリック > **Open frame average** | mean(画素ごとの時間平均) |
| Files で stack 行を右クリック > **Open frame sum** | sum(画素ごとの時間和) |
| Browse の各「Open as frame average」/ Temporal の同名ボタン | mean(名前どおり平均のみ) |

- **average は stack の中で完結します**(2026-08-05 の裁定)。Browse で複数行を
  選んで「Open N selected as ... frame averages」を選ぶと、**選んだ stack の数だけ
  平均が開きます** — 3 stack を選べば 3 枚で、24 枚を混ぜた 1 枚ではありません。
  露出やゲインの違う別 stack のフレームは**同じ時間軸に居ない**ので、混ぜた平均は
  もっともらしく見えて意味がありません。メニュー項目自体が「(one per stack)」と
  枚数を先に言い、実行後にも枚数をトーストで言います
  - 内訳の決まり: **連番行(group)= その stack 全部** / **展開したフレーム行 =
    その stack のうち選んだ枚数だけ**(1 stack 内で N 枚選べば従来どおり 1 枚) /
    **単独の .npy 行 = それ自身**(その行を単独で右クリックしたときと同じ結果)
  - 「stack ではないファイルどうしを平均したい」ときは、先に
    **Open N selected as stack** で 1 つの stack として開き、それを平均してください
    (「これらは 1 つの stack だ」と宣言する一手が要る、という意味です)
  - 形の違う stack を混ぜて選んでも平均は通ります(1 つに束ねないので)。
    束ねる **Open N selected as stack** のほうは従来どおり形の一致が要ります
- 結果は stack ではなく **frame** です(Files では単発 frame として batch に
  ぶら下がります)。なので Histogram / Projection / ROIs がそのまま効きます。
  ただし **時間平均画像の空間 σ は σ_fpn そのものではありません**
  (2026-08-09, #57 判断2)。同じ蓄積器から出ますが、Temporal パネルの
  `sigma_fpn` は**時間残差 `mean(s_t,i²/n_i)` を引いた補正済みの量**なので、
  こちらより**小さい値になるのが正常**です。取り違えないように**名前が違います**:
  ROIs の列は畳み方を名乗る `std (mean_t)` / `std (sum_t)`、Temporal の行は
  補正量とクランプを申告する `sigma_fpn`
  ([analysis-layers.md §3.2](../analysis-layers.md) の修正どおり)
- **double で蓄積**し、NaN は**画素ごとに除外して数えます**(分母に畳みません)
- **NaN が混入していたら Warning が出ます** — 除外したサンプル数と有効枚数
  (何枚を畳んだか)を併記します。同じ数字は結果の note にも残ります
- 部分ロードなら名前と note が「n of N」と言います(黙って「平均」を名乗りません)
- **sum の注意**: NaN の除外が起きると**画素ごとに足された枚数が違う** =
  画素間で別の量になります。note が有効枚数の幅(`0..3 of 3` のように)を
  併記するので、画素どうしを比べる用途では mean を使ってください
- 計算で作った frame はファイルを持たず、**名前と note に由来**を運びます。
  セッションにはレシピ(元 stack の先頭フレームのパス+畳み方)が書かれ、
  復元時に**計算し直します**。sum のレシピ行(`stacksum`)は旧版ビューアでは
  読み飛ばされます(mean に化けて戻ることはありません)
- **note は「いつ計算したか」も言います**(`computed 2026-08-07 10:16:43` の形)。
  報告書に貼る絵の日付はここから写せます
- **元 stack がディスク上で書き換わっても、この絵は勝手に描き直されません。**
  Files の右クリック > Reload from disk で stack を読み直すと、その stack から計算した
  frame average / sum は **(stale)** になります — Files の行・ウィンドウ
  タイトル・Inspector・Temporal パネルの TSV/CSV エクスポートの全部が
  そう言います。絵を今の stack に合わせるのは**ユーザーの一手**:
  Files でその frame を右クリック > **Recompute from stack**(記録が更新され、
  マークが消えます)
- **セッション復元は世代を照合します**: レシピと一緒に、畳んだ各フレームの
  identity tuple(パス+mtime+サイズ)の記録(`stackavggen` 行)が保存され、
  復元の再計算がこの記録と食い違うと note と Files 行が
  「recomputed from newer files (source changed since …)」と言い、Warning が
  出ます。ファイルが書き換わっていなければ何も言いません(同じ絵なので)。
  旧版ビューアはこの行を読み飛ばし、世代の主張なしで復元します
- **同じ stack を2回畳むと文書は2つできます**(結果は dedup されません)。
  2つが同じ記録を持っていれば Files のツールチップが「same picture as …」と
  言います。同じレシピのセッション2行は復元でも2枚のまま潰れません。
  stack を別 batch に移してもレシピはパスで追随します

### 5.2d 役割を束ねて測る — Set Analysis(DSNU / PRNU)

**View > Set Analysis**。ここだけが **DSNU / PRNU という名前を名乗ります**
([terminology.md](../terminology.md) の不変条件: 前処理・参照を含意する有名名は
SetAnalyzer だけが名乗る)。他のパネルの `std / mean [%]` や `sigma_fpn` は
中立名で、同じ量ではありません。

対象は **AnalysisSet** — 「どのデータが dark を演じ、どれが image を演じるか」を
**宣言**した束です。フォルダ名や level 0 から推測することは決してしません
([reader-analysisset.md](../features/adapters/reader-analysisset.md))。Files で set ノードを選ぶと
このパネルがその set の話になります。

| 行 | 役割スキーマ | 出るもの |
|---|---|---|
| `DSNU [DN]` | `{"dark": Stack()}` | dark stack の補正済み σ_fpn(プレーン別) |
| `PRNU [%]` | `{"image": Stack(), "dark": Stack()}` | 画素毎に dark を引いた差画像の σ / μ |

- 式は [flat-field-stats.md](../features/analysis/flat-field-stats.md) (b) 確定分そのままで、**両方とも
  時間残差 `C = mean(s_t,i²/n_i)` を引きます**。引いた量は `fpn_corr [DN]` 列で
  申告し、引き過ぎて負になったら **0 でクランプし「(clamped)」と言います**
  (黙って 0 を返しません — 0 は「固定パターンが無い」ではなく「この stack の
  時間ノイズの下に見えない」という意味です)
- **どちらの役割も stack で、2枚以上**が要ります(補正は σ_t で出来ているので、
  1枚では引けません)。満たさない束縛は**実行せず理由を1文**で言います:
  役割が無い / 未束縛 / frame に束ねてある / series に束ねてある / 枚数不足 /
  image と dark の形が違う / μ ≤ 0
- 結果は**自分の set と役割の n/N を名乗ります**:
  `PRNU [%] - set "10lx vs dark": image 5/5, dark 5/5`。表でこのタグは省きません
- **`shading [%]` と `shading p-p [DN]` が値の隣に必ず立ちます**(#57 判断7)。
  測るのは**その行が統計を取った当の画像**(DSNU なら M_dark、PRNU なら差画像 D)
  に当てた **2次面の p-p と中心比**で、除去したかどうかに関係なく、いつも同じ次数で
  測ります。「除去すべきだったか」を毎回読み手が判定できる、というのがこの列の役目です
  (dark には比の分母になる水準が無いことが多いので、その場合 `%` は `-` になり
  p-p [DN] が答えを持ちます)
- provenance 欄に **cutoff**(シェーディング除去の帯域)が必ず出ます。既定は `raw`
  ですが、これは未実装だからではなく**そう決まっている**からです(判断7)。
  detrend 済みの stack を役割に束ねれば、cutoff はその方式と窓を自分から名乗ります
  (下の 5.2e)
- **PRNU は画素毎減算形**です(#57 判断4)。分散差形は別の推定量なので、
  同じ名前で入れ替えることはしません — どちらを計算したかは provenance が言います
- 規格名は画面に出しません。照合が済んでいない量に規格の名前を付けないためです
- **remote は未対応**(集計はローカルで走ります)。ピア側で走らせる形は別 PR です

### 5.2e シェーディングを除いた stack を作る — detrend(前処理の段)

Files で stack を右クリック → **Detrend (remove shading)**。選ぶと
**detrend 済みの stack が新しく1本できます**。元の stack は無傷でそこに残ります。

**これは「オプション」ではなく「段」です**(#57 判断6)。Histogram / Projection /
ROIs / Temporal に detrend のチェックボックスは付けません — 付ければ同じ列名で
別の量が出てしまうからです。欲しいのは detrend 済みの**データ**で、それを作れば
あらゆる解析がそのまま掛かります([analysis-layers.md](../analysis-layers.md) §5)。

- **既定は「掛けない」**(判断7)。既定のカットオフはそのまま社内の基準値になって
  しまうので、自己記述的な既定は「何もしていない」だけ、という決めです。代わりに
  シェーディング量が常に併記されます(5.2d)
- **掛けるときの既定は「多項式2次・減算・プレーン別」**。メニューの1行目がそれで、
  次数 1/3/4 とブロック中央値 (32/64/128 px)、乗法性シェーディング用の除算は
  「other bands」の下です。**除算はノイズを 1/s 倍するので分散が場所によって
  変わります**(下流の推定量はそれを一様だと仮定しています) — 選べますが警告付きです
- **面は stack の時間平均に対して1回だけ当て、それを全フレームから引きます。**
  引くのは画素毎の定数なので **σ_t は変わりません**(約束3: detrend は空間統計に
  だけ掛かる段)。プレーンごとの平均水準は足し戻すので、**水準(mean)も変わりません**
  — 水準に対する比を取る量が壊れません
- 生成物は**撮ったものの顔をしません**: 名前が「detrended (poly2 sub)」と言い、
  note が方式・窓・除去前後のシェーディング量・「computed, not captured」を運び、
  ファイルは持ちません。セッションには**レシピ**が入り、開き直すと計算し直します
- この stack を set の役割に束ねると、Set Analysis の **cutoff がその方式と窓を
  自分から名乗ります**。どの帯域で測った数字かが、貼り付けた先でも残ります
- **除去した面そのもの(シェーディングマップ)はまだ出せません** — 公開 map / `emit_map`
  は #49 で取り下げ済みです。現行版で出せるのは数値(p-p と中心比 [%])だけで、
  map を再導入するには新たな裁定が要ります
- 一度 detrend した stack をもう一度 detrend することはできません(1段1カットオフ)。
  帯域を変えたいときは**元の stack から**選び直します

### 5.3 ヒストグラム(内蔵)
- 黒点/白点レンジで正規化した 256bin。**選択中の ROI に自動追従**(未選択なら全体)
- **CFA 画像は R/Gr/Gb/B の4系列**に自動分離(チャンネルバランスが一目)。
  系列が2つ以上あれば `plane` セレクタで1つに絞れます(絞るのは**描画だけ**で、
  ビンは常に全系列ぶん計算されています)
- log 切替、黒点未満/白点超過のクリップ率表示。約100万px サンプリング+キャッシュ

### 5.3b 値域ハイライト — この値の画素はどこにいるか

ヒストグラムの x 軸上を**左ドラッグ**すると、その値域に入る画素が画像の上で
**マゼンタに塗られ**、何画素あったかがパネル下部と canvas のバッジに出ます。
「裾を選んで frame を送り、どの画素が出入りするか見る」ための道具です。

- **ドラッグで選択、ダブルクリック(または `[clear]`)で解除。** 横 4px 未満の
  ドラッグは「ジッタ付きクリック」とみなして何も起きません。縦方向は意味を
  持ちません(y は度数)
- **端点はビン端に外側スナップ**し、区間は**半開 `[lo, hi)`**。プロットはビンより
  細かい区別を見せられないので、端点はビン境界を名乗ります
- **端のビンに触れるとその側は開区間**になります。端のビンはグリッド外の値を
  畳み込んでいる(=「ここから上、全部」)ので、`>= 255 DN` と申告され、
  塗った数は必ずそのバーの高さと一致します
- 値は**生の DN**です。表示レンジやガンマを動かしても選択は動きません —
  選んだのは「この値の画素」であって「この明るさに見える画素」ではないからです
- **プレーン束縛**: ドラッグ時の `plane` セレクタが選択に固定されます。CFA で
  `R` を選んでいれば R の位置の画素だけが光ります。多チャンネル(RGB)で `all` の
  ままドラッグすると「1画素1値」が決まらないので断られます
  (`highlight needs ONE channel - pick it above`)。B 側のプレーンは**名前で**
  対応づけられ、その名前が無い文書は塗らずに `B: no R plane` と言います
- **数はビンからではなく、塗ったループが数えます**(ビンは約100万px の
  サンプリング+ROI 限定、塗りは全画素・全フレーム)。なので申告文は必ず
  `whole frame` と領域を名乗ります。NaN は決して該当せず、分母にも入りません
- **画面と export は同じ関数を通ります**。ハイライト中に「Save view as PNG /
  Copy view」すると PNG にもマゼンタが焼き込まれ、toast と stderr に
  `exported with value highlight ...` が付きます
- 差分表示(A-B)は値ではなく差を描く別経路なので塗りません。armed のときは
  バッジが `highlight armed - not shown in difference view` と言います
- セッションには保存されません(再起動で消えます)。ROI が「どこを測るか」の
  宣言なのに対し、これは手に取って覗くレンズだからです

設計の全体像と理由は [histogram-select-design.md](../features/histogram/histogram-select-design.md)。

### 5.4 動的クロップ
- ROI を選択して **「Crop to selected ROI」** → メモリ上で即切り出し(ファイル再読込なし)。
  アノテーションは新しい座標系に追従シフト
- **「Restore full」** → RAW はレシピから、npy はパスから読み直して全体復帰
- CFA 画像の crop 原点はパターン周期(Bayer 2px / Quad 4px)に自動スナップ
- 読み込み時クロップは RAW ダイアログの **crop on load** か CLI `--raw-crop`

## 6. 測定(Analysis)

設計の全体像と理由は [measure-ux.md](../features/analysis/measure-ux.md) を参照。

1. **Measure メニュー**(質問別グルーピング: `Noise / SNR`、`Resolution / Focus`、
   `Uniformity / Flat field`、`Statistics / Sanity`。前提条件はツールチップ、ホストが判定できる未達前提は
   グレーアウト+理由表示)か、Analysis パネルのカテゴリ → 測定の
   2段セレクタで選び **Run**(`auto` で画像/ROI/レンジ変更時に自動再実行)。
   メニュー実行と **`M`(= 直前の測定を再実行)**は Analysis パネルを
   前面に出す。連番があれば Noise グループから Temporal パネルへ飛べる
2. 対象: **表示中の ROI 全部**(それぞれが1列)。ROI がなければ画像全体
3. 結果:
   - グリッド直上に **provenance 行**:
     `[local] 画像名 (frame i/n) 寸法 dtype | 対象 | レンジ | 実行時刻 | 所要 ms |
     アナライザ名 <版> (プラグインファイル名)`。
     末尾が「誰が計算したか」(#46): dll のフルパスは行のホバーで出る。
     **版はプラグインの自己申告**(同梱アナライザは `1.0.0`)。版を名乗らない
     V1/V2 のサードパーティ製プラグインでは `<…>` ごと出ない —— 空欄は
     「宣言なし」であって「不明」ではないため。
     `auto` オフで入力が変わると琥珀色の「inputs changed - Run (M)」が付く
     (古い数値を現在の入力の数値と誤読させない)
   - 数値 → **ROI × 指標の比較グリッド**(ROI のラベルが列名、ヘッダは ROI 色)。
     **unit 列**付き: キーが単位を持つもの(`snr_db`, `*_pct`, `(cy/px)`)は
     そこから、画像値系は保存 dtype にかかわらず DN。
     アナライザの**見出し数値**(mtf50 / prnu_pct / noise)はアクセント色で強調
   - 曲線(SFR 等)→ グリッド下の**折れ線プロット**(ROI 色で重畳)。
     ホバーで最寄りサンプルの数値読み出し、`ref` チェックで基準線
     (規格値・合格ライン。セッションに保存)
   - **Copy table (TSV)** = グリッドをクリップボードへ、
     **Export curves (CSV)...** = 曲線をファイルへ。どちらも provenance 行を
     `#` コメントで含み、2行目の `# plugin: <フルパス>` が計算した dll を
     引用可能な形で名指しする
   - `method` 行に手法と制約が必ず明記される

同梱の測定(詳細・出力キー・制約 → [analyzers.md](../reference/analyzers.md)):

| 測定 | 用途 | 前提 |
|---|---|---|
| stats/moments | 基本統計・分散・エントロピー | 任意 |
| noise/floor | ノイズフロア(タイル中央値)・SNR、CFA別 | 平坦め ROI |
| uniformity/prnu-fpn | PRNU%・行/列 FPN・シェーディング | 明るいフラット |
| sharpness/gradient | フォーカス相対比較 | 同一シーン |
| iso12233/e-sfr | SFR カーブ・MTF50/20 | 斜めエッジ ROI(5〜40°) |

## 8. セッション

`Ctrl+S` / File > Save Session... で `.vsession`(テキスト)に保存:
開いている全画像の**再読込レシピ**(RAW は2軸+crop まで、.npz は配列名まで)、
黒点/白点(link 表示レンジ含む)、選択画像、ズーム・表示中心、表示ガンマ
（Custom 値を含む）、グリッド、
**全アノテーション**(バンド化前の矩形と選択状態も)、**開いていたパネル構成とドック配置**、
ヒストグラム/射影/解析の表示設定、**A/B 比較の状態**(モード・仕切り・B・レンジの関係・
統計の並べ方)、**batch 名と stack 名**、そして **series 一式**(名前・パラメータ・単位・種類・
メンバの値と順序 — stack メンバの畳み方宣言と frame メンバも含む)、**Series Analysis の
フィット設定**(方式・窓)。連番は stack ごとに**見ていたフレーム**まで復元されます。
復元は Open / ドラッグ&ドロップ / `--session`。旧版セッションも読めます。

- **batch と series は「名前」で復元**します(id は実行ごとに変わるため)。
  series のメンバは**先頭フレームのパス**で辿ります。解決できなかったメンバがあれば
  黙って捨てず件数を出します
- 古いビューアは知らない行を読み飛ばすので、**series ブロック付きのセッションも開けます**
  (series が 0 個になるだけ)
- 終了時・クラッシュ時・**60 秒ごと**に自動保存されており、`File > Restore last session`
  で戻せます
- **保存に失敗しても前のセッションは壊れません。** 書き込みは同じフォルダの一時ファイルに
  対して行い、書き終えてディスクに送り出してから対象へ **rename** で置き換えます。
  途中で落ちても・ディスクが一杯でも・電源が切れても、ファイルは**前の内容そのまま**か
  **新しい内容そのまま**のどちらかで、半端な状態にはなりません。失敗したときは
  「session NOT saved: 〈理由〉 - the previous 〈ファイル名〉 is unchanged」と出ます
  (自動保存は無人で走るので toast ではなく Messages パネルに1行)。
  Windows では**読み取り専用のファイル**や**他のプロセスが開いているファイル**は
  置き換えられません(POSIX と違う点)。その場合も前のファイルは無傷で、理由がそのまま出ます
- 注意: Process で生成した画像(ファイル実体なし)は保存対象外です
- **設定ファイル `prefs.txt` も同じ扱いです。**書き込みに失敗しても前の設定
  (テーマ・ウィンドウ位置・ブックマーク・履歴)はそのまま残り、Messages パネルに
  「preferences NOT saved: 〈理由〉 - the previous prefs.txt is unchanged」と1行出ます。
  パネル配置 `layout.ini` は、起動時の一度きりの書き換え(旧 `Remote` パネル名の移行)が
  同じ扱いです。**ImGui 自身が終了時などに書く分は対象外**で、ここだけは直接上書きのままです

### 8a. 手で書く設定ファイル `settings.jsonc`

`prefs.txt` の隣(`%APPDATA%/viewer/` または `~/.config/viewer/`)に
**`settings.jsonc` を置くと、そこに書いたキーが `prefs.txt` の値より優先されます。**
アプリはこのファイルを**読むだけで、絶対に書き戻しません** —— だから書いた
コメントが消えません。無ければ何も起きず、挙動は今までと同じです。

**始め方**は `viewer --settings-template`。今の設定のうち**既定と違うものだけ**を
JSONC で標準出力に出すので、そのままファイルに落としてください
(このコマンドはファイルを一切書きません)。

```
viewer --settings-template > "%APPDATA%/viewer/settings.jsonc"
```

決まりごと:

- **形式は JSONC** = JSON + `//` `/* */` コメント + 末尾カンマ。
  **JSON5 ではありません** —— 単引用符・裸のキー・16進・`Infinity` は断ります。
  エディタの JSONC モードとアプリが同じものを同じ意味に取るためです
- **書いていないキー = 未設定。** 既定と同じ値を書いても動きは変わりませんが、
  **将来既定が変わったときに効きます**(書いた人はその値のまま、書かなかった人は
  新しい既定に乗る)。既定に戻すには**値ではなくキーごと消して**ください。
  `null` は書けません(型エラーとして行・列を名指しします)
- **優先順位**は 組み込みの既定 < `prefs.txt` < `settings.jsonc` < コマンドライン。
  つまりここに書いたキーは**粘ります** —— メニューでトグルすると当座は変わりますが、
  次の起動でこのファイルが勝ちます。そのときは「settings.jsonc set N preference(s)
  that were saved differently: …」と Messages に1行出ます。トグルを効かせたければ
  そのキーを消してください
- **知らないキーは飛ばしますが、黙りません。** 行・列と、綴りの近い既知キーを
  Messages に出します
- **壊れたファイルは名指しで断り、既定に落ちません。** 括弧が合わない等で
  読めないときは `settings.jsonc:5:1: 〈理由〉` と出したうえで**そのファイルを
  1キーも読まず**、`prefs.txt` と組み込みの既定のまま起動します。
  **書き戻しません** —— 上書きすると直す元の記述ごと消えるからです。
  1つのキーだけが型違い・範囲外のときは、**そのキーだけ**断って残りは活かします
- `appearance.displayGamma` は 0 より大きい有限値を受理します。1.0 と 2.2 は
  UI のプリセットですが、ファイルの値域をその2つに限定しません。0、負数、
  float へ変換したときに 0 や無限大になる値は、そのキーだけを拒否します

読むキーのうち `loading.rawRecipes` だけは**オブジェクトの配列**です(§2.2b)。
1件が読めなくても**その1件だけ**を名指しで断り、残りのレシピは読み込みます。

まだ読まないキー(キーバインド、raw の既定、Browse の起動方法／並び順)は
ファイルに書くと「まだ読みません」と名指しで言います。詳細は
[settings-inventory.md](../features/settings/settings-inventory.md) §10。

### 8b. Preferences パネル

`File > Preferences...` は設定表34行を並べます。Read 27行には現在値と、
**どの層が決めたか** (`default` / `this machine` /
`settings.jsonc:<line>` / `command line` / `session (.vsession)`) が出ます。session の
出所は `.vsession` が復元する表示ガンマとピクセルグリッドの2行だけです。
Later 5行 / NotHere 2行は値の代わりに、その場で扱わない理由を示します。

- パネルで変えた値はこのマシンの `prefs.txt` に保存されます。ただし現行版では
  `remote.repoUrl` / `readers.editor` の永続化と `memoryBudgetGB` の編集が未完です
- 同じキーを `settings.jsonc` が決めている場合は、その場の変更が次回起動で戻ることを
  変更時に警告します。編集できる値セルの右クリックから **Copy as JSONC** を選べます。
  **Reset to default** はまだ実装されていません
- **Copy template** は現在値を含む全体雛形をコピーし、**Open settings.jsonc** は
  `readers.editor` → `$EDITOR` → `code -g` → OS 関連付けの順で外部エディタを開きます
- Reader の登録場所は `readers.searchPath`。Preferences の **Open...** から Reader
  パネルへ移り、ファイル／フォルダの追加・削除・順序変更を行います

## 9. コマンドライン

```
viewer [options] [files...]
  --session <f.vsession>     セッション復元
  --raw-dtype <t>            u8|u16|f32|f64
  --raw-interp <i>           gray|rgb|bgr|rgba|bgra|bayer|quad-bayer
  --raw-format <fmt>         旧式複合名 (gray16, bayer16, ...) も可
  --raw-size <WxH>           ダイアログなしで開くには dtype/interp と size が必要
  --raw-offset <bytes>  --big-endian  --bayer-pattern <RGGB|...>  --quad-bayer
  --raw-crop <x,y,WxH>       部分読み込み
  --cfa <none|bayer|quad>    1ch ファイル(.npy 含む)がモザイクで届く場合の指定
  --zoom <z>  --center <x,y> 起動時の表示状態
  --compare <off|wipe|split|diff|blink>  先頭2枚を A/B 比較で開く (`flip` は互換 alias)
  --stack <ask|always|never> 1枚開いたときの連番兄弟の扱い(フォルダ Open には効かない)
  --mem-budget <GB>          連番ローダが握ってよい量(既定 auto = 物理 RAM の 60%)
  --frame <system|integrated>  タイトルバー: OS のもの / メニューバー統合(既定は前回値)
  --settings-template        手で編集する settings.jsonc の雛形を標準出力へ(§8a)
                             全キーを出し、既定値の行はコメントにします。ファイルは書きません
  ssh://user@host/path.npy   リモートのファイルを開く
  ssh://user@host/~/dir      リモートに接続してそのフォルダを表示(ホストだけでも可)
  --remote-exe <path>        向こうで peer を起動する方法
                             (既定 ~/.viewer/viewer-serve、初回接続時に自動導入)
  --remote-policy <auto|local-fetch>  測定をどちら側で走らせるか
                             (既定 auto = サーバ側 / local-fetch = タイルを引いて手元で)
  --serve                    自分が peer になる(stdin/stdout で応答)
```
例: `viewer --raw-dtype f32 --raw-interp bayer --bayer-pattern rggb --raw-size 4096x3072 dump.raw`

`--cfa` と `--bayer-pattern` は**どちらの順でも効きます**。

`viewer --help` が常に正典です(自己診断用の `--*-selftest` も `--bench` も
そちらに全部出ます)。個数はここに書きません — 22 個と書いてあった期間に実際は
31 個あり、正典を名乗る側と数える側が食い違っていました。ここに無い旧オプション(`--npy-axis` など)は撤去済みで、
渡すと理由を言って続行します。

## 10. トラブルシューティング

| 症状 | 対処 |
|---|---|
| Linux でファイルダイアログが開かない | `zenity` か `kdialog` をインストール(D&D は常に可) |
| ウィンドウを動かせない / 枠が変 | `viewer --frame system` で OS のタイトルバーに戻して起動(`View > Integrated title bar` でも切替。設定は保持されます) |
| 日本語ファイル名が「?」になる | CJK フォント導入(Ubuntu: `fonts-noto-cjk`)。起動時トーストで警告 |
| Bayer の crop 位置が 1px ずれる | 仕様: CFA 周期(2/4px)へのスナップ。パターン破壊防止 |
| e-sfr が "no clear single edge" | ROI 内にエッジ1本だけ入れる。傾き 5〜40°、コントラスト確保 |
| ROI が多くて解析グリッドの右端が読めない | グリッドは**横スクロール**します(metric と unit の2列は固定表示)。ROI 数の上限はありません |
| リモート画像に ROI / ピンが置けない | まだ間引きプレビューです。`PREVIEW 1/N` の帯が消える(全画素が届く)まで待ってください |
| 統計パネルの B に `[stale]` が付く | フレームを連続で送っている間は B 側の再計算を止めています。送るのをやめれば追いつきます(§3c) |
| 動作がもたつく / 操作が遅れて反映される | まず **View > Show frame time** で描画自体を確認。描画が速いのに引っかかる場合は、リモート表示(ssh X11 等)で **View > Low bandwidth** が入っていないか確認(入力1回あたりの描画枚数を絞る設定なので、ローカルでは切る) |
| ssh 越しで重い / 帯域を食う | **View > Low bandwidth (remote / ssh)** を有効に。設定は次回起動にも引き継がれます |
| プラグインが読み込まれない | 起動時 stderr に理由(ABI 版数不一致 / CPU 実装なし / 重複名)。`plugins/` は exe と同階層 |

### ビルド環境まわり (Windows)

| 症状 | 原因と対処 |
|---|---|
| ターミナルで `cmake` が見つからない | インストール後に開いたままのターミナル/VSCode は**古い PATH を保持**している。VSCode を完全終了して再起動(タスクバー常駐も終了) |
| configure が `SSL peer certificate ... was not OK` (status_code 60) で失敗 | MinGW/WinLibs 同梱の CMake は CA ストアを持たず、FetchContent の GitHub ダウンロードが検証エラーになる。**CA バンドルを指定**する:<br>`cmake -S . -B build -DCMAKE_TLS_CAINFO="C:/Program Files/Git/mingw64/etc/ssl/certs/ca-bundle.crt"`<br>**環境変数 `CMAKE_TLS_CAINFO` は効かない** —— 現行の CMake は FetchContent のサブビルドに伝播しないので、`-D` の形で毎回渡すか、キャッシュに残る build ディレクトリを使い回すこと(`CMAKE_TLS_VERIFY=0` での回避は非推奨) |
| MinGW でのビルド例 | `cmake -S . -B build-mingw -G Ninja -DCMAKE_BUILD_TYPE=Release` → `cmake --build build-mingw` → `.\build-mingw\viewer.exe`(MSVC は必須ではない) |

#### ビルドとネットワーク —— オフラインの clean clone について

`.exr` を外す `-DVIEWER_WITH_EXR=OFF` は**廃止しました**(2026-08-09)。
**ビルドを切り替えるフラグはこのプロジェクトには1つもありません** ——
`cmake -S . -B build && cmake --build build` が唯一の手順です。

その**代償**を隠さずに書きます。OFF の道が無くなったので、OpenEXR + Imath の
取得が**無条件**になりました。したがって:

> **ネットワークの無い clean clone は、OpenEXR/Imath が既にそのマシンに
> 入っていない限りビルドできません。**

既存のチェックアウトは `build/_deps/` にキャッシュを持っているので影響を
受けません。新規クローンだけの話です。逃げ道は2つあり、どちらも意図的に
残してあります:

| 状況 | どうなるか / どうするか |
|---|---|
| システム(distro / vcpkg / brew)に OpenEXR 3.1+ がある | `find_package` が先に走り、**ダウンロードは発生しません**。以前よりこれが重要になりました |
| source tree がローカルにある | `cmake -S . -B build -DFETCHCONTENT_SOURCE_DIR_IMATH=<imath> -DFETCHCONTENT_SOURCE_DIR_OPENEXR=<openexr>` |

これは TIFF が自前リーダになった理由(`core/tiffread.h`)と**逆向きの結論**
です。EXR には「小さくて正直なリーダ」という選択肢が無いため、そちらを
取りました。vendor 化や CI キャッシュでこの制約は消せますが、それは別の判断
です。
