# Select stacks ダイアログ (picker) の設計

Open Folder(ローカル)とリモートのフォルダスキャンの後に出るダイアログ。
スキャンが見つけた連番ファイル群から「何を・どういう stack で開くか」を決める場所。

## ユースケース

- **UC1: サブフォルダごとに1スタック** — リニアリティ測定の定番レイアウト
  (linset: 7つの光量フォルダ × 24フレーム)。従来どおり、既定のまま Load で
  フォルダごとのスタックが7本できる。
- **UC2: 複数のサブフォルダを1つの stack として開く** — 撮影がディレクトリに
  分割されているが論理的には 1 つの stack の場合。下部のロードモードを
  「選択全体を1スタックに結合」に切り替えると、選択中の全ファイルが
  自然順(番号順)で1本のスタックになる。
- **UC3: フォルダ内のファイルを絞り込み、その結果だけを開く** — 例:
  `*_dark*` だけ、abset の A バリアントだけ。フィルタは**ファイル単位**で
  効き、グループのファイルリスト自体がマッチ分に切り詰められる。
  フィルタで外れたファイルはロードされない。
- **UC4: フィルタが直観的であること** — 入力した瞬間にツリーへ反映
  (Apply ボタン廃止)。各グループに「マッチ数 / 総数」を表示し、上部に
  全体の「N / M files match」を表示。何にマッチしているか(フォルダ名+
  ファイル名)はツールチップとグループ展開で確認できる。

## フィルタの仕様

1つの入力欄のみ。空白区切りの語をすべて満たすファイルが残る (AND)。

- 対象はスキャンルートからの相対パス「フォルダ/ファイル名」。フォルダ名でも
  ファイル名でも絞れる。大文字小文字は区別しない。
- 語は部分一致。`*`(任意列)と `?`(任意1文字)のワイルドカードも使える
  (どこかに含まれればマッチ)。
- `!語` で除外。例: `dark !bad`、`10lx/`、`*_A.npy`。
- 全ファイルが外れたグループはツリーから消える。チェック状態は変えない
  (フィルタは「見える集合を削る」、チェックは「開くグループを選ぶ」)。

## 選択とロードモード

- グループ単位のチェックボックス + フォルダ見出しの一括チェックは従来どおり。
  All / None / Invert は「いま見えているグループ」にだけ効く。
- グループは展開するとマッチ中のファイル名一覧を表示(ImGuiListClipper で
  数千ファイルでも軽い。グループ数はスキャン上限256で抑えられている)。
- 下部のロードモード:
  - **連番ファイル1グループ = 1スタック (N stacks)** — UC1。既定。
  - **選択全体を1つのスタックに結合 (M files)** — UC2+UC3。ファイルの和集合を
    自然順に並べて1本にする。スタック名は選択グループ名の共通接頭辞
    (なければルートフォルダ名)。同じ batch（管理単位）に入る。
- 結合時の安全確認: 選択グループ間で shape/dtype が異なる場合は黄色の警告
  (ローダはミスマッチをスキップする旨)。shape はローカルは .npy ヘッダの
  先読み、リモートは v3 メタデータから。raw と npy の混在結合は不可(赤字で
  理由を表示し Load を無効化)。

## ヘッドレス検証

- `--picker-selftest <dir>`: abset 相当のフォルダで UC3(フィルタ後の
  サブセットがそのファイルだけでロードされる)と UC2(結合が自然順の
  和集合1スタックになる)を実測し、evidence 行を出力する。
- 既存の `--scan-selftest` / `--lin-selftest` / `--framestats-selftest` の
  自動アクセプトは、ダイアログの Load ボタンと同じ pickerAccept() を通る。
