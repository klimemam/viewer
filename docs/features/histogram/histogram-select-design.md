## 0. 一文の定義と、決定の要約

**ヒストグラムの x 軸上で値区間をドラッグすると、その区間に入る画素が
画像の上で塗られ、何画素あったかが画面に申告される。** 名前は
**値域ハイライト (value highlight)**。「選択 (selection)」を避けたのは、
その語が既に2つの物 (annotation の selectedAnn / Files・Browse の行選択) を
指しているから。UI 文字列は `highlight`。

| 問い | 決定 | 節 |
|---|---|---|
| 何の状態か | **軸の状態** (app 1つ)。文書にも注釈にも属さない。セッション非保存 (v1) | §1 |
| 値の意味 | **生の値 [DN] の半開区間 [lo, hi)**。ビン端へ外側スナップ、端ビンは開区間 | §2 |
| CFA / ch | **プレーン束縛**。「1画素1値」が定義できる時だけ定義される。RGB の all は断る | §3 |
| 見せ方 | `renderDocRGBA` に1箇所。**選択内を塗る**(暗くしない)。色はマゼンタ (§11) | §4 |
| 数えるか | 数える。**塗ったループが数える** — ビンから数えない。毎回、地の文で申告 | §5 |
| A/B | 選択は軸のもの。**描画されるペイン全部** (A と B) が各自の画素で応える | §7 |

## 1. これは何の状態か — 軸の状態であって、文書の属性でも注釈でもない

3候補を全部検討した:

- **文書 (ImageDoc) の属性ではない。** この機能の旗艦の使い方は「裾を選んで
  frame を step し、どの画素が範囲に出入りするか見る」で、step のたびに
  uid が変わる。文書に持たせると step で選択が消えるか、数百 frame に
  コピーを同期する羽目になる。選んだのは値であって、その値はどの frame の
  上でも同じ問いとして意味を持つ。
- **注釈 (App::Ann) の層でもない。** 注釈は**場所**の宣言 (どこを測るか) で、
  セッションに保存され、リネームと一覧を持つ。ハイライトは**値**への問いで、
  identity を持たない (名前も一覧も複数個も要らない — v1)。`Ann` は文字どおり
  x,y,w,h しか持てない器でもある。下見の言葉どおり「ROI は**どこを**、
  値域は**どの値を**」で直交する。
- **ヒストグラムパネルの view state に置く — ただし「A の選択」ではなく
  「軸の選択」として。** すべての side は A のビングリッドで刻まれ
  (recomputeHistogramIfNeeded — 1つの軸、1つのグリッド、でなければ重ねは嘘)、
  side-by-side の両半分も同じ軸を張る。だからドラッグが選ぶのは **その共有軸の
  x 区間**であり、「A の選択か B の選択か」という問いは消える: 区間は軸に付き、
  描かれる各ペインが自分の画素で応える (§7)。

**セッションには載せない (v1)。** これは手に取って覗くレンズであって、
測定の宣言ではない — 同型の先例は Temporal の box-zoom (セッション非保存、
「軸に何が載っているか」に鍵づけ)。ROI (宣言、保存) との差がそのまま線になる。
未知キーは古い viewer が読み飛ばすので、後から足すのは追加変更で済む。
**再訪条件**: 再起動をまたいで欲しいという実報告が出たとき — そのときの正解は
たぶんレンズの永続化ではなく、#49 の map か ROI 類似の宣言への昇格である。

文書を切り替えても選択は生きる (値は嘘にならない — 範囲外なら 0 px と申告される
だけ)。黙って残る危険は**常時申告** (§5) が塞ぐ: ハイライトが効いている画面には
必ずそれを言う文が出ている。消し忘れが「見えない状態」になることはない。

## 2. 選択の意味論 — 値区間 [lo, hi)、ビン端に外側スナップ、端ビンは開区間

**選択は生の値 [DN] の区間である。** 表示レンジやガンマを動かしても動かない —
選んだのは「この値の画素」であって「この明るさに見える画素」ではない
(#68 下見の言葉のまま。単位は abValueUnit の規則どおり常に DN)。

**端点はビン端に外側スナップする。** プロットはビンより細かい区別を見せられない
のだから、103.7 のような端点は言ってもいない精度を名乗ることになる。触れた
ビンを丸ごと含む向きに広げる (histBinGrid が「外側に広げる」のと同じ言葉遣い)。
ビン b は [origin + b·w, origin + (b+1)·w) を張る (state.h の HistState コメント)
ので、スナップ後の区間も**半開 [lo, hi)** — ビンと選択が同じ辺の約束を持つ。

**端のビンに触れたら、その側は開区間になる。** ビンの実装は範囲外の値を端の
ビンに畳む (recomputeHistogramIfNeeded: t<0→bin0, t≥256→bin255)。つまり
bin255 のバーは「ここから上、全部」を意味している。選択がそれを字義どおりの
[origin+255w, origin+256w) と読むと、飽和裾を選んだつもりのユーザに、バーの
高さより小さい数を返す — 探していた画素 (グリッドの外に居る飽和画素) を
落として。だから規則は1文にする: **選択はバーが意味するものを意味する。**

- bin0 に触れた → lo 側は無限: 区間 (-∞, hi)。申告は `< hi DN`
- bin255 に触れた → hi 側は無限: [lo, +∞)。申告は `>= lo DN`
- 両方 → 全値。申告は `all values`
- どちらでもない → [lo, hi)。申告は `lo..hi DN`

この規則の配当が §9 の T6: 「塗った数 = 選んだビンの和」が端を含めて**常に**
成り立ち、2つのコード経路 (ビンと塗り) を1本の等式で縛れる。

選択を armed のあとに A のレンジや画像が変わってグリッドが動いても、lo/hi は
動かない (生の値だから)。新グリッドのビン端に揃っていなくてよい — 揃っていたのは
ドラッグした時のグリッドであり、端点は今も正確な DN の数である。

## 3. プレーン束縛 — 「1画素1値」が定義できるときだけ定義される

正典: CFA プレーンは統計で決して混ぜない。そして #68 下見の所感
「R の裾をドラッグしたら R だけ — 面ごとに見ているときに他面が光ると、
何を選んだのか分からなくなる」は正しい。規則はこう一般化する:

**ハイライトは、プレーンフィルタの下で画素が値をちょうど1つ持つときだけ
定義される。** ドラッグ時の `histPlane` (plane セレクタ) を選択に**束縛**して
記録する (`-1` = all)。以後セレクタを動かしても選択の束縛は変わらない
(組み替えたければドラッグし直す)。ケースは全部この1文から落ちる:

| 画像 | 束縛 | 挙動 |
|---|---|---|
| mono (1ch) | ch0 / all | 値そのもの。自明 |
| CFA + 特定プレーン | 例 R | **R の位置の画素だけ** (cfaChannelAt)。他プレーンは値が範囲内でも光らない |
| CFA + all | all | 全画素、各画素は**自分の1値**で判定 (モザイクは1画素1値なので定義できる)。数は §5 のとおりプレーン別に言う — 統計は混ぜない |
| 多ch (RGB) + 特定ch | 例 ch1 | その ch の値で判定 (フィルタの下で1値) |
| 多ch (RGB) + all | — | **v1 では断る**: 画素に値が3つあり「範囲内」が多義。ドラッグは実行されず toast で言う: `highlight needs ONE channel - pick it above` (toggleBand の拒否 toast と同じ作法) |

描画される文書 (B 含む) へのプレーンの当て方は**名前で** (abSeriesMatch —
「B のプレーンは A に名前で合わせる。ch0 は R ではない」の既存規則そのまま)。
束縛した名前がその文書に無ければ、そのペインは**塗らず、そう言う** (§5 の
文が `B: no R plane` と読む)。黙って ch 番号で当てるのは、パネルが既に
禁じた誤りの再演である。

## 4. 見せ方 — renderDocRGBA に1箇所、塗るのであって暗くしない

**場所は `renderDocRGBA` (core/app/compare.inc)。** 画素が RGBA になる唯一の
場所で、そこのコメントの契約 (表示とエクスポートが同じコードを通る。報告書に
貼った絵が画面と違うのは、絵が無いより悪い) がこの機能の置き場所を1つに
決めている。ここに入れた瞬間、画面 = view export が構成上一致する。

**選択内を塗る。選択外を暗くしない。** 判定はこの反例1つで済む: 旗艦の
使い方は裾で、**暗い裾は存在する**。黒い裾を選んで選択外を暗くすると、
選んだ画素は元々ほぼ黒なので、画面全体が黒くなって何も指さない。逆に、
選択内の画素の**明るさは情報を運んでいない** — その値が区間内であることは
選択自身が言っている文で、payload は**位置**だけ。だから位置が最強に読める
形 = 単色の置換で塗る。大面積を選べば画像がポスターになるが、それは
95% を選んだという正直な絵である。

**色: マゼンタ `IM_COL32(255, 0, 255, 255)`、不透明の置換 (§11 で裁定可)。**
- 描画パイプが**値に対して**出す語彙のどれとも重ならない: グレースケール、
  CFA colorize (純 R/G/B の tint)、jet/turbo 系 falsecolor (マゼンタを含まない)、
  diff の warm/cool/黄。センサ画像に「シーンの色」としてマゼンタは出ない。
- **アクセント色は使わない** — #68 下見と唯一違う判断。theme の規約
  (「今どこ/何が選択か」専用) に意味は合うが、(1) アクセントは5色から
  ユーザが選ぶ変数で、Aurora Blue は CFA の B プレーン tint と、Coral は
  R tint と衝突し得る — 画像の上の色が設定で意味を変えるのは駄目。
  (2) アクセントは chrome の語彙で、データ空間に持ち込むと「UI の選択」と
  「画素の該当」が一色になる。1色に2つの文を言わせない。
- ユーザ持ち込みの display LUT がマゼンタを含む可能性は排除できない。
  だから**色は信号にしない** (reload マーカーの裁定と同じ理由 —
  verify-functional D-6: この機械は GL を screenshot できず、テストも
  色覚多様性も色だけの印を読めない)。事実は §5 の申告文が運び、塗りは
  「どこか」を指すだけ。LUT との衝突は文があるかぎり嘘にならない。

**プロット側にも同じ色でバンドを描く** — 選択が作られた場所で見えること。
選択区間を薄い塗り + 縁 (同 hue、低アルファ) で、曲線の下に。side-by-side の
両半分に同じバンド (同じ軸だから同じ場所)。

**適用範囲は「renderDocRGBA が走るところ全部」。例外を作らない。**
A、B (wipe/split/flip)、view export、サムネイル — 1つの規則。diff は
renderDocRGBA を通らない別経路で、画素が差であって値ではないから**塗らない**
— ただし黙らない: diff 表示中に armed なら、canvas のバッジ (§5) が
`not shown in difference view` を添える。語られた制限は欠陥ではない。

**性能**: renderDocRGBA は 12 Mpx で ~76 ms の熱いループ。off のとき
コスト0 (ループ外分岐)、on のとき画素あたり比較1回 + CFA ならプレーン判定。
ドラッグ中は再塗りしない — バンドだけライブで動き、**塗りはリリース時に1回**
(Temporal zoom と同じジェスチャ経済)。arm / 再ドラッグ / clear は開いている
全文書の texDirty を立てる (再構築は描画時に lazy なので、立てるのは安い)。

## 5. 数える — 塗ったループが数える。ビンから数えない

**数は言う。** 「何画素が該当したか」はこの道具が返す測定値そのもので、
欠陥画素の議論 (flat-field-stats) と地続き。そして測定値である以上、
provenance の規律に入る: 量と単位、どの対象の、どの領域を、全画素か
サンプリングか — 運ばない数値は報告書に引用できない。

**唯一の源泉は塗ったループ。** ビンから導いてはならない。理由は2つの母集団が
違うから: ビンは ≤1M px にサンプリングされ、ROI 選択中は ROI しか見ない。
塗りは全画素・全フレーム。同じ顔で別の母集団の数を出すのは、このリポジトリが
一番憎んでいる罠である。renderDocRGBA が塗りながら数え (該当数と、分母になる
プレーン別の有限画素数)、パネルとバッジは**最後の塗りの数を読むだけ** —
独立に数え直す第2の実装を作らない。

- **領域は常に全フレーム。** ROI がヒストグラムを駆動していても、塗りと数は
  全フレーム (ROI 制限は §10 で断る)。パネル上部の `(selected ROI)` 表示と
  食い違って見えるのを防ぐため、**文が常に領域を名乗る**: `whole frame`。
- **NaN は決して該当しない** (isfinite ガード、ヒストグラムと同じ)。分母も
  **有限画素数** — clipLo/clipHi 行の分母の先例に合わせる。
- **CFA の all 束縛では数はプレーン別に言う** (統計は混ぜない)。%はそのプレーン
  自身の有限画素数に対する share。
- 塗りは今の画素を読むので**stale が構造的に存在しない** (曲線は stale に
  なるが塗りはならない — 言われた時のために書いておく)。

**言う場所は2つ、文は1箇所で組む** (abHistXLabel と同じ理由 — selftest が
パネルの出す文字列そのものを印字できること):

1. **ヒストグラムパネルの footer** (描画される side ごとに1行 + clear ボタン):
   ```
   highlight R 1000..1124 DN  -  A: 1234 px (0.12% of finite R, whole frame)   [clear]
   highlight 1000..1124 DN  -  A: R 12 (0.05%) | Gr 3 (0.01%) | Gb 4 (0.02%) | B 890 (3.48%) px  (whole frame)
   highlight R >= 1000 DN  -  B: no R plane
   ```
2. **canvas のバッジ** (armed の間、常時)。パネルを閉じてもハイライトは
   効いている — 申告だけが消える「黙ったレンズ」を作らないための場所。
   A の要約のみの短い形: `highlight R 1000..1124 DN: 1234 px (0.12%)`。
   diff 中は `highlight armed - not shown in difference view`。
   ImGui オーバレイなので **export には入らない** — 従って export された
   PNG のマゼンタは絵の中では説明されない。これは既存の view export と同じ
   受け入れ (レンジ/ガンマ/LUT も焼き込まれて説明されない) だが、export の
   toast と stderr 行には `exported with value highlight ...` を必ず足す。

数はどこにも export しない (v1)。TSV に載せたくなったら provenance ブロックの
家風 (export-design) に従って別途 — 再訪条件は実要望。

## 6. 操作

- **左ドラッグ** (プロット矩形内、横 ≥ 4 px — zoomRangeFromDrag と同じ
  「ジッタ付きクリックは意図ではない」しきい): バンドがライブで追従、
  **リリースで armed**。縦方向は意味を持たない (y は度数) — 常に全高バンド。
- クリック (ドラッグ未満) は何もしない。再ドラッグは置換。
- **ダブルクリックで clear** (Temporal zoom のリセットと同じ語彙) +
  footer の `[clear]` ボタン。Esc には載せない (既に他の意味を持つ)。
- ヒストグラムに既存のドラッグ操作は無い (box-zoom は Temporal のもの) ので
  ジェスチャの衝突は無い。ヒストグラムに zoom は存在しないし、この変更でも
  作らない。
- plane セレクタ・log・レイアウトの変更は選択に触らない (§3: 束縛は
  ドラッグ時に固定)。バンドは armed の間つねに描く — 軸は同じだから。

## 7. compare のとき

選択は軸のもの (§1)。描画されるペインは A と B の2つ (compare の画像モードは
2枚 — compare-n の画像側グリッドは未来の話) で、**両方が各自の画素で塗られ、
各自の数を名乗る** (§5 の footer が side ごとに1行)。「同じ値域を B にも当てて
比べたい」(#68 下見の 2) はこれが既定でそのまま叶う。A だけ / B だけの
モードは作らない — 選択は軸に1つ、が v1 の形 (再訪条件: per-side の要望が
実物で出たとき。そのときも「A の選択と B の選択」ではなく「ペインごとの
on/off」が正しい形のはず)。

C 以降のスロットは描画されないので塗られず、**数も主張しない** — 数えるのは
塗った物だけ (§5 の単一源泉)。ビンから数えれば C の数も出せるが、それは
サンプリングされた別母集団の数で、§5 が禁じた道そのもの。

## 8. 置き場所

- **状態**: `App::HistHighlight highlight` — state.h の HistState の隣。
  `on; float lo, hi; bool loOpen, hiOpen; int plane; char planeName[8]`
  (名前は束縛時に写す — 当てるのは名前で、番号ではない §3)。
  数の置き場 (renderDocRGBA が書き、パネルが読む) は uid をキーに A/B の2口
  あれば足りる — 形は実装裁量、規律は「塗ったループ以外が書かない」こと。
- **純関数**: `histHlFromDrag(pr, a, b, origin, w) -> {b0, b1, ok}` と
  スナップ/開区間の規則 — canvas.inc の zoomRangeFromDrag の隣。マウス無しで
  selftest が写像を釘付けにできる形 (同じ理由、同じ場所)。
- **塗りと数**: renderDocRGBA (compare.inc §4)。
- **ジェスチャ・バンド・footer**: panel_histogram.inc。
- **バッジ**: canvas.inc のオーバレイ群の隣。
- **probe**: `g_histHlProbe` — パネルとバッジが**実際に言った文**を書き残す
  (g_histSideProbe と同じ理由: この機械は GL を screenshot できない。守る
  対象は沈黙)。off のとき空。
- 新しい pref は無し。セッションのキーも無し (v1, §1)。

## 9. 段階と試験

各段は単独で main に入り CI 緑 (3OS)、単独で意味がある。試験は fail-first —
先に書いて赤を見てから実装し、PR に赤の run を書き残す。期待値は手で導出し、
導出を assert の隣にコメントで置く。

> **selftest の家は1つで共有される** (selftest home は全テスト共通)。armed の
> ハイライトは**後続の全 render テストを magenta に染める**ので、この群の
> 各テストは app.highlight を入口と出口で必ず clear すること。逆向きの
> ガードとして T8 (off = 不変) を最初に置く。

**段1 — 選択が存在する: ジェスチャ + バンド + 範囲の申告 (塗りはまだ)**
ドラッグ→スナップ→バンド→footer とバッジが範囲を言う→clear。単独の意味:
プロット上で範囲を刻んで読める測定補助 (「この裾は 1000..1124 DN」)。
数はまだ無い — 文は段2で伸びる (probe の期待値も段2で更新する。書いておく)。
- T1 スナップ: u16, black=100, white=1123 → histBinGrid: span=1023,

## 10. v1 で断ること (再訪条件つき)

| 断ること | 理由 | 再訪条件 |
|---|---|---|
| RGB 多ch の all 束縛 | 「範囲内」が多義 (§3) | 「どれかの ch が範囲内」の実要望 |
| ROI 内に限る塗り | 領域の束縛が増えると申告が二重になる。全フレーム+明示が単純で正直 | 「ROI の中だけ」の実要望 — そのとき領域束縛を文に載せて足す |
| セッション保存 | レンズであって宣言ではない (§1) | 実際に失って困った報告 |
| 複数区間 (両裾同時) | 器が倍になる。端開区間の規則で片裾は1ドラッグ | 欠陥解析で両裾同時の実要望 |
| マスク/ROI/欠陥リストへの昇格 | それは #49 の map と SetAnalyzer の領分 | 欠陥画素 SetAnalyzer の着地 |
| 選択外を暗くする補助 | 単独では暗い裾で破綻 (§4)。併用は器だけ増える | 疎な画素が実運用で見つけられない報告 (v1 の緩和は数の申告と texNearest) |
| diff ペインへの塗り | 画素が差であって値ではない。別経路 | — (代わりにバッジが言う) |
| C 以降のスロットの数 | 塗っていない物を数えるにはビンから導くしかなく、それは §5 が禁じた道 | 画像側の N ペイン (compare-n 10) が着地したとき |
| 数の TSV/CSV export | 画面の申告で足りる (v1) | 実要望 — export-design の provenance ブロックの家風で |
